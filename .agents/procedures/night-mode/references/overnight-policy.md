# night-mode — overnight policy

## The overnight delta (all this skill actually owns)

**Seat-class item mapping ([autonomous-night v3 §5](../../../../docs/superpowers/specs/2026-08-09-autonomous-night-v3-design.md)):** items 1 (fork policy), 3 (quota backoff), 5 (verification discipline) and 8 (standing authorization) plus the morning report bind EVERY night seat; items 2/4/6/7 bind only seats actually running the implementation loop — their upstream problem class is the unattended SDD run, not a decision sweep.

1. **Unattended autonomy / fork policy.** No human overnight, so: **technical** forks (which impl is better on the merits; an open design decision) → resolve autonomously with recorded rationale. **Genuine owner** forks (taste/strategy with no determinate best on the project's merits) → append to `<plan>.decisions.md`, do NOT decide, do NOT block; surface in the morning report. **Night-envelope conditional ([session-bus v2 §4](../../../../docs/superpowers/specs/2026-08-09-session-bus-v2.md)):** when a live top-tier seat exists and is sweeping, it MAY decide a parked question whose decision OBJECT sits inside a kickoff-authorized stage scope (the object cut — item 8), recording the entry BEFORE application; genuine owner forks and floor-category objects stay parked regardless. **decisions.md entry shape (Part I extension, v2 §4):** decision package (evidence file:line, options, trade-offs) · decision · rationale · falsifier («wrong if …») · reversibility class + concrete undo note · `decided-by:` · status (`applied | rework | superseded`). **Advisor conditional (2026-08-10, [advisor-pattern-design §2/§5.1](../../../../docs/superpowers/specs/2026-08-10-advisor-pattern-design.md)):** a concept/value fork below the floor → file an ask file + send `ASK` when the advisor is reachable (non-blocking — defer the item, keep working); floor-object forks stay parked for the operator regardless (the advisor may only pre-build the decision package). **How to file one — do not hand-write the format:** `bash scripts/check-ask-files.sh --print-template [consult|materiality-dispute] [role]` emits a fileable skeleton, `--help` prints the mailbox path resolved on this machine plus the filename + atomic-write recipe, and the same script with no arguments validates the result (pre-push section `ask-file-schema`). The emitter and the validator are one file on purpose, so a skeleton that no longer passes is a red test rather than a stale doc. _Operator-repo surface at v1_ — the mailbox default is `rules-as-tests-aif`-scoped and the script is not shipped, so on a consumer install this bullet's ask leg is inert and the fork stays parked ([advisor-pattern-design §1](../../../../docs/superpowers/specs/2026-08-10-advisor-pattern-design.md): consumer delivery is a later stage, never a silent copy).
2. **Two-altitude whole-work pass.** After all increments converge, run ONE MORE review from BOTH altitudes over the ENTIRE assembled diff AND the whole plan, plus a completeness-critic («what task / acceptance-criterion / edge is unverified?») — beyond SDD's per-increment review. Cap per-increment rework at ~4 iterations; if unconverged → mark BLOCKED, log why, continue other increments (never wedge the whole night on one).
3. **Quota / backoff resilience** (ADAPT of AIF watchdogs, SSOT #45). The loop is upper-tier-heavy (Claude: Opus-heavy); on a `429` / rate-limit, back off with `ScheduleWakeup` (~20–30 min, or the harness's own sleep/resume) and resume — survive the rolling reset window rather than dying. Commit every converged increment durably so a restart loses nothing.
4. **Workflow context-economy.** Run the loop through the **Workflow** tool so only structured summaries return to the orchestrator context — never pull full diffs/code in. Track ONLY: which increment, converged?/blocked?, plan version, quota budget. New Workflow per phase; `resumeFromRunId` is only for a killed/edited run, not for new work.
5. **Verification discipline** (how to verify correctly when no human catches a wrong claim): **empirical over inferred** — any load-bearing claim about tool/harness/code behavior is _tested_, not asserted from «it follows from the model» (this skill's own diff-visibility fact below was first inferred, challenged, then proven by a live probe); **file:line not memory** (T3); **non-vacuous paired-negatives** — RED observed before GREEN (T15); **verify-against-source before ship** (re-check git/CI, never merge on recall); **adversarial** reviewers (a clean low-coverage review is «insufficient coverage», not «clean»).
6. **Harness fact — diff visibility (verified 2026-07-02 via a live `isolation:"worktree"` probe):** an isolated agent runs in a SEPARATE worktree — its UNCOMMITTED changes are invisible to a non-isolated sibling, but a COMMIT on a named branch IS visible via the shared `.git`. So the Executor **commits every increment** to the shared branch; reviewers read `git show <branch>`. Sequential loop → Executor non-isolated in the shared worktree; `isolation:"worktree"` only for genuinely-parallel Executors on disjoint files.
7. **Advisor strategy — Fable as on-demand advisor (subscription-native ADAPT of Anthropic's Advisor tool; [prior-art-evaluations.md #201](../../../../docs/meta-factory/prior-art-evaluations.md)).** Anthropic's real [Advisor tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/advisor-tool) pairs a cheap executor (runs every turn) with a stronger advisor it calls on-demand over one shared transcript — but it is an **API-only** server tool, **not exposed in Claude Code or on a Pro/Max subscription** (verified 2026-07-04 via `claude-code-guide`). night-mode runs the same _strategy_ on subagents, subscription-only (operator directive 2026-07-04: run it on the subscription, not the API): the **executor itself flags a consult** — returning a `NEEDS_ADVISOR` note with the specific question (a night-mode convention, NOT one of SDD's statuses `DONE`/`DONE_WITH_CONCERNS`/`NEEDS_CONTEXT`/`BLOCKED`; its liveness is unproven until a live run) — when it hits a non-obvious design decision, gets stuck, or is about to declare done. This is **executor-initiated**, as in the real pattern (NOT the coordinator deciding for it). The coordinator then dispatches a **top-tier advisor** subagent (the most-capable tier — Claude: Fable; the harness's top model elsewhere; on a single-tier harness, a fresh-context same-tier reviewer) that reads the shared _committed_ context (item 6 — commit first so the advisor sees real state) and returns ≤~80-word focused advice; the **executor** is re-dispatched carrying it. The executor gives the advice weight but adapts if it empirically fails or a primary source contradicts it, and on an evidence-vs-advice conflict reconciles in one more consult rather than silently switching. Consult **sparingly** — highest value once before committing to an approach and once before declaring done, not on trivial reactive steps. **Honest gap vs the real tool (stated, not hidden):** context is coordinator-supplied (not auto-forwarded) and it costs extra subagent dispatches (not a single call) — accepted for a no-paid-API subscription run. The advisor _informs the approach; it never replaces the executor in the loop_ (advice-injection over model-swap — a refinement of SDD's BLOCKED handler, which re-dispatches with a more capable model on the increment's own signal).

8. **Standing authorization for an unattended run (the SSOT — `/pipeline` §7 and `/dispatcher` §2.4 point here, never restate).** Invoking this skill **IS** the operator's request to run the loop without confirmation rounds. Under it the session MAY, unprompted: (a) dispatch **read-only** cold-review subagents — [`agents/fidelity-auditor.md`](../../../../agents/fidelity-auditor.md), [`agents/backward-sweep-auditor.md`](../../../../agents/backward-sweep-auditor.md), [`agents/compliance-verifier.md`](../../../../agents/compliance-verifier.md); (b) where the runtime-bridge is installed (factory depth), drive the `REVISE` rework cycle through `packages/runtime-bridge/src/cli/answer.ts --decision request_changes` within the 2-round cap — without it the same cycle runs through the harness's own review loop; (c) push, open PRs, and squash-merge to `staging`. It MUST instead **escalate** on: a `base=main` merge, a **second consecutive** `REVISE` on unchanged scope, a `STOP` or `KICKOFF-AMBIGUOUS` verdict, or any parked owner-fork (delta item 1 — read through the object cut below: in-envelope objects may be decided per item 1's night-envelope conditional; everything floored escalates).
   **Night autonomy ceiling — the object cut ([autonomous-night v3 §6](../../../../docs/superpowers/specs/2026-08-09-autonomous-night-v3-design.md)).** Whether a night seat may decide a parked question is cut by the decision's OBJECT — the surface its application touches and whose scope authority covers it — never by lane or git operation. Object INSIDE a kickoff-authorized stage scope (the decision only picks among options the stage already owns) → conveyor: the change rides the stage PR under this item's merge authorization, with the decision recorded (decisions.md entry + PR `## Parked questions`) BEFORE the merge and reversibility = a pointed-at revert on staging visible to morning review. Object OUTSIDE any authorized stage scope — shared standing config, maintainer-owned artifacts (Ownership Contract), new PRs / scope widening, spend, security/permissions, the goal → floor: stay parked with the pre-built decision package. **Floor categories DOMINATE stage-scope membership** — stage-scope authorizes only what no floor category claims; genuine owner-forks (item 1), deletions of non-generated artifacts, and externally-visible actions stay floored regardless of object. **Tie rule: ambiguous object → floor** (conservative default; the ledger records the ambiguity for a morning re-cut). **Advisor conditional (2026-08-10, [advisor-pattern-design §2/§5.1](../../../../docs/superpowers/specs/2026-08-10-advisor-pattern-design.md)):** before flooring a decidable concept/value object, file an ask + `ASK` the advisor when reachable (skeleton + filing recipe: `bash scripts/check-ask-files.sh --print-template` / `--help` — item 1) — an in-envelope object may then be decided on the advisor's answer (decisions.md entry BEFORE application); floor categories and still-ambiguous-after-answer objects floor regardless. Ceiling sentence: _night may operate the pipeline to its authorized caps and decide parked questions inside the envelope; it may never move the goal, the floor, or its own authorization._ **`#umbrella-execution-launch-without-operator` (formerly `#worker-dispatch-via-subagent`) is NOT weakened and (b) does not touch it:** the auditors in (a) are read-only, already inside the envelope [`pipeline/SKILL.md §5`](../../pipeline/SKILL.md) grants («Phase -1 read-only reviewer + read-only research subagents»), and the rework channel in (b) is REST — no subagent at all. Write-task Workers still go to a fresh session or to aif, never the Agent tool.
   **Substrate choice — the aif factory is `/dispatcher`'s loop, not a second copy of it.** When the executor substrate is the aif docker factory rather than in-session subagents, the dispatch → monitor → Q&A → **pre-egress fidelity** → harvest → stage-gate → advance (§2.7 frontier read) → `done.md` mechanics are `.claude/skills/dispatcher/SKILL.md §2` (factory depth only, alongside the aif runtime it drives) — invoke it, do not re-describe it, exactly as the loop above is SDD's. This skill contributes only the autonomy policy: the authorization above, item 1's fork policy, item 3's backoff, and the terminal condition below. The two substrates are the two columns of the acceptance contour's D6 rework table ([spec](../../../../docs/superpowers/specs/2026-07-23-acceptance-contour-design.md)); the fidelity cap is 2 either way.
   **Honest classification — this is prose, not a mechanism ([attention-is-not-a-mechanism.md §1](../../../rules/attention-is-not-a-mechanism.md)).** It mitigates a **server-delivered** session-prompt default («Do not call the AgentTool unless the user requested it») that lives outside this repo: not in `.claude/settings.json`, not in any tracked file, unreachable by hook or CI, and not a permission-mode effect — so it can be **decision authority only**, never a detection layer, and the fail-closed `pr-body-fidelity` gate remains the actual enforcement. **Falsifier:** if that default changes or disappears, this paragraph is a **no-op** (harmless, but buying nothing); if it ever hardens from a prompt append into a tool-level block, prose cannot help and the reachable channel becomes the harness. Evidence + why the phrasing-based immunity was illusory: [research-patches/2026-07-24-unattended-agent-dispatch-default.md](../../../../docs/meta-factory/research-patches/2026-07-24-unattended-agent-dispatch-default.md).
