## §4 Lock decision — negative-existence evidence

The design's first route is an abstract-namespace unix-socket bind lock. The decision rests on one structural argument and one live probe, both reproduced here.

**Negative existence (pathname-socket alternative refuted).** A pathname socket or lock file needs an unlink-on-release step. A crashed holder leaves the pathname behind; the next acquirer must then decide whether the holder is dead — and per domain trap T-AUT-B an expired lock or stale mtime cannot prove an external worker ceased. The r1 review identified this as a takeover hazard: a `stale-time` takeover can delete a lock still held by a live-but-slow process. The shipped protocol contains **no unlink anywhere** — asserted by a static pin inside row 11 (`static pin: the protocol has no unlink anywhere (the r1 takeover hazard is structurally absent)`, passed in the run above) — because the kernel frees an abstract name at holder death with no filesystem residue at all. Acquisition is a single `bind()` syscall: atomic by construction, no lock file, no read-check-write window. Non-Linux hosts fail closed with `unsupported_pending_prerequisite` ([lock.mjs:81](../../../../.agents/procedures/pipeline/helpers/autonomy-binding/lock.mjs)) — the hold names the prerequisite, it does not degrade to a file lock.

**Live probe, shipped module** (run 2026-10-27 in this container against [lock.mjs](../../../../.agents/procedures/pipeline/helpers/autonomy-binding/lock.mjs); probe source and re-run command in §11). Output quoted verbatim:


**Residual, repaired (supersedes this section's earlier acceptance).** The r4-era text accepted a symlink-alias residual on a «single-canonical-spelling operator contract» and claimed the CAS-on-revision write rejected the concurrent alias write as a correctness net. The acceptance review refuted both halves (A1-CODE-01): the CAS read and rename are separate operations, so two aliases holding two different locks can both pass CAS and overwrite each other; and an operator convention is not a mechanism. The repair derives containment, lock identity and write target from **one** fully resolved spelling — `canonicalRecordPath` ([store.mjs:274](../../../../.agents/procedures/pipeline/helpers/autonomy-binding/store.mjs), realpath of the longest existing ancestor plus the leaf chain) — used by `ensureStageOwnership` (an escaping ancestor is rejected `record_outside_stage_root` **before any write**), by the lock key ([lock.mjs:52](../../../../.agents/procedures/pipeline/helpers/autonomy-binding/lock.mjs), so two aliases contend on one lock), and by `writeRecordAtomic` (the write lands on the same resolved target it locked; a retarget between read and write is rejected `record_path_retargeted`). An unresolvable path fails closed `lock_target_unresolvable` / `record_target_unresolvable` — never a lexical fallback. The CAS is now defense-in-depth against a mid-pass swap, not the serialization story. Pinned by row 16's four alias-safety arms (§14 F1); the old residual test that asserted distinct lock keys was **replaced**, not kept beside the repair.

## §5 Resume authorization — production hold + row-19 battery

Stage A holds production `resume` unconditionally. [engine.mjs:102](../../../../.agents/procedures/pipeline/helpers/autonomy-binding/engine.mjs) builds `unsupported_pending_prerequisite`; the CLI emits it before any record interaction, and a supplied `--grant` path is named in the hold reason but can never clear the hold (verb handling in [autonomy-binding.mjs:229-235](../../../../.agents/procedures/pipeline/helpers/autonomy-binding.mjs)). The pure transition proposer `proposeResumeTransition` ([record.mjs:382](../../../../.agents/procedures/pipeline/helpers/autonomy-binding/record.mjs)) is fixture-only: it computes a proposal from trusted input and persists nothing; a static pin asserts no production path wires it to persistence.

Row 19 (five subtests, all passed in the §3 run) is the evidence battery. Item 4's negatives, stated exactly as tested (the earlier revision here overclaimed — it listed «wrong actor, expired evidence», neither of which the battery exercises; recorded as a B observation, §14.6):

1. `production CLI negatives: every resume shape stays held with unchanged record bytes` — `resume` with and without `--grant`, on bound and unbound records; record digest compared before/after.
2. `observation/worker-supplied grant is DATA: stored verbatim-none, no resume, no admission` — a grant arriving through a worker observation cannot self-authorize.
3. `direct production engine invocation stays held — no CLI-only check to skip` — the hold lives in the engine, not the argument parser.
4. `fixture-only pure transition: valid trusted input proposes consumption; negatives reject; nothing persists` — the future seam is exercised; its tested negatives are scope (`featureId`, `stage`, `taskId`, `recordPath` → `grant_scope_mismatch`), stale `controlRevision` (`grant_revision_stale`), stale record digest (`grant_digest_stale`), malformed grant (`grant_invalid` for short rationale and for a non-granted action), replay (`grant_replayed`), and non-paused origins (`illegal_control_transition` for active and pause-pending bases). Wrong-actor and expired-evidence are NOT in this battery.
5. `static pin: no production path wires the fixture-only transition to persistence` — the resume hold is structural, not a flag default.

This is deliberate non-credit, not incompleteness: resume authorization is a stage-B+ business-control surface, and faking it in A1 would have manufactured PA7 evidence (see §6).
