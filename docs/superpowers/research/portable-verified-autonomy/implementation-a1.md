## §4 Lock decision — negative-existence evidence

The design's first route is an abstract-namespace unix-socket bind lock. The decision rests on one structural argument and one live probe, both reproduced here.

**Negative existence (pathname-socket alternative refuted).** A pathname socket or lock file needs an unlink-on-release step. A crashed holder leaves the pathname behind; the next acquirer must then decide whether the holder is dead — and per domain trap T-AUT-B an expired lock or stale mtime cannot prove an external worker ceased. The r1 review identified this as a takeover hazard: a `stale-time` takeover can delete a lock still held by a live-but-slow process. The shipped protocol contains **no unlink anywhere** — asserted by a static pin inside row 11 (`static pin: the protocol has no unlink anywhere (the r1 takeover hazard is structurally absent)`, passed in the run above) — because the kernel frees an abstract name at holder death with no filesystem residue at all. Acquisition is a single `bind()` syscall: atomic by construction, no lock file, no read-check-write window. Non-Linux hosts fail closed with `unsupported_pending_prerequisite` ([lock.mjs:81](../../../../.agents/procedures/pipeline/helpers/autonomy-binding/lock.mjs)) — the hold names the prerequisite, it does not degrade to a file lock.

**Live probe, shipped module** (run 2026-10-27 in this container against [lock.mjs](../../../../.agents/procedures/pipeline/helpers/autonomy-binding/lock.mjs); probe source and re-run command in §11). Output quoted verbatim:

The revision read/check stays a sequential consistency check under the kernel lock — it is not an atomic compare-and-swap and not the serialization story (§18.3 corrects this section's earlier «defense-in-depth against a mid-pass swap» CAS wording to match the narrowed store comments, §16.3). ## §5 Resume authorization — production hold + row-19 battery

Stage A holds production `resume` unconditionally. [engine.mjs:170](../../../../.agents/procedures/pipeline/helpers/autonomy-binding/engine.mjs) builds `unsupported_pending_prerequisite`; the CLI emits it before any record interaction, and a supplied `--grant` path is named in the hold reason but can never clear the hold (verb handling in [autonomy-binding.mjs:301-307](../../../../.agents/procedures/pipeline/helpers/autonomy-binding.mjs)). The pure transition proposer `proposeResumeTransition` ([record.mjs:631](../../../../.agents/procedures/pipeline/helpers/autonomy-binding/record.mjs)) is fixture-only: it computes a proposal from trusted input and persists nothing; a static pin asserts no production path wires it to persistence.

Row 19 (five subtests, all passed in the §3 run) is the evidence battery. Item 4's negatives, stated exactly as tested (the earlier revision here overclaimed — it listed «wrong actor, expired evidence», neither of which the battery exercises; recorded as a B observation, §14.6):

1. `production CLI negatives: every resume shape stays held with unchanged record bytes` — `resume` with and without `--grant`, on bound and unbound records; record digest compared before/after.
2. `observation/worker-supplied grant is DATA: stored verbatim-none, no resume, no admission` — a grant arriving through a worker observation cannot self-authorize.
3. `direct production engine invocation stays held — no CLI-only check to skip` — the hold lives in the engine, not the argument parser.
