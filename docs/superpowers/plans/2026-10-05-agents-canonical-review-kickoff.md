# Canonical agents — cheaper independent review kickoff

> **For agentic workers:** Perform a fresh-context read-only whole-change review. Tests that mutate files require your own disposable copy. Use existing reviewer-discipline and verification-before-completion procedures.
> **Authoritative for:** independent review steps for the exact returned implementation result.
> **NOT authoritative for:** source repair, host trust or publishing.

**Goal:** Verify factory output against both operator stages and return concrete findings without spending another senior implementation session.
**Architecture:** Review one frozen result, reuse deterministic gates and collect changed native receipts on the actual supported host.
**Tech Stack:** Existing Bash/Node/Vitest, renderers, native doctor and saved evidence drivers.
**Spec:** [review contract](../specs/2026-10-05-agents-canonical-independent-review-design.md), [implementation contract](../specs/2026-10-05-agents-canonical-completion-design.md).

## Global constraints

Review source is read-only. Do not fix, stage, commit, push, merge or modify trust/global configuration.
Use the operator-selected cheaper seat or existing configured AIF review seat; no silent model/transport override.
AIF project default review is GLM-5.3 SDK as observed on 2026-10-05; name does not establish cost or present host capability.
Review only when review-target.json and actual result are available. A kickoff prepared before implementation is not a review receipt.

## Task 1: Pin the reviewed population

- [ ] Read recorded operator premises and both specs, then the frozen review-target.json.
- [ ] Verify archive/patch/base/head and every intended source/link/mode hash.
- [ ] Enumerate all changed paths and canonical source-map entries. Separate authored owners, native entries, generated payloads, guards and delivery.
- [ ] Read implementation report last, treating it as claims. Confirm no protected bytes or consumer-owned files changed without authority.

## Task 2: Check architecture and adapters

- [ ] Inspect every mapped path mechanically for owner/entry closure; read semantic changes and any transform exceptions.
- [ ] Inspect representative complete procedures plus every specially changed loader/adapter: mandatory shell blocks, invocation arguments, helper locations and native descriptions.
- [ ] Run affected source/native/adapter controls in your isolated copy; include the canonical/legacy clean and violation controls.
- [ ] Verify source-edit propagation and whole-body plugin drift using existing tests, without changing accepted source.
- [ ] Check explicit executor/MCP/lifecycle limitations against code; diagnostic is not enforcement of an unknown effect.
- [ ] Verify fresh Git payload contains common owners and native discovery entries without a recovery generator.

## Task 3: Check consumer and package delivery

- [ ] Inspect manifest/profile/ignore/build changes against the intended audience and tracked file set.
- [ ] Inspect all 15 final snapshot cells and compare link identity/target containment.
- [ ] Run changed fresh/upgrade/force/refresh/dry-run/customization controls; retain valid unchanged exact-result receipts.
- [ ] Reproduce one standalone npm pack installation with contributor source unavailable and exercise a delivered helper/check.
- [ ] Require final MANIFEST/build-index and self-audit receipts, or name the actual unresolved gate.

## Task 4: Verify changed native joins on the real host

- [ ] Establish host/tool capability and source identity. Container-only seat must mark this task HOST-PENDING and hand the same task to the operator-selected cheaper host seat.
- [ ] Run read-only native doctor in the accepted destination: report discovery, registration and trust separately.
- [ ] Exercise complete-source loading, an invocation with arguments and an actual mandatory helper; include a controlled helper failure.
- [ ] Exercise changed canonical-path rule/violation feedback and pre-effect deny with clean controls in disposable paths.
- [ ] Reuse earlier manual compact receipt only when the changed inputs match; separately assess child identity/cache and automatic compact requirements.
- [ ] For absent failed-write/cancellation contracts, require a supported executed fallback or report unresolved behavior. Never invent a callback.
- [ ] No trust changes, paid turns or global plugin refresh. If activation changed, provide exact definitions requiring operator action.

## Task 5: Report and hand back

- [ ] Recheck frozen identity at close. Source drift invalidates affected checks.
- [ ] Produce R1–R10 evidence matrix and requirement dispositions for S1/S2.
- [ ] Keep all historical 20+32 entries; preserve complete=false while the broader contract is incomplete.
- [ ] Write review-report.md with four separate verdicts: architecture, native behavior, installer, package.
- [ ] For material findings, send exact rework instructions through the already-authorized dispatcher/task route; do not fix source yourself.
- [ ] ACCEPT only with complete in-scope evidence or explicit operator scope disposition. AIF done, test count, discovery count or confident prose is insufficient.
