Each enrollment is immutable/versioned and names stable project identity, assigned host, backend/project/profile, source repository/workflow/check, permitted red classes, earliest backfill time, eligibility revision and triage scope digest. No discovery of arbitrary repositories or projects. Exactly one active host enrollment is allowed per project; migration requires the old runner stopped and its durable store transferred and reconciled. SQLite is a local-host lock, not distributed CAS.

Pin-freshness at the pinned SHA schedules `43 5 * * *` UTC, has a 10-minute job timeout and 24-hour stale ancestor budget. Its manifest-absent red before cutover is intentional. Read-only metadata showed three scheduled completed failures, latest run 38048084011 at the pinned SHA; it did not establish failure causes. A separate manifest GET returned 404. Neither proves a cutover receipt or job causality.

Before a signed cutover receipt, a classified manifest-absent condition opens one bounded triage episode per enrollment/condition revision. Later observations and run attempts attach to that unresolved episode without new tasks. A new failure class or incompatible scope gets a distinct episode. After a cutover receipt naming URL, served SHA, owner and evidence digest, manifest absence is a defect episode under a new policy epoch. Do not silently close/suppress the pre-cutover incident merely because a task is done.

Polling uses three complementary discovery passes: (a) new runs with a rolling 24-hour creation-time overlap; (b) persisted nonterminal run attempts revisited by run ID and attempt number every tick until terminal, regardless of creation age; (c) a complete admitted-history rescan every 15 minutes to discover reruns of previously terminal old runs. The rescan includes all runs created since the immutable enrollment backfill boundary, not just recent creation dates; a run's latest run_attempt is only an upper bound for discovery. Enumerate every unseen attempt number from 1 through that bound (or from the last contiguous persisted attempt +1) using the documented GitHub GET `/repos/{owner}/{repo}/actions/runs/{run_id}/attempts/{attempt_number}` endpoint. Persist each attempt independently and classify every eligible terminal attempt, even if a later attempt succeeded. An attempt2 failure followed by attempt3 success between scans must still enqueue attempt2. Persisted nonterminal attempts use that same specific-attempt read until terminal. Missing/forbidden/expired attempt responses set SOURCE_GAP; never advance the contiguous attempt-discovery cursor across a missing number or infer old conclusions from the latest snapshot. Attempt enumeration progress is not terminal completion coverage. Reconcile unfinished attempts independently of a run's latest status. A resumed old run before that boundary is outside supported coverage and must not be represented as covered. Admission must explicitly accept that boundary or extend it to the required entire source history. No updated-time filter or webhook guarantee is assumed. Store known run IDs, contiguous_discovered_attempt and individual attempt states; stop with SOURCE_GAP if a complete rescan cannot be finished within the admitted API/page budget, retention removes required history, or the accepted interval cannot be enumerated. A known nonterminal run is never discarded at the boundary or on a rolling-window expiry. Newly created runs arriving during a rescan are picked up by the next overlap pass; complete scans use a fixed creation-time upper bound and overlapping time windows. Maximum old-rerun detection target is 15 minutes within the admitted history; this is a proposed service target requiring source acceptance evidence. Polling fetches pages up to 100 items using provider run/attempt identities. Cursor advancement, source_runs/source_attempts tracking and event persistence share one database transaction, only after every page in the interval is accounted for. A stored scan boundary uses provider creation time plus run ID; repeated overlap is deduplicated. Admission sets the initial backfill boundary and maximum outage/backfill horizon. Provider limits, pagination truncation, permission errors, rate limits, clock skew and outages beyond the horizon set SOURCE_GAP/DEGRADED and stop cursor advancement; they never produce a green coverage claim. Reconcile the gap before claiming automatic coverage. GitHub filtered run queries may cap at 1000 results; split time windows or explicitly mark the unresolved interval. No new authenticated receiver is needed. An already-authorized receiver may later call the same enqueue transaction, with its own reviewed contract.

## 4. Durable state location and exact v1 schema

Resolve `HO8_STATE_ROOT` if explicitly supplied in the admitted host inventory; otherwise macOS `~/Library/Application Support/getff/ho8/v1`, Linux `${XDG_STATE_HOME:-~/.local/state}/getff/ho8/v1`, Windows `%LOCALAPPDATA%/getff/ho8/v1`. Require an absolute, local, persistent directory; reject temp/network filesystems and missing Windows state root. Database: `<root>/<sha256(stable-project-identity)>/outbox.sqlite3`. Stable identity is the admitted backend deployment identity plus project ID, not checkout path. Canonicalized root/device identity is stored and checked on open to prevent accidental second stores. No secrets are stored.

SQLite connection requires foreign_keys=ON, journal_mode=WAL, synchronous=FULL and busy_timeout=5000. Transactions use BEGIN IMMEDIATE and committed fenced updates; runtime writes outside transactions are forbidden. Disk-full, corruption, unsupported SQLite mode or busy expiry are explicit failures. Do not fall back to JSONL or memory. Store directory mode 0700/files 0600 where supported; Windows equivalent ACL must be verified. Backup includes WAL-safe SQLite backup and schema/version validation, not a copied live main file. Crash/durability behavior is an acceptance obligation, not established by import availability.

Columns below are the complete v1 logical schema. TEXT IDs/digests use lowercase SHA256 or exact external strings; `*_ms` are integer UTC epoch milliseconds; booleans are INTEGER 0/1. Nullable columns are suffixed `?`. Other columns NOT NULL. Canonical JSON is UTF-8, recursively sorted object keys, ordered arrays, no undefined/nonfinite numbers; its digest is SHA256 of exact bytes. Original bounded structured evidence bytes are retained, not normalized terminal output.

Allowed incident states: PENDING, CLAIMED, DISPATCH_INTENT, DISPATCH_UNKNOWN, TASK_IDENTIFIED, RELEASE_UNKNOWN, DELIVERED, ATTENTION, RESOLVED. Allowed attempt states: INTENT, UNKNOWN, IDENTIFIED, RELEASE_UNKNOWN, DELIVERED, DEFINITELY_REJECTED. CHECK constraints enforce these enums. Event and incident inserts use deferred foreign keys in one transaction. Immutable payload/kickoff fields may not be updated; fresh observations become events. Journal retention cannot expire an unresolved incident or any ambiguity. Resolved episodes retain immutable receipt/digests; compaction requires a separately reviewed retention policy.

`event_id` hashes enrollment ID, provider record ID, attempt, head SHA and failure class. `episode_key` hashes source kind, admitted source identity, failing check/operation, failure class, scope digest and policy epoch. For harvest add upstream task ID and stable operation fingerprint; when task ID is unavailable use explicit harvest invocation UUID persisted at invocation start. A process retry must carry that invocation ID. No incident identity is fabricated from error text. `incident_id` hashes enrollment, episode key and generation. Repeated reds attach to an unresolved generation; a verified resolution receipt ends it. A later red after resolution opens generation+1. Source evidence can accumulate after delivery; a task already delivered is never blindly recreated.

## 5. Claim, timeout and recovery protocol

1. Check event uniqueness before allocating a generation, then enqueue event plus find/create incident atomically. A duplicate event remains bound to its original incident, including after resolution; it never opens a new generation. A duplicate unique source key with inconsistent head/payload identity is SOURCE_CONFLICT, not a silently overwritten event. Harvest writes before exiting; failed enqueue keeps the original red exit and emits a machine-readable OUTBOX_WRITE_FAILED diagnostic. It is not accepted delivery. This synchronous local boundary needs no live backend. Existing egress remains unchanged.
2. A single enrolled runner claims PENDING with a transaction conditional on state/token, increments fencing token, writes owner/lease and commits. Proposed lease is 120 seconds, renewed every 30 seconds. External HTTP is never held inside a SQLite transaction. Every subsequent write checks owner/token. Reclaim after lease expiry may reconcile; it may not automatically POST.
3. Persist exact bounded triage kickoff and DISPATCH_INTENT before any POST. Include machine marker `ho8:v1:<incident_id>:<kickoff_digest>:<scope_digest>` in the kickoff description header. Avoid a self-referential digest: kickoff digest hashes the immutable body excluding this marker line; store the complete transmitted bytes plus that documented body digest. Scope includes evidence URLs, owner, allowed files/actions and explicit prohibitions. Triage may diagnose/recommend; it may not repair, spend, publish, change security/provider, merge main or recursively spawn handover tasks without separate authority.
4. Guarded AIF claim first verifies project/profile/isolation/auth/cost gates read-only. Disable the existing self-heal path for HO8 through an explicit guard option. Keep paused=true, autoMode and native reviews; do not weaken review or ownership. No generic dispatch fallback. Use existing 10-second AIF timeout. A returned ID is persisted then GET/readIdentity verifies task ID, deployment, project ID, exact kickoff body digest/marker, scope digest, selected effective profile and AI execution owner. Missing fields fail closed; existing typed getStatus does not establish these checks.
5. A POST timeout, transport loss, malformed response or crash after INTENT is DISPATCH_UNKNOWN. No retry POST, cancel or lease-steal POST. Scoped list plus independent GET may recover a single exact marker match. Multiple matches set ATTENTION and block release. Zero matches is not proof of no creation: retry reads with 5/15/60-second backoff, then every five minutes; after 15 minutes mark ATTENTION while continuing reconciliation. The thresholds are proposed policy, not measured capability.
6. **Uniqueness admission gate:** before autonomous activation, demonstrate a deployed guarantee for complete incident reconciliation and definitive non-creation, or an already-existing incident idempotency mechanism. Ordinary eventual list visibility alone cannot safely prove absence. If no such guarantee exists, this design deliberately leaves UNKNOWN unresolved and cannot claim automatic recovery/full HO8. Chief must select a separately reviewed backend contract change or narrower partial rung; do not invent an endpoint/header or quietly add backend code to this scope.
7. After identity verified, persist receipt/TASK_IDENTIFIED before release PUT. Release only the known task ID, and only after a separate RELEASE_FENCING admission gate: prove an already-existing deployed conditional release that fences all gate-relevant task fields and project/profile policy, or an enforceable existing exclusive-mutation/immutability contract from identity verification through release. The inspected ordinary PUT has no such expected version/identity parameter. OwnershipRevision CAS alone is insufficient. A pre-GET/post-GET pair is not preventive fencing. If this guarantee is absent, retain TASK_IDENTIFIED/ATTENTION, keep the task paused, and request an owner-bound separate backend contract proposal; no release or security/ACL change is implied here. A timeout is RELEASE_UNKNOWN: GET reconciles paused/status on that same task; never creates another. Known paused task may receive repeat PUT paused=false only after confirming identical identity and gate validity; no DELETE rollback. Advanced/running status can confirm release only with identity readback. Invalid ownership/profile/scope sets ATTENTION.
8. Commit DELIVERED receipt with release_verified_ms and all current event delivery_ack_ms in one transaction. ACK means durable verified delivery, not repair acceptance. Late events on that incident receive ACK only against the same valid receipt. Source-specific ACK occurs after this transaction. A crash before ACK replays observation without a new task.
9. RESOLVED requires owner-bound acceptance evidence showing the external condition addressed or an explicit reviewed expected-condition disposition. Task `done` is insufficient. Superseding enrollment/scope requires chief reconciliation; do not erase an unresolved incident. Native task errors/stalls attach evidence to the existing incident and route attention through the existing owner; never recursively generate unlimited remediation tasks.

This gives atomic local ownership and at-most-one attempted creation until ambiguity is resolved. It does not promise unconditional remote exactly-once delivery with the currently observed API. That limitation is a build/activation gate, not an implementation detail to hide.

## 6. Scheduler and liveness

Measured: localhost health HTTP200; the installed `dev.getff.aif-close-merged` launchd job is loaded, has 191 runs and recent periodic logs. It runs at minutes 0/15/30/45, fetches mutable staging, and may return exit0 for aif-down SKIP. It is a closure sweep, not an HO8 poller/watchdog. Participants-mode snapshot is not dispatch authorization. No HO8 scheduler or worker heartbeat has been measured.

Proposed HO8 runner is one bounded tick using the admitted existing host scheduling facility, not another coordinator. Target poll cadence: 60 seconds; tick watchdog: 90 seconds; DB heartbeat: 15 seconds; alert threshold: no completed tick for 180 seconds or pending delivery older than 15 minutes. These are proposed acceptance targets. An independent already-authorized observer must detect stopped runner, stale heartbeat, source gaps and unavailable backend. If no such observer is admitted, scheduler death remains an explicit unmet requirement. A runner cannot prove its own continued existence.

Delivery, source freshness, runner process health and worker progress are separate dimensions. Task checkedAt is a poll timestamp, not worker heartbeat. Before full closure, measure the deployed native worker lease/activity field and its expected cadence, define stale-worker timeout, and prove observation without new ownership/coordinator actions. No current field is assumed. Stalled worker after delivery does not erase the receipt or authorize duplicate creation. Existing owner handles recovery under preserved task gates.
