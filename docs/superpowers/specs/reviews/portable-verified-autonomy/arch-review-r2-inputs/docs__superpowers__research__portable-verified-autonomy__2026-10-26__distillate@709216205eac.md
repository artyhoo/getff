## Return to intent, then arch

**Verifier verdict: GO to product reconsideration, conditional on the separate cold K-pass.** All nine promises have explicit plausible routes or discriminating experiments; no demonstrated contradiction requires weakening the approved product brief. This is not GO to implementation or adoption of a host.

The next intent round should restore the existing experience: the maintainer agrees an outcome; agents complete work, meaningful review, correction and authorized delivery; relevant experience carries forward; the maintainer intervenes for real decisions. Research supports keeping that meaning. It rules out interpreting success as more bots, a completed model turn, a new task with uncontrolled memory, or an installation receipt alone.

Carry exactly these unresolved product decisions forward, with evidence rather than a repeated interview:

1. **D4 — representative first task:** C3 compares bounded correctness fix, convention/rule change, installer delivery and research-only work. The first three can demonstrate development outcomes; research-only success is insufficient for whole-feature acceptance. Choose based on the actual recurring bottleneck, not the easiest demo.
2. **D5 — session continuity requirement:** is preserving already-open agent sessions essential, or may the selected host create/manage the sessions for its task? H2 shows these are different capabilities; no architecture should silently substitute one for the other.
3. **D6 — setup horizon:** retain raw setup plus recurring effort; choose the usage horizon before making a net-benefit claim. No numeric saving is yet justified.

If these decisions change an essential promise, update and reapprove the PRD exactly. Otherwise preserve its current approval and record the choices separately. Only then return to arch for alternative selection, final design, testing seams, independent reviews and the first bounded implementation slice. This research neither creates a current solution spec nor repairs AIF admission.
