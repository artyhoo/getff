## Findings

### MAJOR 1 — No independently selected current *agreed specification*

`D:82` gives the PRD approval a per-feature current selector outside the candidate, with an advance/read contract. `D:78` lets the spec/kickoff carry its own parent and decision references, and `D:110` requires the launch consumer to “independently re-resolve” the exact agreed specification and current review. It never defines who records the currently operator-agreed spec, where that selection lives, or how a new agreement supersedes it. The earlier design's `progressive.json`/`readinessRef` (`2026-10-07-idea-arch-incremental-design@6d26ba299a27.md:180-190`) is itself proposed and expressly not adopted wholesale by `D:13,25,80`; the live `/arch` retell checker only checks source-tag grammar, not agreement (`.agents/procedures/arch/references/ideation.md:52`). A current `matches` attempt for old spec A can therefore be self-consistent with an unchanged kickoff even after operator-agreed spec B exists. The PRD selector does not distinguish A from B when the PRD is unchanged.

Failure-scenario: The operator agrees to a revised architecture B while keeping the same PRD. A queued kickoff names A and its valid spec-review attempt. At dispatch, the implementation can verify every candidate-provided digest and `matches` result but has no independently selected current spec B to compare, so it starts the superseded plan, violating `P:14,29` (the agreed-spec and autonomous-execution boundary) and `D:110,130`.

### MAJOR 2 — Freshness contract omits the post-planning implementation-start effect

`D:110` names write-time/direct/automatic dispatch checks before task creation or planner execution; `D:116` names release/resume guards. The current scoped AIF route deliberately stops at `plan_ready` and starts implementation only through `start-reviewed.ts` (`.agents/procedures/pipeline/references/dispatch.md:23`; `packages/runtime-bridge/src/cli/start-reviewed.ts:76-116`). That command re-reads the task and validates a PlanReview against its persisted contract, then posts `start_implementation`; neither this proposal nor the existing `enforceAnswerScope` contract (`resultReview.ts:333-345`) explicitly requires re-resolving the current PRD approval and agreed-spec review at that last effect. `answer.ts`'s restart decisions are separately guarded (`cli/answer.ts:94-109,413-442`), which shows why the effect population cannot be inferred from `dispatch.ts` alone. `D:114` states historical evidence must not grant current permission, but does not bind that rule to `start-reviewed`.

Failure-scenario: A scoped task is claimed, released and planned under PRD A, then `/intent` approves PRD B before `start-reviewed` runs. Its unchanged PlanReview still matches the persisted A task and current plan. The command posts `start_implementation` without consulting the independent B selector, allowing actual execution on a superseded product promise despite `D:110,133`.

### MAJOR 3 — Design-only suppression has no write-time binding

`P:14,29` and `D:110,130` require an explicit design-only instruction to cause no task/planner effect while retaining the existing autonomous route. The existing hook acts immediately on a `Write`/`Edit` of a `*/kickoff.md` whose first line is `<!-- bridge: auto -->` (`.claude/hooks/runtime-bridge-dispatch.sh:154-185`) and runs the dispatcher (`:255-270`); the hook input is file path/tool event, not the operator's design-only instruction (`:20-30`). `/arch` currently specifies that single-task factory exit may write this auto marker (`.agents/procedures/arch/references/exit-and-escalation.md:21-25`). The proposed document-freshness check would still pass if PRD/spec/review are current. The design states the prohibition but does not bind the marker/authoring moment to it before the hook runs. This needs a concrete procedural or artifact rule, with the AC5 negative exercised against the real hook route; it does not require a new per-kickoff vote or a wholesale skill rewrite.

Failure-scenario: During a design-only session, `/arch` prepares an otherwise valid single-task kickoff using its present auto-marker exit convention. The PostToolUse hook dispatches it on write before any later exit choice or prose warning can prevent the effect. All document checks are green, so the new freshness guard cannot enforce the operator's explicit no-execution boundary.
