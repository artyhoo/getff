### Pin mechanism (R3, R4, R5)

- `framework.pin` (landing, one line, default `main`). `scripts/fetch-framework.mjs` reads it; a branch name resolves through `git ls-remote https://github.com/artyhoo/getff <ref>` to a SHA; then `git init` + `git fetch --depth 1 origin <sha>` + `git sparse-checkout set docs/site` + `git checkout FETCH_HEAD` into `.framework/` (gitignored — the landing `.gitignore` carries only `.source/` today, so the entry is part of the S1 landing task). The depth-1 fetch of a non-tip SHA is supported: the server advertises `allow-reachable-sha1-in-want`. The resolved SHA is exported to the build (`FRAMEWORK_SHA`) and stamped into the AI projections (R12). Same script locally, in PR CI and in `deploy.yml` — **and always BEFORE `npm ci`**, whose `postinstall: fumadocs-mdx` reads `source.config.ts` and would otherwise resolve a collection directory that does not exist yet (R5).
- Trigger: framework workflow `notify-landing.yml` — `on: push: branches: [main]`, one step: `gh api repos/artyhoo/getff-landing/dispatches -f event_type=framework-main-moved` with `GH_TOKEN: ${{ secrets.LANDING_DISPATCH_TOKEN }}`; exit code propagates, so a rejected token is a red run on the promote the operator just made. Pinned action SHAs per `ci-tool-pinning.md`; no LLM, no paid call (`no-paid-llm-in-ci.md`).
- Landing `deploy.yml`: add `repository_dispatch: types: [framework-main-moved]`; the existing `push: main` and `workflow_dispatch` stay (a landing change or a manual run still deploys). This one line ships in its **own trigger-only PR before the cutover** (R4) — `repository_dispatch` only fires workflows already present on the receiving repo's default branch (landing default = `main`), so leaving it inside the cutover PR would make the first exercise of the freshness path happen after the irreversible step.
- Freshness detector: framework `pin-freshness.yml` (daily) compares the live `verified-at` against `origin/main` and goes red when the site is more than 24 h behind — one detector covering a promote that never happened, a dispatch that never fired and a landing build that went red (R22).
- Freeze/unfreeze = a landing PR editing `framework.pin`. No cron, no bot PRs (R4 evidence).

### Redirect contract (R7, B-D4)

`old-urls.txt` is generated by **enumerating the live surface** — 196 HTML pages ∪ 195 `.md` twins ∪ `/llms.txt` ∪ `/llms-full.txt` ∪ `/sitemap-0.xml` ∪ `/sitemap-index.xml` ∪ `/rss.xml` ∪ `/api/search` (~397 URLs, not 196) — and committed with the command that produced it. `redirects.json` maps every old path that moves to its new path. `scripts/write-redirect-stubs.mjs` (post-build) writes **two shapes**: `out/<old>/index.html` for a directory-shaped URL and a literal file at `out/<old>` for a file-shaped one such as `/docs/faq.md`, since `out/docs/faq.md/index.html` is not served at that path. Every stub = meta-refresh + canonical + **`noindex`** + a visible link, and is excluded from the sidebar and from `llms.txt` (D33 via R21). `scripts/check-redirects.mjs` (PR CI + deploy) asserts: every enumerated URL resolves in `out/` to a page or a stub; **every D33 census URL resolves to a REAL page, never a stub**; each stub target exists in `out/`; no stub shadows a real page. **Retention decided 2026-09-14 under P-AF (closes TD-12; ratified by the umbrella as D37, 2026-09-14):** a stub exists ONLY where a successor page exists in the new IA — `redirects.json` is a map to real targets, and for a reference draft the target is the generated reference page of the same family (D29). A draft URL with no successor is NOT stubbed: it is listed in `retired-urls.txt` (committed with the cutover PR, one reason per line) and returns 404 from cutover day — P-AC: the unneeded keeps no place. `check-redirects.mjs` therefore accepts exactly three states for every enumerated URL — real page | stub with an existing target | listed in `retired-urls.txt` — and fails on an unlisted URL. **D37 adds one constraint:** a retired URL that is still referenced from the framework's own surfaces — `README.md`, `docs/**`, the `llms.txt` head template, the npm package README (`packages/core/README.md`) — is a coverage-gate ERROR in the cutover PR: fix the reference, or un-retire the URL as a stub to the nearest successor. The check needs those files, which the `docs/site`-only sparse checkout does not carry, so in the cutover PR `check-redirects.mjs` is given `--framework-full <dir>` — a second depth-1 checkout of the framework at the same pin (public repo, no token) — and greps the four surfaces for every `retired-urls.txt` entry; the landing build itself keeps the narrow checkout. Stubs that do exist are kept indefinitely: no retention window and no remover, because a dated window is a second mechanism that decays into «forever» the first time nobody runs it. Live post-merge probe per the stage table.

### Mermaid verification record (R6)

Verified 2026-09-13 from installed source: `remarkMdxMermaid` (`fumadocs-core/dist/mdx-plugins/remark-mdx-mermaid.js:3-26`) rewrites ```mermaid fences into `<Mermaid chart>`; no component ships in `fumadocs-ui`; Fumadocs' own recipe is an async server component over `beautiful-mermaid` `renderMermaidSVG` (1.1.3, MIT, zero DOM, 6 diagram types). Decision: that recipe, minus its silent code-block fallback — the component throws, the build fails (`#warning-nobody-reads`). **Narrowed after cold round 1:** the library's throw is a HEADER check only (`package/src/parser.ts:46`); content INSIDE a supported type is dropped silently and byte-identically (measured: a garbage line, a `click` directive, an unsupported shape, a `par/and` block all render as if absent). So the component validates its input against a node/edge allow-list BEFORE calling `renderMermaidSVG` and throws on anything outside it — otherwise the design would have swapped a visible dropped fence for an invisible dropped edge. The allowed-type list (flowchart, state, sequence, class, ER, XY) is handed to the docs-author contract (D30 carve-out) AND enforced from one shared module by the framework-side fence check (R19) and this component — «the skill is told the list» is advice, not a gate. **UNVERIFIED until the first S1 build:** fumadocs-mdx 15.4.0 compiling a `.md` page whose tree carries the injected JSX node; fallback = pages authored as `.mdx`. The S1 fixtures are TWO, because one of them tests the half that already works: an unsupported `gantt` fence (build must fail — verified it throws) **and** a supported-type diagram carrying a dropped element (must fail the pre-render allow-list).

- **Refresh gate (R13):** `packages/core/hooks/check-docs-refresh.test.ts` — a sandbox suite that EXECUTES the script (`spawnSync` + `mkdtempSync`, the `check-doc-authority.test.ts:8,133` pattern), or `tests/hooks/*.test.sh`. Three cases (changed cited file + untouched page → FAIL; + deferral token → PASS; + short reason → FAIL). Explicitly NOT `pre-push.test.ts`: that file executes nothing and its own `:109` sends behavioural paired-negatives elsewhere, so the three cases written there would be string greps that pass whether or not the gate fires. Both callers take the range as an argument, so a drift between channels is the falsifier — compared on the same explicit range, not across a push-range/`base..HEAD` mismatch.
- **Gold cards (D24b):** `generator output == hand-written gold card` byte-for-byte for the 5 gold pages + family 1; a diff is a generator defect.
- **Redirects (R7/R21):** `scripts/check-redirects.mjs` over the ENUMERATED `old-urls.txt` (~397 URLs: pages ∪ twins ∪ generated files) in `pages-build`; a deliberately removed mapping in a test branch must go red, and a stub deliberately placed at a D33 census URL must ALSO go red (both negative runs recorded once in the S1 PR body). The file-shaped stub arm has its own case: `/docs/faq.md` must be served as a file, not as `…/faq.md/index.html`.
- **Mermaid (R6/R19):** TWO fixtures, because the obvious one tests the half that already works. (a) unsupported TYPE (`gantt`) → build fails (verified: `parser.ts:46` throws). (b) SUPPORTED type carrying content the library drops silently — a `click` directive or a garbage line, measured byte-identical to the clean diagram — must fail the component's pre-render allow-list. With both fixtures removed the build passes. The same allow-list module is asserted at the framework channel by R19, so the two cannot drift.
- **Link resolution at the pin (R20, the seam D31 named):** `lychee --offline` over `out/` in `pages-build` — internal links and stub targets against the rendered tree at the pin. Known gap, recorded not hidden: an out-of-range `#L<n>` in a `blob/<sha>` permalink returns 200 and no link checker sees it; that check is relayed to the D29 generator carve-out where the anchor is produced.
- **Pin + dispatch (R4/R22):** BEFORE the cutover, through the trigger-only landing PR — one manual `notify-landing` run → a landing deploy run with `event: repository_dispatch` against the site that is live today. The rejected-token run points the secret at a deliberately invalid token for one run (deleting the secret does NOT test this: `${{ secrets.… }}` then expands to empty and the step fails on a MISSING credential, a different HTTP path from a rejected one). After cutover the freshness detector `pin-freshness.yml` is the standing seam: live `verified-at` == `origin/main` within 24 h.
- **Rollback (R15):** revert rehearsal build green before the cutover merge.
- **S0 measurement (R2):** one `jq` command over the session jsonl reading the transcript's OWN `compact_boundary` records — `select(.subtype=="compact_boundary")` → `trigger` (`auto` vs `manual`), `preTokens`, `postTokens`, `cumulativeDroppedTokens`. Not the `usage`-difference proxy: measured against a real transcript it returned 3 boundaries where 5 occurred and could not separate auto from manual. Filter `select((.isSidechain // false) == false)` so a dispatched subagent's records do not mix two context budgets, and state the definition of «turn» used for the pages-per-cycle denominator. Recorded in the S0 closure note, no new tooling.

## Consequences

- **Six** operator hands in total, in a fixed order (R14); no bump PRs, no bot PRs, no subdomain. One cron exists — `pin-freshness.yml` in the FRAMEWORK repo (R22), where the 60-day auto-disable rule that ruled cron out for the landing does not bite.
- One secret enters the system (`LANDING_DISPATCH_TOKEN`, framework repo); its failure mode is a red run on the operator's own promote, not a stale site nobody notices.
- The landing loses 195 hand-written route twins and 196 draft pages in one PR; the frozen list is the whole enumerated live surface (~397 URLs), not the page subset, and it freezes those URLs forever. Whether 180 reference-DRAFT URLs deserve permanent stubs is escalated, not decided here.
- Unverified items are named with their fallbacks, each settled by the first S1 build rather than by another design round: **Mermaid-in-`.md`** (fallback: pages become `.mdx`); **the single dynamic `.md` route** (fallback: keep generating N literal route folders — the repo's own comments say the literal folders ARE the static-export workaround); **a throwing server component actually failing `next build`** (no error boundary may sit between `DocsBody` and the MDX tree — the mechanism the whole «build fails, never degrades» claim rests on); **how the smoke build reaches the second repo** (a cross-repo push needs a token, a local push is an operator hand — S1 must say which); **`LANDING_DISPATCH_TOKEN`'s fine-grained `contents: write`** (the REST reference documents only the classic `repo` scope; confirmed at secret-creation time). The depth-1 non-tip fetch is NO LONGER on this list — it is supported, measured, and its fallback dropped.
- Boundary relayed to the umbrella seat: permalink resolution happens at the landing build; the generator emits `path:line` + `sources:` frontmatter (R12, R13). Two further relays out of cold round 1 — the permalink line-range check belongs to D29 (R20's recorded gap), and promoting `/code-review ultra` from Class-C prose to a deterministic arm belongs to `operational-conventions.md` (R9's recorded limit).
- The umbrella's headline failure mode now has a detector. Before cold round 1 every failure mode in this design had one except «the published site is stale» — the mode P-A exists to prevent (R22).
