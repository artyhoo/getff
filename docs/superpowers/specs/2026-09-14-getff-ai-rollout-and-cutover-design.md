## Operator-premise register (verbatim-faithful in meaning; copied from the umbrella register, never paraphrased)

- **P-A** — Dynamic docs are wanted NOW, not at the end: parts of the framework are reworked constantly, docs go stale; new features already done need docs immediately; docs must always be current; this also serves the AI developing the project — it looks into its own docs first.
- **P-B** — A human writes nothing. All text is generated: high-quality, comfortable and useful for a human reader as one rendering, informative and useful for AI as another.
- **P-K** — Refreshing pages can also run in Claude Code, not only in aif; aif was meant for the BULK work. The operator is for saving expensive Claude tokens, as long as quality does not suffer.
- **P-M** — Do ALL the bulk work in aif FIRST — but only after writing and thinking everything through carefully and in detail, preparing everything so that aif does it WELL; then check and improve with Claude at the end.
- **P-P** — «aif on GLM; Claude only on the EXTERNAL contour». No Opus/Fable seat inside aif.
- **P-R** — «the factory must control ITSELF; Opus only checks the FINAL work; Fable = advisor / creator / inventor, owns the DESIGN; the PLAN is written by Opus, and when something is unclear Opus asks Fable.»
- **P-S / P-T / P-U** — Gold prose written ONCE by the top tier (Fable); the first pass is the full page content (tables' shape, diagrams, examples, layout); a CLEAN Fable session does it after the needed skills exist; «I need your ADVICE, not agreement».
- **P-V** — «not necessarily aif — simply, right when something in the project changes, AT MERGE there must be a requirement to update the docs; or better still, the docs update automatically — but here everything has to be of high quality».

## Decision

Three stages, each exited by a deterministic gate or a named cold seat — never by «someone looks». The landing stays a pure renderer; every new mechanism is one script with one home.

### Pin mechanism (R3, R4, R5)

- `framework.pin` (landing, one line, default `main`). `scripts/fetch-framework.mjs` reads it; a branch name resolves through `git ls-remote https://github.com/artyhoo/getff <ref>` to a SHA; then `git init` + `git fetch --depth 1 origin <sha>` + `git sparse-checkout set docs/site` + `git checkout FETCH_HEAD` into `.framework/` (gitignored). The resolved SHA is exported to the build (`FRAMEWORK_SHA`) and stamped into the AI projections (R12). Same script locally, in PR CI and in `deploy.yml`.
- Trigger: framework workflow `notify-landing.yml` — `on: push: branches: [main]`, one step: `gh api repos/artyhoo/getff-landing/dispatches -f event_type=framework-main-moved` with `GH_TOKEN: ${{ secrets.LANDING_DISPATCH_TOKEN }}`; exit code propagates, so a rejected token is a red run on the promote the operator just made. Pinned action SHAs per `ci-tool-pinning.md`; no LLM, no paid call (`no-paid-llm-in-ci.md`).
- Landing `deploy.yml`: add `repository_dispatch: types: [framework-main-moved]`; the existing `push: main` and `workflow_dispatch` stay (a landing change or a manual run still deploys).
- Freeze/unfreeze = a landing PR editing `framework.pin`. No cron, no bot PRs (R4 evidence).

### Build-time projections under `output: 'export'` (R12, D8b, D29a)

Framework generators emit `.md` pages with `path:line` anchors and `sources:` frontmatter; the landing build resolves anchors to `https://github.com/artyhoo/getff/blob/<FRAMEWORK_SHA>/<path>#L<n>` and writes: `.md` twins (existing `page.data.getText('processed')` route pattern, one dynamic route instead of 195 hand-written ones), `llms.txt` (existing `app/llms.txt/route.ts`), `docs/manifest.json` (per-family JSON from the generator, D29a, plus `verified-at: <sha>` and `stale-since` = the `docs-refresh: deferred` token present at the pin). Human render carries none of this (D8b). Next.js `redirects()`/`headers()` are inert under export and are not used.

### Redirect contract (R7, B-D4)

`redirects.json` maps every old path to its new path; `scripts/write-redirect-stubs.mjs` (post-build) writes `out/<old>/index.html` = meta-refresh + canonical + visible link; `scripts/check-redirects.mjs` (PR CI + deploy) asserts: each of the 196 entries of `old-urls.txt` resolves in `out/` to a page or a stub; each stub target exists in `out/`; no stub shadows a real page. Stubs are kept indefinitely. Live post-merge probe per the stage table.

### Mermaid verification record (R6)

Verified 2026-09-13 from installed source: `remarkMdxMermaid` (`fumadocs-core/dist/mdx-plugins/remark-mdx-mermaid.js:3-26`) rewrites ```mermaid fences into `<Mermaid chart>`; no component ships in `fumadocs-ui`; Fumadocs' own recipe is an async server component over `beautiful-mermaid` `renderMermaidSVG` (1.1.3, MIT, zero DOM, 6 diagram types). Decision: that recipe, minus its silent code-block fallback — the component throws, the build fails (`#warning-nobody-reads`). The allowed-type list (flowchart, state, sequence, class, ER, XY) is handed to the docs-author contract (D30 carve-out). **UNVERIFIED until the first S1 build:** fumadocs-mdx 15.4.0 compiling a `.md` page whose tree carries the injected JSX node; fallback = pages authored as `.mdx`. The S1 negative fixture (an unsupported `gantt` fence) is the evidence that the build fails rather than degrades.

### Self-application

This design's own rule — «every exit is a gate or a named seat» — is applied to itself: the spec exits through the two cold /arch §2 seats (D27) with the verdict grammar above; the review brief carries paths only. The measurement obligation (S0 numbers, S1 build time, S2 probe) is stated per stage so a stage cannot close on a feeling.

## Testing seams

- **Refresh gate (R13):** `packages/core/hooks/pre-push.test.ts` — three cases (changed cited file + untouched page → FAIL; + deferral token → PASS; + short reason → FAIL); the CI step calls the same script, so a drift between channels is the falsifier, not a second test.
- **Gold cards (D24b):** `generator output == hand-written gold card` byte-for-byte for the 5 gold pages + family 1; a diff is a generator defect.
- **Redirects (R7):** `scripts/check-redirects.mjs` over `old-urls.txt` in landing PR CI; a deliberately removed mapping in a test branch must go red (negative run recorded once in the S1 PR body).
- **Mermaid (R6):** landing build with an unsupported-type fixture page → build fails; with the fixture removed → build passes.
- **Pin + dispatch (R4):** after cutover, one promote → green `notify-landing` run + a landing deploy run with `event: repository_dispatch`; a revoked-token dry run (operator deletes and recreates the secret once) → red framework run.
- **Rollback (R15):** revert rehearsal build green before the cutover merge.
- **S0 measurement (R2):** one command over the session jsonl (`jq` over per-turn `usage`: max of input + cache_creation + cache_read; count of drops > 100k between consecutive turns) — recorded in the S0 closure note, no new tooling.

## Consequences

- Four operator hands in total (R14); no bump PRs, no cron, no subdomain.
- One secret enters the system (`LANDING_DISPATCH_TOKEN`, framework repo); its failure mode is a red run on the operator's own promote, not a stale site nobody notices.
- The landing loses 195 hand-written route twins and 196 draft pages in one PR; the redirect list freezes those URLs forever.
- Unverified items are named (Mermaid in `.md`, depth-1 fetch of a non-tip SHA) with their fallbacks; each is settled by the first S1 build, not by another design round.
- Boundary relayed to the umbrella seat: permalink resolution happens at the landing build; the generator emits `path:line` + `sources:` frontmatter (R12, R13).
