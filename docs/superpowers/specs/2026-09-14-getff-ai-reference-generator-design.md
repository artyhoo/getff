The «documents lie» thesis (README) is the design constraint, not an obstacle: a card field is honest only when a machine already consumes it, or when its absence fails a gate. Swagger UI reads badly because it is a skeleton with no narrative next to it; docs.rs, godoc, Stripe and Terraform provider docs are generated and readable because prose sits beside the schema — that prose is the umbrella's band B (D29 advice). This spec designs the skeleton so it cannot drift, cannot be padded by an AI, and stays small enough to read.

**One generator, two projections, one fence engine.**

### §3.1 Per-family JSON shape (consumed interface — G17)

```json
{
  "schemaVersion": 1,
  "family": "B",
  "familyName": "skills",
  "generator": "scripts/render-reference.mjs",
  "members": [
    {
      "name": "ai-doc",
      "kind": "skill",
      "shipsTo": { "tier": "core", "stacks": ["ts-server", "react-next"] },
      "installedTo": { "absent": "not-byte-copied" },

```

No `pin` key and no permalinks anywhere in the file: a pre-commit renderer cannot know the SHA of the commit it is creating, so a framework-side pin would be one commit stale by construction (D34); the landing knows the SHA it cloned and stamps it. Universal keys are **present on every member of every family**; a value that the sources cannot supply is the absence object `{ "absent": "<reason-id>" }` (G18; the `installedTo` line above shows the shape — it is an E-family extra, not universal, and appears here only to fix the token's shape), never a missing key, an empty string or an empty object; `shipsTo.stacks` may be `[]` and then renders as `not installed on any lane`. `extras` carries the §4 family columns; `example` is a fixture path or `null` — the generator inlines that fixture's region into the card fence itself, never a landing-side include (G15, R18); `shipsTo.tier` is `framework` for operator-contour members. Every file validates against `docs/site/reference/schema/<family>.schema.json` (`additionalProperties:false`, no empty strings). Consumers (face pages, twins, `llms.txt`) read members by `name` and never re-derive a value the JSON carries (D12).

## §6 Readability rules (what a reader sees)

- **Every page the generator touches carries `kind:`** (D30 C13; the sheet kind on sheets, the family-overview kind on overviews) — set by the page author, checked by the generator, never invented (G11).

- **Values are rendered strings, not JSON:** `ships-to: core · ts-server, react-next` not `["ts-server","react-next"]`; permalinks are rendered by the landing from `path:line` at the pin (D14a).
- **No empty cells ever, no silent narrowing either:** every cell is a value or a gated-absence phrase (G18); a universal column is never dropped; an extras column is dropped only by a recorded schema decision (G1). **Settled by umbrella D36** (stages S0a/S0b/S1 = the umbrella spec's §2 stage skeleton, `2026-09-13-getff-ai-site-design.md:49`: S0a source-hole batch, S0b gold pages + rules, S1 generator + landing): D14d's «render honest blanks meanwhile» is superseded for the conveyor — the interval it assumed is stage S0a (the generator runs `--write` there to enumerate holes; the two-way completeness test is S0a's exit criterion, not a page gate); from S0b on a missing source field fails the build naming the file. The generator never creates a page and never creates empty sheets (TD2-6).
