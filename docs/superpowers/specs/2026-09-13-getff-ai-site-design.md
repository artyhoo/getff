## 0. The problem this umbrella solves

The framework has ~180 hand-drafted reference sheets the operator does not want to ship (P-G), a landing site with a docs section that a claims audit stopped (BS3, 18 GAP), and parts of the framework that change every week. The operator's premises fix the shape of the answer: dynamic docs now, not later (P-A); a human writes nothing, all text is generated and cold-audited (P-B); one criterion of truth for the project, the docs and the AI (P-D); examples everywhere (P-E); when the project changes, the AI itself determines which pages are affected and refreshes them (P-H).

## 1. The reader's view

- **Who reads first (D1).** An evaluating developer and their AI agent, through one welcoming gate: landing → docs hub → drill-down. The operator is the second reader and reaches their pages in one click.
- **Familiar entry points (D4, D4b, D4c).** The four sidebar tabs Learn / Guides / Understand / Reference stay; on top of them the familiar «Docs» entry, a pinned «Get started» group of 7 pages (E1 of the face session), Installation and Quick start. Layers (rules beta / factory experimental) are badges and a filter, never navigation. The maturity badge reads from one source, `packages/core/manifest/maturity.json` (D32).
- **What a reference page is (D5).** Three bands: A — a fact card generated by a script from the framework at the pin; B — prose generated by an AI session from the sources, cold-audited, never hand-kept; C — evidence: anchors to source lines, collapsed, with «verified by» links to principle tests. One generated overview page per family.
- **Posture (D6, D8b).** Understand pages argue: pain → mechanism → proof → honest limit. Reference pages never sell. No human-facing freshness badge; freshness lives in the machine projection and in the deferred token (D8b, D34).
- **Agent-first (D9, D10, D11).** `llms.txt`, a generated manifest, `.md` twins per page reachable through Fumadocs' own page actions (View as Markdown / open in ChatGPT / Claude / Cursor), Context7 + DeepWiki submission as a release step. No MCP server, no server-side Ask-AI (static export, $0).
- **Languages (D3).** EN-only build now; i18n slots reserved (`hideLocale: 'default-locale'`, `dot` parser, EN fallback); a second language never changes an existing EN URL.

## 2. Architecture and stage skeleton

### 2.1 One source, two projections

The framework repository is the source: `docs/site/` holds the fact cards (per-family JSON + fenced card regions — band A / C, deterministic renderers), the overview pages, `face-facts.json` (D42), `terms.md` and the gold prose (band B). The landing repository is a pure renderer that checks the framework out at a pin during its build (D14a, D34): it resolves `path:line` anchors into `blob/<sha>` permalinks, stamps `verified-at`, renders the human HTML projection and writes the agent projection — the `.md` twins, `llms.txt`, `llms-full.txt`, the manifest — from the same sources (§2.4 conveyor boundary, D28a, D35). Generators on the framework side emit `path:line` and `sources:` frontmatter only — never permalinks (D34: a pre-commit renderer cannot know the SHA of the commit it is creating).

The pin is framework `main`, moved by `repository_dispatch` at every promote (P-AD, D34): one PAT secret, a red run on failure, no cron moves the pin, no bump PRs; the ONE scheduled workflow in the package is the staleness detector `pin-freshness.yml` (D31 R22, daily — F BU MAJOR-1). `beta.getff.ai` is dropped; previews build on `artyhoo/getff-docs-smoke`.

### 2.2 Regeneration and refresh

Deterministic framework-side content (bands A/C, the overviews, `face-facts.json`, the derived `sources:` — D43) is regenerated in the same PR: pre-commit `--write`, pre-push and CI `--check`, the precedent being `render-rule-index.mjs --check` at `packages/core/hooks/pre-push.ts:1352` (D14b). Generated bands are delimited by fence markers from `packages/core/composition/fence.ts`, so the deterministic and the prose halves of one page can be checked separately. Emitter contract of that engine (bottom-up note 6): the begin marker carries a `plan=<path>` attribute (`fence.ts:29-31`); unknown attributes are tolerated and `hash=` is never emitted (`fence.ts:10-13`).

Prose refresh is a merge gate, not a sweep (D26, P-V): the intersection of a PR's changed files with the `sources:` frontmatter of every page names the affected pages; the gate is one script, `scripts/check-docs-refresh.mjs`, called from a pre-push section and from `audit-self.yml` (D34 — aif containers never run pre-push, D29a). The only escape is a `docs-refresh: deferred — <≥20-char reason>` token in the PR, which the page then carries as its `stale-since` until refreshed (D8b). A page without `sources:` frontmatter is a generator defect, never a gate exemption; `sources:` itself is derived — body anchors ∪ card sources — by the renderer's `--write` and verified by `docs-check.mjs`, so its completeness is by construction for every anchored fact (D43).
