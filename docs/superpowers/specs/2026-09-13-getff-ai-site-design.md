## 0. The problem this umbrella solves

The framework has ~180 hand-drafted reference sheets the operator does not want to ship (P-G), a landing site with a docs section that a claims audit stopped (BS3, 18 GAP), and parts of the framework that change every week. The operator's premises fix the shape of the answer: dynamic docs now, not later (P-A); a human writes nothing, all text is generated and cold-audited (P-B); one criterion of truth for the project, the docs and the AI (P-D); examples everywhere (P-E); when the project changes, the AI itself determines which pages are affected and refreshes them (P-H).

This document is deliberately thin. It holds what only the umbrella can hold — the premises, the decisions with their falsifiers, the stage skeleton, the seams and the slots — and delegates every detailed surface to a carve-out session that owns it (D28–D31, P-X–P-AA). The four carve-outs were run in parallel by separate sessions; their questions came back to this seat as escalations and were answered as register rows (D28a, D29a, D29b, D24c, D32, D33, D34). Nothing in §3 or §4 is reconstructed: both sections are the live register copied line by line (T10 — the population precedes the conclusions).

## 1. The reader's view

- **Who reads first (D1).** An evaluating developer and their AI agent, through one welcoming gate: landing → docs hub → drill-down. The operator is the second reader and reaches their pages in one click.
- **Familiar entry points (D4, D4b, D4c).** The four sidebar tabs Learn / Guides / Understand / Reference stay; on top of them the familiar «Docs» entry, a pinned «Get started» group of 7 pages (E1 of the face session), Installation and Quick start. Layers (rules beta / factory experimental) are badges and a filter, never navigation. The maturity badge reads from one source, `packages/core/manifest/maturity.json` (D32).
- **What a reference page is (D5).** Three bands: A — a fact card generated by a script from the framework at the pin; B — prose generated by an AI session from the sources, cold-audited, never hand-kept; C — evidence: anchors to source lines, collapsed, with «verified by» links to principle tests. One generated overview page per family.
- **Posture (D6, D8b).** Understand pages argue: pain → mechanism → proof → honest limit. Reference pages never sell. No human-facing freshness badge; freshness lives in the machine projection and in the deferred token (D8b, D34).
- **Agent-first (D9, D10, D11).** `llms.txt`, a generated manifest, `.md` twins per page reachable through Fumadocs' own page actions (View as Markdown / open in ChatGPT / Claude / Cursor), Context7 + DeepWiki submission as a release step. No MCP server, no server-side Ask-AI (static export, $0).
- **Languages (D3).** EN-only build now; i18n slots reserved (`hideLocale: 'default-locale'`, `dot` parser, EN fallback); a second language never changes an existing EN URL.

## 2. Architecture and stage skeleton

### 2.1 One source, two projections

The framework repository is the source: a generated folder `docs/site/` holds the fact cards, the overview pages, the `.md` twins, the manifest and `llms.txt` (band A / C, deterministic renderers) plus the gold prose (band B). The landing repository is a pure renderer that checks the framework out at a pin during its build (D14a, D34): it resolves `path:line` anchors into `blob/<sha>` permalinks, stamps `verified-at`, renders the human HTML projection and serves the agent projection unchanged. Generators on the framework side emit `path:line` and `sources:` frontmatter only — never permalinks (D34: a pre-commit renderer cannot know the SHA of the commit it is creating).

The pin is framework `main`, moved by `repository_dispatch` at every promote (P-AD, D34): one PAT secret, a red run on failure, no cron, no bump PRs. `beta.getff.ai` is dropped; previews build on `artyhoo/getff-docs-smoke`.

### 2.2 Regeneration and refresh

Deterministic content (bands A/C, manifest, twins, overviews) is regenerated in the same PR: pre-commit `--write`, pre-push and CI `--check`, the precedent being `render-rule-index.mjs --check` at `packages/core/hooks/pre-push.ts:1352` (D14b). Generated bands are delimited by fence markers from `packages/core/composition/fence.ts`, so the deterministic and the prose halves of one page can be checked separately.

Prose refresh is a merge gate, not a sweep (D26, P-V): the intersection of a PR's changed files with the `sources:` frontmatter of every page names the affected pages; the gate is one script, `scripts/check-docs-refresh.mjs`, called from a pre-push section and from `audit-self.yml` (D34 — aif containers never run pre-push, D29a). The only escape is a `docs-refresh: deferred — <≥20-char reason>` token in the PR, which the page then carries as its `stale-since` until refreshed (D8b). A page without `sources:` frontmatter is a generator defect, never a gate exemption.

### 2.3 Who writes what (P-R, D21–D25)

- **Fable** (this seat and one clean content session, P-U/D25): design, the umbrella spec, and the first full content pass — the gold pages (D24b), made with maximum care and reviewed before any conveyor starts.
- **Opus** (separate sessions, D27): the two cold spec reviews; the gold-page review before family 1; the checkpoint after family 1 (D22); the final check; adjudication of gold-card diffs together with the content session (D24c).
- **aif on GLM** (D19, P-P): the bulk conveyor over the remaining families and the change-driven refresh, with the diataxis-based writing skill (D17) and the deterministic style half (D17b), calibrated on 5 trial pages (D17c).
