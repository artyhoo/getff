## Open questions (substrate) — ~~blocking~~ RESOLVED 2026-07-18

**Status: RESOLVED.** The maintainer's target pipeline (local CC → aif-handoff container with in-aif Claude coordinator + GLM-5.2 worker) is the aif-native path. aif-handoff supports per-agent model frontmatter: `implement-coordinator` (or any coordinator agent) can run on `model: opus` while `implement-worker` runs on `model: glm-5.2`, both inside the same container. Verified live in `docs/superpowers/specs/2026-06-02-aif-parallel-dispatch-design.md:64` (`model=sonnet, transport=cli` per task) and `agent-collision-resolution/kickoff.md:21` (aif loads `.claude/agents/*.md` via `settingSources:["project"]`).

The original concern — that aif-handoff points at one endpoint per container and therefore cannot host both Claude and GLM — was **wrong**: the per-container endpoint is the _default_, but aif's agent-definition frontmatter allows per-agent model override on top of that default. The skill at `.claude/skills/claude-glm-executor-handoff/SKILL.md` therefore targets the in-aif Claude coordinator, which reads `.claude/skills/` natively. The "two containers" and "LiteLLM proxy" alternatives are no longer required.

This section is retained as a record of the resolved question; the skill's §0 carries the corrected framing.
