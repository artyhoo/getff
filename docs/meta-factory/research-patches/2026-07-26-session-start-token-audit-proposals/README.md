## Binding invariants (cross-cutting)

- **Note A — `paths:` is a YAML list, one item per glob.** Pasting the marker's comma-separated
  string as a scalar yields either «rule never loads» or «rule stays always-on» — both without
  any error, defeating the trim invisibly. Each glob is one `- ` list item. Proposal 1's
  diff uses the correct list form — do not "simplify" it.
- **Note B — `claudeMdExcludes` + §2 hook line are BINDING-paired.** Adding
  `autonomous-loop-continuity.md` to `claudeMdExcludes` without also adding the 4th line to
  `inject-session-bootstrap.sh`'s AIF_AUTONOMOUS block (proposal 2) **silences §2's wait rule
  for every session** — the rule's own Class header
  (`.claude/rules/autonomous-loop-continuity.md:9`) declares its channels as (a) the Stop-hook
  arm and (b) the autonomy block in `inject-session-bootstrap.sh`; always-on CLAUDE.md
  injection is **not** among them. The pairing closes a declared-channel-vs-reality gap rather
  than opening one. Apply 2 + 3 in the same maintainer commit.
- **Note C — `git-conflict-merge-forward.md` exclusion accepted-degradation, recorded.**
  Excluding this rule leaves an agent meeting a CONFLICTING PR without the §2 merge-forward
  recipe pre-loaded: the muscle-memory `git rebase` is blocked by the operator-global
  `git-safety.sh` at execution time, and the CLAUDE.md Harness-gates pointer still routes to
  the recipe — so the cost is one wasted first-attempt cycle, not a wrong outcome. That cost
  is accepted in exchange for 9,285 bytes at every session start.
- **Re-grep citations after proposal 1.** Inserting frontmatter on `zcode-parity-doctrine.md`
  SHIFTS every line number in that file. At S2 authoring time (2026-07-30) NO file in the repo
  cites this rule by `:line-number` (mechanically verified via
  `git grep -nE 'zcode-parity-doctrine\.md:[0-9]+'`), so the line-shift is a non-event.
  Proposal 1's apply recipe retains a re-verification grep as a binding step in case new
  `:N` citations land between S2 and the maintainer's application.
- **All four proposal diffs are mechanically generated.** Each was verified with
  `git apply --check` against the pre-application HEAD of
  `feature/session-start-token-audit-c781e8` (commit 336d031ef, 2026-07-30). They are
  ready-to-apply, not illustrative.

## Token impact (S1 attribution table projection)

Applied together, the four proposals are projected to remove the following from every
host-cc session-start (S1 §2 totals: 140,216 bytes / ~39,021 tokens → projected post-S2):

| Proposal | Bytes removed at session-start | Token delta (est) | Notes |
|---|---|---|---|
| 1 — zcode paths: frontmatter | 22,177 | ~5,544 | Pure removal |
| 2 + 3 — claudeMdExcludes (`autonomous-loop-continuity.md`) + §2 hook line | 13,459 − ~600 = ~12,859 (autonomous); 13,459 (interactive) | ~3,365 autonomous / ~3,365 interactive | The §2 hook-line addition costs ~600 bytes per `AIF_AUTONOMOUS=1` session (zero for interactive). Note B pairing. |
| 3 — settings claudeMdExcludes (`git-conflict-merge-forward.md`) | 9,285 | ~2,321 | Pure removal |
| 4 — MEMORY.en index rewrite (RU → EN, content files unchanged) | ~13,000 | ~7,219 | RU byte-cost 2× per token vs EN; the saving is the byte delta weighted by the RU→EN ratio change, not byte-delta/2.2 (corrected in S3 — see S3 §10.1) |
| **TOTAL projected** | **~57,321 bytes** | **~18,449 tokens** | |

S1 host-cc baseline 39,021 → projected ~20,572 tokens (within the ≤25k budget). The container
(aif-container) baseline is 29,589 tokens (no operator MEMORY.md); proposals 1+2+3 apply
without operator-local artefacts, projecting ~18,560 tokens (also within budget). Re-measurement
closes this in S3.

> **Baseline note (added in follow-up to S3):** this projection uses the S1 pre-Task-7 baseline
> (39,021). S3 §10.1 reports the post-Task-7 baseline (38,325 — Task 7's CLAUDE.md hot/cold split
> saves ~696 tokens host-cc) and the corresponding post-application projection of 19,876 tokens
> (38,325 − 18,449). The two projections differ by exactly Task 7's saving; both are GREEN within
> the ≤25k budget.

**Autonomous-session overhead note:** the only proposal that ADDS bytes anywhere is proposal 2
(§2 hook line, ~600 bytes per autonomous turn). All other proposals are pure-removal. The
net for autonomous sessions is therefore the same ~18,449 token reduction minus the ~150 tokens
the §2 hook line costs per autonomous turn. Interactive sessions see the full ~18,449 token
reduction with zero offset.
