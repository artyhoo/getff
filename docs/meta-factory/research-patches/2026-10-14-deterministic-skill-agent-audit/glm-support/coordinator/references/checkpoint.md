# Checkpoint and destination packet

> **Authoritative for:** the continuity fields added by coordinator to the existing owner record or handoff.
> **NOT authoritative for:** a replacement task registry, task-context schema or MBP handoff protocol.

At an admitted stage boundary, quota failure or context handoff, update the existing owned record. If none exists, use one task-local checkpoint in an owned output directory. Preserve these fields without duplicating full manuals:

| Field | Required content |
|---|---|
| Outcome and authority | Observable endpoint; granted scope; source decisions; messaging, spend, install and publication boundaries |
| Identity and ownership | Project/root, candidate checkout/ref, agreed delivery checkout, harness, accountable owner/chat, runtime task ID and actual session ID separately; write reservation and observer |
| Destination inputs | Complete accessible kickoff/spec and relevant input/approval references, exact SHA or content hashes; selected procedure/host bindings and actual tool capabilities |
| Evidence and dependencies | Candidate/executed/accepted/merged/installed facts separately; artifact/version and check command/result; prerequisite versions; derived outputs affected by the change |
| Caps and recovery | Original cap and cumulative use, remaining attempts, quota checkpoint and verified reset/availability condition; no fresh allowance on resume |
| Next action and observation | One next permitted action, accountable owner, expected actionable event, process/wait handle, shared claim or uncertain-send receipt, actual external blocker |

For a remote/container destination, transport the required files or complete contents through the supported task-input mechanism. Map source reference/hash to destination reference/hash and verify the worker can read them there. A Mac absolute path, chat attachment or queued message is not proof of transport. If unreachable, report the specific missing input and repair transport within existing authority before execution.

Use MBP `handoff` for write/rehydrate only when it is installed and appropriate; read its selected operation, schema and protocol. Add the continuity fields to its existing sections; do not replace its schema or overwrite another owner's HANDOFF.md. Without MBP, this compact record is sufficient. Reading a checkpoint does not launch work; reconcile live identity/evidence, then continue under the active role and authorization.

When accepting, verify the load-bearing result directly and retain exact-version evidence. Unchanged accepted files keep their evidence; changed dependencies or content invalidate only the affected claims and required exact-version gate. For parser/installer/generator failures, verify complete output and genuine exit status, repair the shared contract and its causal derived set; never hide a regression by an unjustified baseline refresh.
