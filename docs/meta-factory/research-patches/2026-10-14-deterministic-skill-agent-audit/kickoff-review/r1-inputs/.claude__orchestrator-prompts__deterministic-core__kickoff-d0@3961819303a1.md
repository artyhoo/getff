## §2 Command, technology and boundedness

Source entry: `packages/core/audit-self/living-docs-audit-cli.ts`. Ready artifact: `packages/core/audit-self/living-docs-audit.bundle.mjs`, built by the existing runtime-bundle owner. Consumer destination: `scripts/living-docs-audit.mjs`, delivered with the role through existing installer/resource owners. Bundle required first/third-party runtime imports; no consumer tsx/npm/build step. This path choice follows existing scripts delivery, not `@rules-as-tests/core`'s TS bin entries.

Invocation contract:

```text
node scripts/living-docs-audit.mjs --project-root <absolute-root> --profile <base|react-next|react-spa|react-native> [--diagnostics-dir <absolute-directory>] [--timeout-ms <integer>] [--max-output-bytes <integer>]
```

Require an explicit root and profile; no auto-detection from the presence of React or an implicit contributor cwd. Resolve the root once; every read and child cwd uses it. Reject missing, inaccessible or ambiguous targets before starting a backend. Validate paths and numeric bounds. Do not interpolate arguments into shell command strings. Preserve spaces, Unicode, nested cwd and native Windows path behavior.

Initial engineering limits: 60,000 ms per external process, 2,097,152 combined stdout/stderr bytes per process. Overrides must be positive integers, at most 300,000 ms and 16,777,216 bytes. The base script documents a 5–10 second typical target; the 60-second deadline is a provisional safety bound, not a measured performance guarantee. Record observed supported-run durations and adjust bounds only with a concrete case, keeping them finite. Kill timed-out/overflowed work with tested cleanup; never leave it running while returning a completed result. No automatic retries.

Target effects: reads only. No installation, network acquisition, repair, Git changes or persistent target writes. Requested diagnostics use an explicit location outside the audited tree; otherwise keep bounded diagnostic excerpts and state that full logs were not retained. Do not create a target-local log by default. Failure to write requested diagnostics is an error; continue independent read-only checks where possible and retain known findings. Bounded control-process tests may use a fake runner, but actual profile acceptance must execute shipped runners.

## §4 Family result and role

Exactly one family-local JSON result on stdout, stderr for launcher diagnostics. Define its concrete types/schema at the audit owner; do not add a global protocol. Required fields: resolved target, requested profile, selected runner identity, per-check identity/status, findings with original severity and actual locations where available, completeness/reasons, process exit and diagnostic references if retained. Derive counts from canonical findings. Do not manufacture missing line numbers or semantic advice.

Per-check states: `passed`, `violations`, `not-applicable`, `incomplete`, `error`. Severity of a finding is separate from whether acquisition/checking completed. Exit 0: all applicable work complete, no blocking violations. Exit 1: all applicable work complete with blocking violations. Exit 2: invalid invocation, incomplete work or execution error; known violations remain present. A soft warning alone does not block or imply incompleteness. No-clean result when any required work is unavailable.

The role reads target declarations and invokes this one command. Keep purpose, applicability/profile, runtime and backend prerequisites, explicit input/effects, result/exit interpretation, diagnostic pointer and semantic reporting obligations. Remove displaced script-selection/run/counter/drift recipes and manual report bookkeeping. The model explains relevance, suspected probe bugs and possible repairs; it cannot edit target/probe files or declare missing evidence passed.

No new broad event hook. Existing role/skill/native entry ownership supplies invocation. A deterministic test extracting and executing the role's actual invocation is caller-path evidence; it does not prove a real model chose to invoke it or a trusted native hook fired. Record these evidence layers separately.

| Case | Required observation |
| --- | --- |
| Controlled clean installed layout for each admitted profile | Correct root/runner/probe population, completed work, exit 0; real runner, not only a stub. |
| Missing declared skill/rule or actual probe violation | Intended identity/location/severity appears; unrelated stderr cannot satisfy the assertion. |
| Clean and debt-bearing JSON, negative/code-fence mentions | Structured parser discriminates; no regex substring false-positive substitute. |
| Malformed/unreadable JSON or unreadable directory plus known violation | Exit 2, completeness false, original violation retained. Test real read failure with appropriate permissions/controlled IO boundary; root-readable chmod alone is not evidence. |
| Required input/script/chained base missing | Main incomplete, auxiliary checks still run; no empty-population PASS. |
| Framework root with missing consumer script | Honest incomplete branch through the same command; not a positive control or fallback to another checkout. |
| Exit 0 + FAIL; crash/nonzero + no findings; empty/partial output | Contradictions/errors retained, never clean. |
| Skipped required tool; documented non-applicability; completed soft warning | Three distinct interpretations, not one WARN bucket. |
| Modified/custom runner or unknown output version | Explicit unsupported/incomplete; preserve consumer bytes. |
| Root path spaces/Unicode, nested cwd, wrong/missing target | Exact target honored or refused; no contributor-root fallback. |
| Timeout/output overflow/diagnostic-write failure | Bounded termination and cleanup, incomplete/error, prior findings retained. |
| Actual delivered command missing a dependency/resource | Installed test fails without contributor node_modules/import fallback. |
| Role invocation removed/bypassed; parser or completeness checker replaced by success-only behavior | Unchanged independent oracle fails for intended missing work/result. Direct helper tests alone cannot satisfy this row. |
| Over-rejecting checker | Clean companion fails the unchanged oracle for the intended excess rejection. |
