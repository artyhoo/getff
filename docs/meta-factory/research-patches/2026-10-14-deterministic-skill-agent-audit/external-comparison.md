## Main interpretation

Both are hybrids: human/LLM-readable workflow contracts plus actual deterministic mechanisms. Neither source supports the universal claim that every skill's behavior or every engineering principle is deterministic and enforced. A script can make a narrow invariant deterministic (schema, exact SHA association, diff pattern, CI-state classification); a model still selects the playbook, chooses experiments, interprets runtime observations and resolves semantic findings. Distinguish (1) instructions to write/run a script, (2) shipped script, (3) registered automatic hook, (4) required repository/forge gate. These are separate strength levels.

### Deterministic tools actually shipped

Complete pstack scripts-area inventory is in inventory.json. Production groups:

1. `check-plan.mjs` (Node). It validates a particular program-plan document structure, required sections/ordered PR sub-blocks, ten live lanes, screenshot filenames and pass-predicate wording, and metric/probe/baseline/rule perf boxes. It exits nonzero on detected structural violations: [lines 121–187](<https://github.com/cursor/plugins/blob/1e5c90a4b6f249917bd21fe361b3a2a7deb741b8/pstack/skills/poteto-mode/scripts/check-plan.mjs#L121-L187>), [exit](<https://github.com/cursor/plugins/blob/1e5c90a4b6f249917bd21fe361b3a2a7deb741b8/pstack/skills/poteto-mode/scripts/check-plan.mjs#L202-L205>). Important limit: code checks names/strings; it does not read screenshots, run lanes, verify evidence exists or decide a claimed PASS is true. It accepts both checked and unchecked boxes.
2. `orch/orch.ts` + `orch/store.ts` (Bun/TypeScript). A file-backed orchestration store: `units.tsv`, `ledger.tsv`, inbox, gates, frontier JSON, standing instructions, lock and atomic file writes. This is NOT SQLite. [store type/header contract](<https://github.com/cursor/plugins/blob/1e5c90a4b6f249917bd21fe361b3a2a7deb741b8/pstack/skills/poteto-mode/scripts/orch/store.ts#L17-L45>), [atomic-write/locking implementation](<https://github.com/cursor/plugins/blob/1e5c90a4b6f249917bd21fe361b3a2a7deb741b8/pstack/skills/poteto-mode/scripts/orch/store.ts#L330-L432>). It records verification rows against PR+SHA and returns NOT-VERIFIED if that exact pair is absent: [1401–1440](<https://github.com/cursor/plugins/blob/1e5c90a4b6f249917bd21fe361b3a2a7deb741b8/pstack/skills/poteto-mode/scripts/orch/store.ts#L1401-L1440>). Rows are mutable/replaced for a repeated PR+SHA, evidence is a required string, verifier is optional. Recording a row does not independently authenticate the verifier or inspect evidence.
3. `watch-pr/*`: CLI, GitHub adapter, pure policy, renderer, type contract and paired tests. Classifies conflicts, review-thread blockers, failing/pending CI and merge gates from snapshots: [policy 218–264](<https://github.com/cursor/plugins/blob/1e5c90a4b6f249917bd21fe361b3a2a7deb741b8/pstack/skills/poteto-mode/scripts/watch-pr/policy.ts#L218-L264>). Provides structured sequence/timestamp envelopes and bounded query retry. A readiness status is not the live behavior verdict demanded by Shipping; watcher does not itself merge.
4. `worktree-audit.sh`: worktree safety audit used by cleanup playbook.
5. `bootstrap.ts`: lazy deterministic dependency setup keyed by package.json+lock hash, installs frozen Bun lockfile: [17–61](<https://github.com/cursor/plugins/blob/1e5c90a4b6f249917bd21fe361b3a2a7deb741b8/pstack/skills/poteto-mode/scripts/bootstrap.ts#L17-L61>). Installation would mutate environment; not executed here.
6. `show-me-your-work/scripts/log.sh`: append TSV decisions, evidence and outcome with UTC timestamp; strips row/control delimiters and escapes formula-like leading characters: [1–42](<https://github.com/cursor/plugins/blob/1e5c90a4b6f249917bd21fe361b3a2a7deb741b8/pstack/skills/show-me-your-work/scripts/log.sh#L1-L42>). A decision ledger is a trace, not a verifier.

Tests exist for plan checker, orchestration store/CLI and watcher policy/GitHub/CLI. Their presence is code evidence; pass status was not established in this research.

### Live verification and screenshot evidence

[create-verification-skill](<https://github.com/cursor/plugins/blob/1e5c90a4b6f249917bd21fe361b3a2a7deb741b8/pstack/skills/create-verification-skill/SKILL.md#L11-L40>) instructs an agent to discover real launch/driver/observation surfaces and generate a project-local verify skill, helper scripts and a feature map. Evidence can be screenshots, PTY transcripts, responses, logs, exit codes or DB side effects. It demands an end-to-end smoke run and proof survives cleanup. It explicitly distinguishes real target from a stand-in.

[Visual parity](<https://github.com/cursor/plugins/blob/1e5c90a4b6f249917bd21fe361b3a2a7deb741b8/pstack/skills/poteto-mode/playbooks/visual-parity.md#L3-L8>) requires immutable baseline before migration, rerunnable image diff and zero pixel delta; this is a playbook requiring the agent to establish/run the harness, not a universal bundled screenshot oracle. Screenshot capture or a screenshot filename by itself does not prove behavioral correctness.

### Automatic merge: qualified YES, never universal/default

[Shipping](<https://github.com/cursor/plugins/blob/1e5c90a4b6f249917bd21fe361b3a2a7deb741b8/pstack/skills/poteto-mode/playbooks/shipping.md#L3-L10>) is a documented automatic landing procedure for a requested stack. Independent non-author verifier per PR runs parent vs head using real control surface; only contiguous verified bottom-up run can land; patch-id checks validate verdict continuity; `gh pr merge --squash`/Origin merge and readback distinguish requested/queued from actually merged. Existing verdict becomes invalid when patch drifts. [Autopilot-full](<https://github.com/cursor/plugins/blob/1e5c90a4b6f249917bd21fe361b3a2a7deb741b8/pstack/skills/poteto-mode/playbooks/autopilot-full.md#L7-L23>) assigns one owner per PR and independent root swarm, and allows owner merge only after root verification plus CI. It explicitly scopes the operator grant to queue items, keeps operator-owned gates/out-of-queue PRs at merge-ready, says a plan request is not go, forbids bypassing forge approvals and propagates operator stop.

General autonomy itself has Always-pause categories: [poteto-mode 81–87](<https://github.com/cursor/plugins/blob/1e5c90a4b6f249917bd21fe361b3a2a7deb741b8/pstack/skills/poteto-mode/SKILL.md#L81-L87>). The upstream scripts do not encode a cryptographic operator grant or enforce the entire shipping recipe; playbook compliance remains part of agent judgment. Do not summarize as “it automatically merges all tasks into main.”

## Independent port: substantive extra mechanisms

[README 255 onwards](<https://github.com/mdsmithaustin/pstack/blob/13c863b9c3ca0ddb7ceeab4daca4e69c5021a0d3/README.md#L255-L275>) and PORTING.md distinguish harness adaptations and port-owned additions. Examples: portable subagent launcher/persona payloads, model-config validator, skill listing/invocation policy, deslop, research/code-review playbooks, runtime/spec/command probes. [role-contract.json](<https://github.com/mdsmithaustin/pstack/blob/13c863b9c3ca0ddb7ceeab4daca4e69c5021a0d3/skills/poteto-mode/scripts/orch/role-contract.json#L1-L38>) enumerates harnesses and model role categories; it is explicit data, not runtime proof of model availability.

Most consequential: the port ships **merge-gate** absent from this upstream snapshot. [Nine explicit gates](<https://github.com/mdsmithaustin/pstack/blob/13c863b9c3ca0ddb7ceeab4daca4e69c5021a0d3/skills/poteto-mode/scripts/watch-pr/merge-gate.ts#L22-L55>) cover verdict, head, patch-id, checks, review bodies, threads, mergeability, draft and merge queue. [head/patch-ID policy](<https://github.com/mdsmithaustin/pstack/blob/13c863b9c3ca0ddb7ceeab4daca4e69c5021a0d3/skills/poteto-mode/scripts/watch-pr/merge-gate.ts#L144-L190>) allows moved SHA only with unchanged patch. Truncated review conversation is handled as unverified, not silently complete: [218–226](<https://github.com/mdsmithaustin/pstack/blob/13c863b9c3ca0ddb7ceeab4daca4e69c5021a0d3/skills/poteto-mode/scripts/watch-pr/merge-gate.ts#L218-L226>).

It really performs merge via `gh pr merge --squash --match-head-commit <sha>` and readback: [merge-effects 184–205](<https://github.com/mdsmithaustin/pstack/blob/13c863b9c3ca0ddb7ceeab4daca4e69c5021a0d3/skills/poteto-mode/scripts/watch-pr/merge-effects.ts#L184-L205>). CLI has `--check` and structured exit distinctions for refused/queued/merged. **However:** [CLI 78–85](<https://github.com/mdsmithaustin/pstack/blob/13c863b9c3ca0ddb7ceeab4daca4e69c5021a0d3/skills/poteto-mode/scripts/watch-pr/merge-gate-cli.ts#L78-L85>) and [runMergeGate 480–496](<https://github.com/mdsmithaustin/pstack/blob/13c863b9c3ca0ddb7ceeab4daca4e69c5021a0d3/skills/poteto-mode/scripts/watch-pr/merge-gate.ts#L480-L496>) explicitly permit `--override <reason>` to post failed-gates comment then execute the merge. It is an auditable escape hatch, not an unbypassable gate; source does not authenticate human authorization for the override. This is consequential for getff's “cannot silently bypass” property: visibility vs prevention are different.

Repository contributor checks live in `tools/gate-check.sh`, `.github/workflows/{lint,skill-checks,upstream-sync}.yml`, and tests under tools/tests. Portable skill/harness scripts have their own tests. Hundreds of code files in the snapshot are eval fixture projects, not hundreds of production automation commands. None of these harness-specific facilities should be attributed to Lauren Tan without checking upstream.

### Floor guard: real reference code with source-extracted contract tests
