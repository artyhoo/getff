# Dot relay — runtime operation

> **Authoritative for:** runtime operation of the dot relay — exact CLI commands, opaque transport contracts, existing identities, durable OFF, uncertain-execution recovery, timer install, and the no-merge boundary.
> **NOT authoritative for:** project goal — see [README.md#why-this-exists](../README.md#why-this-exists). Relay design semantics and the binding opaque amendment — see the state-dir `DESIGN.md` (`/Users/art/.local/state/getff-dot-relay/DESIGN.md`). Coordinator-side bridge duties — see `COORDINATOR-BRIDGE.md` in the same directory. Agent discipline — `.agents/roles/`.

The relay moves private review-derived work between the dot cloud chats and a local supervised executor, without any party printing packet contents. Implementation: `scripts/dot-relay/` (`contract.mjs`, `ledger.mjs`, `executor.mjs`, `cli.mjs`, `active-clock.py` (host-awake budget helper), plus the coordinator-side `bridge-runner.body.js`); tests: `node --test scripts/dot-relay/*.test.mjs`. CI wiring (F11): the five explicit test files run in the always-on `dot-relay-suites` job of `audit-self.yml`, wired into the required `ci-success` aggregate — the portable offline matrix (fake subprocess/cloud adapters, isolated temp roots, zero network/model calls, no secrets). The Darwin-only host-clock and host-surface arms carry `skip:` gates there (executor clock tests; CLI arms needing the boot id `kern.bootsessionuuid`, `plutil`, real process-table probes, or a single >128 KiB argv element that Linux `MAX_ARG_STRLEN` cannot deliver; bridge-runner cycle arms, which drive the real CLI tick/host reconciliation over isolated temp roots and collapse to `BLOCKED` off-Darwin), so a Linux CI run is portable coverage only and never host E2E / calendar-timer acceptance — a genuine supported-host test receipt stays a separate activation prerequisite (`HOST_E2E_UNVERIFIED`).

## HYBRID deployment limitation

Deployment mode is **HYBRID**, permanently recorded in the runtime `config.json`:

- The **coordinator** (root operator session) is woken by the owned launchd calendar timer `ai.getff.dot-relay` (six `StartCalendarInterval` firings at local hours 0/4/8/12/16/20, `RunAtLoad=true`, `KeepAlive=false`, never `StartInterval`) and drives the cloud tool transport by hand — the relay itself has **no cloud credentials and no cloud client**.
- The **executor** is one owned foreground GLM child (`/Users/art/.local/bin/glm`, model `glm-5.3`) supervised with exact pid/process-start/session identity; each solution execution deadline is 7200000 ms.
- Until the root coordinator supplies an activation receipt (`bridge-activated --automation-id …`), native status reports `bridge.state=PARTIAL_AWAITING_BRIDGE` and `bridge.active=false`. **Never claim a zero-token idle cloud relay** — cloud traffic only happens when the coordinator acts.

## Native execution in an existing Codex chat

An admitted `native-binding.json` selects `NATIVE_EXISTING_OWNER`. Its exact source files and owner-supplied authority, source acceptance, installation and receiver-contract artifacts are hash-bound. The native `tick` returns the existing owner identity; it never creates a GLM session, reserves a model attempt or debits historical counters. `supervise` refuses with `NATIVE_OWNER_REQUIRED`. Legacy GLM behavior remains for historical deployments without this binding; it is not the operative native route.

The native bootstrap runs on one owned four-hour heartbeat in the existing owner chat. Its typed push entry is `native-push --argv-json JSON --binding-sha256 SHA`: only the installed repository, actual working branch, observed push URL and exact ordinary `push origin HEAD:refs/heads/<task-branch>` tuple are admitted. Option variants, another remote/refspec and shell composition fail before git dispatch. This adapter changes no global policy, hook or provider setting.

`bridge-activated` in native mode additionally requires `--receipt-file`: the owned receipt binds the native installation and bootstrap to an actual ACTIVE heartbeat TOML with matching ID, target owner, four-hour recurrence and bootstrap hash. Absent, corrupt or moved admission leaves `bridge.active=false`; activation never clears durable OFF. Baseline holds and the frozen historical producer state are preserved until exact authorized consumption/ownership receipts are imported. Starting transport is not permission to replay completed analysis.

## Runtime root layout

`init --root ABS` creates (and later requires) exactly:

```text
<root>/ledger.sqlite      transactional ledger (node:sqlite, WAL, schema user_version=3; every migration commits its schema/data AND its version write in ONE transaction — a pre-atomicity crash image converges only when it matches the exact expected image, anything ambiguous fails closed with SCHEMA_MIGRATION_BLOCKED and is preserved untouched)
<root>/config.json        label, interval, deployment_mode HYBRID, source SHA
<root>/objects/<sha>.json published immutable envelope bytes, named by artifact sha256
<root>/spool/             in-flight upload state machines (<upload>.state.json journal, <upload>.whole.tmp, part temps)
<root>/inbox/<id>.json    metadata-put results (chunk-assembled, final-verified)
<root>/plans/bridge-plan.json   bounded metadata-only tick plan
<root>/worker/            supervisor lock, private child stdout/stderr/startup receipts (0600)
<root>/OFF.json           durable stop marker (when OFF)
<root>/timer.json         install-timer receipt
<root>/bridge-activation.json   coordinator activation receipt
<root>/bridge-runner-pin.json   reviewed pin of the deployed bridge-runner body (see below)
```

Root must be absolute, contain no literal `..` segment, and not itself be a symlink (`ROOT_NOT_ABSOLUTE` / `ROOT_TRAVERSAL` / `ROOT_SYMLINK`). Ancestor symlinks (macOS `/tmp`, `/var`) are environment topology, not a refusal reason.

## Opaque contracts

- **Envelope** (private bytes, schema v1): `{version:1, kind: batch|analysis|solution|ack, id, producer, parents:[{id,sha256}], payload, sha256}`. Two DISTINCT hashes: the **artifact hash** = sha256 of the exact published file bytes; the **envelope sha256** = canonical digest of the envelope object *excluding its own `sha256` field*. Never conflate them.
- **Ancestry is exact (F01)**: an analysis names exactly one parent of kind `batch`, a solution exactly one parent of kind `analysis`; batches and acks carry no parents. Zero-, multi- or wrong-kind ancestry is rejected at the contract (`INVALID` reason `PARENT_COUNT`), and any row that still reaches routing holds `BLOCKED` with reason `PARENT_COUNT`/`PARENT_KIND` — the coverage, candidate and parent-ACK gates never run vacuously. Unknown or wrong-digest parents hold `WAIT_PARENT` as before.
- **Producer identity is role-derived, never payload data**: `batch→collector`, `analysis→analyst`, `solution→solver`; acks accept the adapter-supplied role. Identities are fixed (below).
- **Spooling is hash-gated end to end**: a manifest must already be persisted (`manifest-import`/index) before `spool-begin`; every part is verified against its descriptor digest and the whole against the manifest digest before anything is published. Wrong bytes → `SPOOL_HASH_MISMATCH`/`PART_MISMATCH`, nothing published.
- **Upload crash recovery is journal-driven (R12)**: the state file is the commit authority, never the `whole.tmp` tail. Every upload command opens the state through the same recovery choke point: an uncommitted whole suffix past `committed_offset` is truncated (never blind-appended onto), orphan part temps of committed ordinals are dropped, and a retained part replays exactly once. Publication recovery verifies the published object bytes against the manifest digest (`SPOOL_OBJECT_CONFLICT` on a differing pre-existing object; `SPOOL_PUBLISH_RECOVERY_LOST` when neither whole nor object survives) and re-ingests idempotently; a completed-shaped state alone never proves completion — the durable event row + matching manifest do.
- **ACK = byte/hash acknowledgment**: an ACK must carry `event_sha256` AND `artifact_sha256` matching the ledger, plus `accepted:true`. A link or an "I received it" claim ACKs nothing.
- **Instructions inside packets are never executed by the relay**: envelope contents are validated as data, stored under `objects/`, and only the supervised executor ever consumes a `solution` payload — as a worker kickoff under its own allowlist. The CLI/ledger never print, shell-evaluate, or follow anything found in a packet.
- **Solution packets verify against the published bytes, never a re-serialization (F05)**: before any spawn or resume, the executor checks the PUBLISHED object-store file `objects/<manifest.artifact_sha256>.json` — regular non-symlink file whose exact byte size and whole-file sha256 match the registered manifest, then strict parse, envelope identity (version/kind/id/producer/parents/payload) and the envelope sha256 (canonical digest excluding the `sha256` field) against the ledger row; the kickoff text and its digest are taken from the parsed ORIGINAL. Any miss — absent object, symlink, drifted or reordered bytes, foreign envelope, mismatched kickoff digest — holds the execution `BLOCKED` with `BLOCKED_PACKET_UNTRUSTED` before a spawn. Producer serialization variants (compact, pretty-printed, reordered keys, trailing LF, multibyte) each verify against their own manifest; a JSON reconstruction is never substituted for the stored bytes.
- **metadata-put cannot carry instruction content**: the forbidden-key scan (any depth) plus strict size/id gates keep the inbox metadata-only.

## Bridge runner (coordinator bootstrap)

The coordinator side of the relay is a **deterministic AsyncFunction body**, not a model loop: `scripts/dot-relay/bridge-runner.body.js` is compiled by the trusted bootstrap as `new AsyncFunction('tools','config','emit', source)` and runs one bounded cycle per invocation.

- **Deployment flow (dual pin):** the operator reviews the body, then writes `<root>/bridge-runner-pin.json` (`{version:1, sha256, source_commit, reviewed_at}`). The bootstrap fetches the source with `bridge-source --expected-sha256 <pinned sha>`; the CLI refuses (`BRIDGE_SOURCE_UNTRUSTED`, before a single source byte is returned) unless the caller pin, the root pin file, and the actual file bytes all agree, the file is not a symlink, lives in the CLI directory, and is ≤64 KiB. The returned config is trusted: root, cli, node, expected sha, source commit, the three chat ids + coordinator id, the per-role Page registry (collector `page_070fdd367758819192e503c9cee51251`, analyst `page_955c5f291f78819199e9ba5da85bee76` — F04-corrected), `timer_adapter_required:true` (F08: the bootstrap must inject the validated `{setTimeout, clearTimeout}` pair before the body runs; the adapter itself is host-injected, never serialized), and fixed budgets (cycle 45 s wall, 10 events, 10 index pages).
- **Body sandbox:** no imports/require/process/Buffer/console/fetch/node:/Deno tokens anywhere in the source (enforced by test); the only surfaces are the three public cloud tools (`wait_threads`, `send_message_to_thread`, `chatgpt_space_read_page_reference`) and `exec_command`, which the body uses exclusively for env-wrapped, fully single-quoted invocations of this CLI scoped to `--root`.
- **Bootstrap validator:** the wrapper rejects any returned/emitted value that is not EXACTLY the fixed schema `{version:1, mode:'HYBRID', state, counts:{sources,deliveries,acks,executions}, blockers:[{code,event_id}]≤10, continuation}` (≤4096 B printable ASCII) → `BRIDGE_OUTPUT_REJECTED`; an exception outside the body → `BRIDGE_BOOTSTRAP_FAILED`. The body itself self-validates the same schema before emitting (a failure collapses to a minimal `BLOCKED`/`BRIDGE_EXCEPTION` object) and emits exactly once; the embedded marker comment must never appear in any output.
- **Cycle order:** `status` first (durable OFF → bounded `OFF` state, zero cloud calls; `recovery_import_pending` → bounded `RECOVERY_IMPORT_PENDING` state, likewise zero cloud calls and no tick/wait/send) → one idempotent `tick` → `plan`; F08 priority — `pending_uploads` recovery, then eligible delivery/receipt settlement (claim-first sends over ONE shared per-cycle `event_limit` cap) run BEFORE continuation acquisition and BEFORE new input is read; resume open index chains; `wait_threads` exactly once for the three fixed targets; import `{type:'ack'}` messages; follow locator index chains; then fetch manifests discovered by a refreshed plan and settle the freshly spooled work under the SAME cycle cap (acquisition can never out-spend settlement); commit the cursor. F16: each paged collection's cursor commits via `plan-advance` ONLY after the cycle durably processed every offered item — an OPEN index chain never advances (it must re-surface next cycle), a send-cap-deferred receipt page never advances, and locator cache loading never advances (those rows retire on generation completion); a page whose items all settled (or all recorded blockers) commits its cursor, so every eligible id surfaces exactly once per scan and nothing is skipped or duplicated across crash/restart.
- **Locator protocol (strict):** a thread message that is JSON and carries an `index`/`producer`/`status` key CLAIMS locator shape; it must validate exactly — keys exactly `{version, generation, index, producer, status}` with `version:1`, `status` ∈ `{READY, WAIT, BLOCKED}`, `producer` = the thread's role id, `generation` matching `[A-Z0-9][A-Z0-9-]{0,63}`, and `index:{page_id, reference, sha256, bytes}` (reference ≤1024 chars, 64-hex sha256, bytes 1..200000) — or the whole cycle is `WAIT` with `WAIT_PROTOCOL` (never a guess). Plain non-JSON chatter is ignored.
- **Index reference grammar (F04):** a resolution reference is a FULL opaque `library-file:<payload>` / `project-file:<payload>` target taken EXACTLY as the supported tool returns it — a slash is NOT part of the grammar (real Library targets are opaque ids), the nonempty payload is never decoded or rebuilt, and the bare type label (`library-file`/`project-file`, or an empty payload like `library-file:`) is NOT a full reference. A full reference is fetched directly (`INDEX_DESCRIPTOR_MISMATCH` unless sha256+bytes match the descriptor); the bare label alone enters the strictly role-gated Page fallback. Anything else is `INDEX_REF_UNRESOLVED` before any fetch of any kind.
- **Page fallback reads the real nested fields (F04):** the one bounded `chatgpt_space_read_page` search call answers with `structuredContent.page` where completeness is `page.selection.selection_complete === true` and canonical text is `page.content.blocks[].markdown` (string) — ≤16 blocks, ≤262144 UTF-8 bytes of markdown, label-verified full-reference candidates (`INDEX_PAGE_LOOKUP_FAILED`/`INDEX_REF_AMBIGUOUS`/`INDEX_REF_UNRESOLVED` otherwise), each candidate fetched and proven by exact digest+size before exactly-one-match wins and the resolution is persisted. An explicit access denial on ANY fetch (reference or page search) is a fixed hold (`SOURCE_READ_FAILED` / `INDEX_PAGE_LOOKUP_FAILED`) — never an inline materialization from other page content; the ≤49152 B inline fallback exists ONLY on the send path.
- **Chain and bytes:** each index page is fetched by reference and proven (sha256 + size, ≤200000 B) BEFORE materialization via chunked `metadata-put` + `index-import --expected-index-sha256`; artifact parts are spooled codepoint-safely (12 KiB chunks) through `spool-part-begin/append/finish`; an interrupted explicit part is re-begun (temp replaced).
- **Interrupted uploads resume, never restart (F09):** a `pending_uploads` entry carries its authoritative `phase` and `committed_offset`. Publication phases (`PUBLISHING`/`PUBLISHED`/`INGESTED`) dispatch straight to idempotent `spool-finish` — zero source refetch, zero new append. An `UPLOADING` implicit part resumes by refetching the source once, verifying it against the descriptor, and appending only the codepoint-safe suffix after the already-appended byte offset; a torn or foreign offset (and any contradictory commit image) holds `SPOOL_RESUME_UNSUPPORTED` with the original state retained. A manifest represented by a durable pending upload is never begun a second time — one upload identity survives recovery.
- **Sends:** claim-first; message = `DOT_RELAY_DELIVERY ` followed by the strict wrapper returned by `delivery-claim`: actual claim ID, event ID, canonical event digest, whole-file digest/size, destination and the exact original manifest string. The original manifest/envelope bytes are never rewritten. `delivery-verify` checks the wrapper against the actual CLAIMED row before the native bootstrap sends. The shared `receiveDelivery` parser verifies whole bytes, envelope identity/role/parents and both digests; when given ordered part texts it also verifies every part hash/size before returning the access ACK. Outcome: a decoded result echoing the destination threadId → receipt `sent`; anything else — error envelope, untyped failure, threadId mismatch, budget timeout (`CYCLE_TOOL_TIMEOUT`) → receipt `uncertain` + `SEND_UNCERTAIN`, never a blind retry (uncertain deliveries are no longer PENDING, so no later cycle re-sends). A failed or denied send NEVER falls back to inlining packet content — artifacts move only by verified reference (the same no-inline rule as the locator path).
- **Native cycle fence (F08):** `bridge-bootstrap` checks the caller's source pin and native-binding hash, injects real host timers and a structured `operation_exec` adapter, and executes the pinned body. `bridge-cycle-begin/end` retain cycle ownership; a filesystem mutex serializes ownership transitions. Every CLI mutation and MCP send gets an fsynced PENDING intent before dispatch, followed by a hashed captured result before DONE. Unknown outcomes keep the fence; a later cycle cannot clear it from a timeout or dead PID alone. Old cycle tokens cannot start later operations. The bootstrap retains tool promises and polls yielded CLI sessions rather than abandoning them when the body deadline expires. Actual installed source/receiver acceptance, schedule ownership and supported-host cycle evidence remain activation prerequisites; offline tests alone do not authorize start.
- **Replay-aware progress:** repeat effects (CLI replay receipts) do not count; a cycle with no first-time effects reports `IDLE`. Budget exhaustion with work pending reports `continuation:true` — the coordinator simply runs another cycle.

## OFF and resume

`off --reason` sets a durable OFF that survives restarts and blocks ALL admissions — ingest, delivery claims, execution claims, resume-attempt admission (`admitNextAttempt` refuses with `OFF` inside the admission transaction: no attempt row, no allowance charge, no active-row change), the `supervise` dispatch boundary, and manifest/snapshot/index imports (ACK-only `receipt-import` stays open so in-flight acknowledgments settle). A supervisor rechecks durable OFF immediately before every owned child launch (F02): if OFF wins the race the reserved attempt is retained unchanged — no spawn, no failure count — and the next tick reconciles it. `bridge-activated` records activation but cannot clear OFF. Resuming is a coordinator control action with evidence; OFF itself has no TTL and no auto-clear.

## Uncertain execution recovery

Executions that die without a durable terminal receipt hold their slot — never TTL-released, never blindly retried. Recovery is evidence-driven at two layers:

- **Process probes are three-way (F03):** every process-identity consumer (host reconciliation, supervisor lock, death proofs, the OFF/cessation ladders, tick-owner takeover) treats a probe as exactly one of `exact-live` (pid + ps `lstart` start text both match), `absent` (ONLY the documented OS-specific no-such-process result — BSD/macOS `/bin/ps -o lstart=` under `LC_ALL=C` exiting 1 with empty stdout), or `unknown` (thrown command, unexpected exit status, malformed/empty output, live pid with a differing start = reuse). `unknown` NEVER authorizes death, adoption, interruption, takeover or a signal: the row holds for a later tick as `uncertain-identity`. The one canonical adapter is `productionProcessProbe` in `executor.mjs` (re-exported for the CLI — never re-implemented per consumer). Same pid + different start is REUSED — never signalled. Production spawn failures arrive asynchronously (`error` event, not a sync throw): the wrapper owns the error, closes its capture descriptors, settles a `whenSpawnSettled()` boundary and classifies identically to the sync path (`BLOCKED_LAUNCH` / `BLOCKED_PERMISSION` / `UNCERTAIN_SPAWN`) — an unhandled `error` can never crash a supervisor, and a missing pid is never recorded as a live RUNNING child.
- **Host reconciliation (`reconcileHost`, run only by the owned scheduler tick)** decides each active row: `retain` (same boot, supervisor proven live), `adopt-monitor` (supervisor dead, exact child alive — a monitor adopts it, ZERO model spawns), `interrupted-host` (different boot — ids preserved for SAME-session resume), `uncertain-identity` / `uncertain-stop` (identity unprovable — including any UNKNOWN supervisor or child probe — or same-boot supervisor AND child proven dead with no receipt). Each decision carries the row's `session_id`.
- **Adoption is per-attempt and ownership-exclusive (F06):** every launch (run and resume) persists `worker/<execution>.a<attempt>.capture.json` BEFORE the spawn — the exact private capture files that attempt writes (strict writer: identical replay only; any drift or symlink holds with `BLOCKED_ATTEMPT_CAPTURE`). A monitor adopting a resumed child selects the CURRENT admitted attempt's capture through that manifest (legacy pre-F06 disks derive the name; attempt-1 files are never read for attempt ≥ 2), re-verifies the published packet original, the checkpoint contract (session-bound) and the immutable worker files BEFORE monitoring (fixed holds `BLOCKED_PACKET_UNTRUSTED` / `BLOCKED_RESUME_METADATA`, original bytes never rewritten), and takes the same exclusive supervisor lock a launch takes: the owner identity is durably recorded on the attempt row, a second concurrent monitor is refused with `SUPERVISOR_LOCK`, the attempt count never moves, and the slot is released on every monitor exit path.
- **Automatic same-session recovery from a DUE tick:** `interrupted-host` rows dispatch `supervise --resume` (SAME session, SAME worktree, next precharged attempt); `uncertain-stop` rows dispatch `--resume` ONLY when the `claude agents` census freshly PROVES that exact session gone (`verifiedDead`) — a live or unprovable census holds the row for a later tick. The supervise side re-proves session absence itself before admitting the attempt.
- **Supervisor lock (`worker/supervisor.lock`, R07):** ownership is acquired BEFORE any attempt reservation and reconciled conservatively — a previous-boot or proven-dead holder is taken over with the displaced bytes retained as `supervisor.lock.stale-<ts>` evidence; a live holder blocks (`SUPERVISOR_LOCK`), an unprovable one blocks (`SUPERVISOR_LOCK_UNPROVEN`). A stale lock therefore never blocks ordinary boot recovery and never burns a precharged attempt.
- **Explicit coordinator reconciliation** stays the path for everything else: `reconcileExecution({execution_id, evidence, decision})` where evidence must carry the exact session id and explicit operator/coordinator control prose; `CONFIRM_DEAD` moves the row to `ABORTED_UNCERTAIN` and frees the global slot.

Because `executions.solution_id` is UNIQUE, an aborted solution is **never re-run** — a repair round arrives as a NEW solution envelope (at most two recorded repair rounds per failure; a same-boot resume failure counts only when concrete — sleep/clock-death never does). A supervise child names its reserved row at open (`resumeReserved`); every other un-finished row found at process start is reconciled by the tick's host reconciliation — the safe direction is always "no second launch".

## No merge

The relay and the supervised executor **never merge, never arm auto-merge, never force-push** (`gh pr merge*`, `git push *--force*`, `git rebase*` are disallowed at the child allowlist level). `verifyPr` only VERIFIES, and its verdict is context-bound (F07): DONE requires the exact stable head SHA, the PR base matching the base the approval was granted against (`BLOCKED_BASE_MISMATCH` on a rebase under the same head), base `staging`, OPEN non-draft, no auto-merge, not CONFLICTING and never `UNKNOWN` mergeability, and the deployed required-check set — compared by check name AND app/workflow identity against the expected policy set — all `pass` with state `SUCCESS`.

App identity comes from a complete REST check-run snapshot for the exact head, using `filter=latest`, `per_page=100` and explicit pages. Each read admits at most 1000 runs and requires stable `total_count`, exact page lengths, unique positive run IDs and matching `head_sha`; missing, malformed or excessive evidence holds `BLOCKED_CHECK_POLICY`. Every successful CLI check must match exactly one run by name and link. Two runs sharing a link are ambiguous even when one app is trusted. The unique run must be completed with conclusion `success`, have a positive producing app ID, and match the policy-pinned app slug (`required: [{name, workflow, app}]`). Immutable run and app IDs must remain identical between the two verification reads; identity drift holds `BLOCKED_CONTEXT_MOVED`. Both paginated reads share the same fresh active-clock budget; page subprocess timeouts are capped by its remaining allowance, and expiry or backward clock movement prevents another page call.

Every gh subprocess call runs through a bounded adapter (F12): a per-call timeout, the documented pending/failing exit statuses parsed as data (exit 8 pending, exit 1 failing — never a throw), and infrastructure failures classified into fixed hold codes — tool missing (`GH_TOOL_MISSING`), auth (`GH_AUTH`), transport/timeout/undocumented exit (`GH_TRANSPORT`), unparseable output (`GH_MALFORMED`) — with raw stdout/stderr never surfaced. An infrastructure hold leaves the execution `VERIFYING` with its approval receipt untouched, so a later reconciliation resumes without a duplicate approval. Post-review verification consumes a finite durable budget (`review_verify_budget`: allocated once per execution, charged additively, capped, never replenished on replay); a missing or unproven budget holds `BLOCKED_VERIFY_BUDGET` instead of defaulting to unlimited polling, and exhaustion reports `BLOCKED_CI` with the still-pending names. Review approval is context-bound too: the receipt (schema v2) carries repository, PR number, base SHA, the policy snapshot, an explicit Dot GO and the immutable published source of the review evidence; receipt/disagreement holds are `BLOCKED_POLICY_MISMATCH` / `BLOCKED_RECEIPT_CONTEXT`, and a replayed historical receipt reports the historical outcome (`verified_now:false`) — it never projects fresh merge approval. Merge authority stays exactly where the repo's merge policy puts it.
