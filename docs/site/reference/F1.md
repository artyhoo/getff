# Rules

A [rule](../terms.md#rule) is a written convention that getff turns into an executable
artifact where it can: a test, a git hook, a CI check. Where nothing mechanical can
check the rule, it stays prose and says so. This page lists every rule the getff team
holds its own repository to, so you can find the one that governs what you are
looking at.

## When not to reach for this family

Do not expect getff to put these rules in your project. Every rule in this family
carries `ships-to: framework` on its fact card: the getff team holds its own
repository to these files and ships none of them to you. Reading them shows you the
discipline working on a real repository. To get the same effect in your project, copy
the pattern rather than the files: write the rule down, then give it the earliest
gate that can reach it — [How it works](../how-it-works.md) walks through that order.

A Class `C` rule stops nothing. Prose informs; a [gate](../terms.md#gate) blocks. If
a convention must hold even when the agent ignores it, it needs a gate. Whether a
given rule has one is exactly what the `class` row and the page's evidence section
answer.

The reverse holds too: a rule says what must not happen, a [skill](../terms.md#skill)
teaches how to do the job well. If your problem is that the agent does not know how,
start with the [skills family](B.md), not here.

## How to read a rule page

Every rule page opens with the same fact card. The rows:

- **name** is the rule file's name without the `.md` ending.
- **kind** is `rule` for every page in this family.
- **ships-to** is `framework` for every page in this family — see the first note
  above.
- **class** grades what stands behind the rule: `A` ships with an executable test,
  `B` with a named mechanism that is not a test, `C` is prose only.
- **description** is one line taken from the rule file's own header. When that header
  line wraps, the row reads cut short; the page's explanation always gives the full
  scope.
- **source** is the file and line the description was read from.
- **fires** repeats the header's `Fires:` line: the moments the rule applies.
- **channels** names where the rule reaches you, in the glossary's sense of a
  [channel](../terms.md#channel): edit-time, pre-commit, pre-push, CI, or production
  audit. Rules that ship no gate still list channels — that is where their text is
  delivered.
