# /night-mode — thin overnight layer over subagent-driven-development

Run a well-scoped implementation task to completion with **no human in the loop**. The dispatch loop — a coordinator dispatching a fresh implementer per increment, then two independent reviewers, with a rework loop to convergence — **is `superpowers:subagent-driven-development` (SDD)**. Use it. This skill adds **only** what SDD does not cover for an _unsupervised overnight_ run. If you catch yourself re-describing the executor/reviewer roster or the review loop, stop — that is SDD's job, and re-describing it is the `#parallel-evolution-creep` this project exists to prevent.

## The loop is SDD (do not reinvent)

Invoke `superpowers:subagent-driven-development` for the core: coordinator → fresh implementer subagent per increment → **two** fresh reviewer subagents (spec-reviewer ≈ top-down / architecture; code-quality-reviewer ≈ bottom-up / code) → rework loop. **Overnight model posture — relative capability tiers, not hard-coded model names** (so it degrades across harnesses and model sets exactly as SDD's «least powerful model per role» does — this subordinates to that framework, does not re-describe it). Assign each role a tier, then fill it with whatever the active harness offers: **top tier → advisor** (Claude: Fable); **next tier → executor + top-down (spec/architecture) reviewer** (Claude: Opus) — the quality-first floor for the overnight run; **cheaper tier → bottom-up code-quality reviewer + mechanical increments** (Claude: Sonnet). The window **slides** to the available set — Claude with no Fable → [advisor Opus, executor Sonnet, cheap Haiku]; another harness (e.g. GLM/zcode) → [its most-capable, its mid, its cheap]. If a harness exposes only ONE model tier, the advisor collapses to a **fresh-context same-tier second opinion** (a different context catches different things — not a stronger model), or is skipped. A per-session tier override (e.g. «drop the executor a tier for mechanical increments», «no advisor this run») is stated at launch. Advisor-consult mechanism: delta item 7.

> **Harness portability — agnostic with graceful degradation (NOT CC-only).** The loop needs only **sequential subagent dispatch**, which exists on CC AND on zcode/GLM — verified 2026-07-04: `~/.zcode/cli/agents/` holds real subagent sessions, `~/.zcode/cli/artifacts/sess_subagent_agent_*` are dispatches that ran, and zcode ships a **Settings → Subagents** surface. The CC-named primitives this delta uses are **capabilities with portable fallbacks**, not hard requirements: `Workflow` (context-economy) → keep the summaries-only discipline by hand where there is no Workflow tool; `ScheduleWakeup` (quota-backoff) → the harness's own sleep/resume, or a manual resume; `isolation:"worktree"` (parallel executors on disjoint files) → run **sequential** where the harness has no parallel subagents (zcode dispatches subagents but not in parallel — `skill-creator/SKILL.md:101`), which is SDD's default anyway; subagent **hooks** (digest/report injection) are absent on zcode (its event set has no `SubagentStart`/`SubagentStop`) → carry that discipline in the dispatch prompt instead. **Net: night-mode is _designed_ to run on any harness with sequential subagent dispatch; only the parallel-executor speedup and hook-based context-hygiene degrade.** The _precondition_ (zcode has sequential subagents) is verified 2026-07-04, but an end-to-end night-mode run on a non-CC harness is **not yet exercised** — per this skill's own §5, treat portability as _designed-not-proven_ until a live probe. It _targets_ the portable-with-graceful-degradation bar that `pipeline`/`dispatcher` meet **by test** (principle 21); night-mode has no such conformance test yet. Consumer-facing default = dual / graceful-degradation ([dual-implementation-discipline.md §2/§3](../../rules/dual-implementation-discipline.md)).

> **Cross-provider edge (Claude→GLM-5.2 executor inside aif).** When an in-aif coordinator (Opus/Sonnet) dispatches to a GLM-5.2 worker (aif-native via per-agent `model:` frontmatter), the input-prompt contract + GLM-5.2-specific behavioural deltas live in [`.claude/skills/claude-glm-executor-handoff/SKILL.md`](../claude-glm-executor-handoff/SKILL.md) — a thin adapter over this skill + `orchestrator-worker-discipline` + SDD. Its §5 honest-gaps marker is **designed-not-proven** until its research-patch probes land; do not assert GLM behaviour from inference.

## The overnight delta (all this skill actually owns)

1. **Unattended autonomy / fork policy.** No human overnight, so: **technical** forks (which impl is better on the merits; an open design decision) → resolve autonomously with recorded rationale. **Genuine owner** forks (taste/strategy with no determinate best on the project's merits) → append to `<plan>.decisions.md`, do NOT decide, do NOT block; surface in the morning report.
2. **Two-altitude whole-work pass.** After all increments converge, run ONE MORE review from BOTH altitudes over the ENTIRE assembled diff AND the whole plan, plus a completeness-critic («what task / acceptance-criterion / edge is unverified?») — beyond SDD's per-increment review. Cap per-increment rework at ~4 iterations; if unconverged → mark BLOCKED, log why, continue other increments (never wedge the whole night on one).
3. **Quota / backoff resilience** (ADAPT of AIF watchdogs, SSOT #45). The loop is upper-tier-heavy (Claude: Opus-heavy); on a `429` / rate-limit, back off with `ScheduleWakeup` (~20–30 min, or the harness's own sleep/resume) and resume — survive the rolling reset window rather than dying. Commit every converged increment durably so a restart loses nothing.
4. **Workflow context-economy.** Run the loop through the **Workflow** tool so only structured summaries return to the orchestrator context — never pull full diffs/code in. Track ONLY: which increment, converged?/blocked?, plan version, quota budget. New Workflow per phase; `resumeFromRunId` is only for a killed/edited run, not for new work.
5. **Verification discipline** (how to verify correctly when no human catches a wrong claim): **empirical over inferred** — any load-bearing claim about tool/harness/code behavior is _tested_, not asserted from «it follows from the model» (this skill's own diff-visibility fact below was first inferred, challenged, then proven by a live probe); **file:line not memory** (T3); **non-vacuous paired-negatives** — RED observed before GREEN (T15); **verify-against-source before ship** (re-check git/CI, never merge on recall); **adversarial** reviewers (a clean low-coverage review is «insufficient coverage», not «clean»).
6. **Harness fact — diff visibility (verified 2026-07-02 via a live `isolation:"worktree"` probe):** an isolated agent runs in a SEPARATE worktree — its UNCOMMITTED changes are invisible to a non-isolated sibling, but a COMMIT on a named branch IS visible via the shared `.git`. So the Executor **commits every increment** to the shared branch; reviewers read `git show <branch>`. Sequential loop → Executor non-isolated in the shared worktree; `isolation:"worktree"` only for genuinely-parallel Executors on disjoint files.
7. **Advisor strategy — Fable as on-demand advisor (subscription-native ADAPT of Anthropic's Advisor tool; [prior-art-evaluations.md #201](../../../docs/meta-factory/prior-art-evaluations.md)).** Anthropic's real [Advisor tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/advisor-tool) pairs a cheap executor (runs every turn) with a stronger advisor it calls on-demand over one shared transcript — but it is an **API-only** server tool, **not exposed in Claude Code or on a Pro/Max subscription** (verified 2026-07-04 via `claude-code-guide`). night-mode runs the same _strategy_ on subagents, subscription-only (operator directive 2026-07-04: run it on the subscription, not the API): the **executor itself flags a consult** — returning a `NEEDS_ADVISOR` note with the specific question (a night-mode convention, NOT one of SDD's statuses `DONE`/`DONE_WITH_CONCERNS`/`NEEDS_CONTEXT`/`BLOCKED`; its liveness is unproven until a live run) — when it hits a non-obvious design decision, gets stuck, or is about to declare done. This is **executor-initiated**, as in the real pattern (NOT the coordinator deciding for it). The coordinator then dispatches a **top-tier advisor** subagent (the most-capable tier — Claude: Fable; the harness's top model elsewhere; on a single-tier harness, a fresh-context same-tier reviewer) that reads the shared _committed_ context (item 6 — commit first so the advisor sees real state) and returns ≤~80-word focused advice; the **executor** is re-dispatched carrying it. The executor gives the advice weight but adapts if it empirically fails or a primary source contradicts it, and on an evidence-vs-advice conflict reconciles in one more consult rather than silently switching. Consult **sparingly** — highest value once before committing to an approach and once before declaring done, not on trivial reactive steps. **Honest gap vs the real tool (stated, not hidden):** context is coordinator-supplied (not auto-forwarded) and it costs extra subagent dispatches (not a single call) — accepted for a no-paid-API subscription run. The advisor _informs the approach; it never replaces the executor in the loop_ (advice-injection over model-swap — a refinement of SDD's `BLOCKED`-handler «re-dispatch with a more capable model», SDD lines 114–120).

8. **Standing authorization for an unattended run (the SSOT — `/pipeline` §7 and `/dispatcher` §2.4 point here, never restate).** Invoking this skill **IS** the operator's request to run the loop without confirmation rounds. Under it the session MAY, unprompted: (a) dispatch **read-only** cold-review subagents — [`agents/fidelity-auditor.md`](../../../agents/fidelity-auditor.md), [`agents/backward-sweep-auditor.md`](../../../agents/backward-sweep-auditor.md), [`agents/compliance-verifier.md`](../../../agents/compliance-verifier.md); (b) drive the `REVISE` rework cycle through `packages/runtime-bridge/src/cli/answer.ts --decision request_changes` within the 2-round cap; (c) push, open PRs, and squash-merge to `staging`. It MUST instead **escalate** on: a `base=main` merge, a **second consecutive** `REVISE` on unchanged scope, a `STOP` or `KICKOFF-AMBIGUOUS` verdict, or any parked owner-fork (delta item 1). **`#worker-dispatch-via-subagent` is NOT weakened and (b) does not touch it:** the auditors in (a) are read-only, already inside the envelope [`pipeline/SKILL.md §5`](../pipeline/SKILL.md) grants («Phase -1 read-only reviewer + read-only research subagents»), and the rework channel in (b) is REST — no subagent at all. Write-task Workers still go to a fresh session or to aif, never the Agent tool.
   **Substrate choice — the aif factory is `/dispatcher`'s loop, not a second copy of it.** When the executor substrate is the aif docker factory rather than in-session subagents, the dispatch → monitor → Q&A → **pre-egress fidelity** → harvest → stage-gate → `done.md` mechanics are [`.claude/skills/dispatcher/SKILL.md §2`](../dispatcher/SKILL.md) — invoke it, do not re-describe it, exactly as the loop above is SDD's. This skill contributes only the autonomy policy: the authorization above, item 1's fork policy, item 3's backoff, and the terminal condition below. The two substrates are the two columns of the acceptance contour's D6 rework table ([spec](../../../docs/superpowers/specs/2026-07-23-acceptance-contour-design.md)); the fidelity cap is 2 either way.
   **Honest classification — this is prose, not a mechanism ([attention-is-not-a-mechanism.md §1](../../rules/attention-is-not-a-mechanism.md)).** It mitigates a **server-delivered** session-prompt default («Do not call the AgentTool unless the user requested it») that lives outside this repo: not in `.claude/settings.json`, not in any tracked file, unreachable by hook or CI, and not a permission-mode effect — so it can be **decision authority only**, never a detection layer, and the fail-closed `pr-body-fidelity` gate remains the actual enforcement. **Falsifier:** if that default changes or disappears, this paragraph is a **no-op** (harmless, but buying nothing); if it ever hardens from a prompt append into a tool-level block, prose cannot help and the reachable channel becomes the harness. Evidence + why the phrasing-based immunity was illusory: [research-patches/2026-07-24-unattended-agent-dispatch-default.md](../../../docs/meta-factory/research-patches/2026-07-24-unattended-agent-dispatch-default.md).

## Terminal condition + morning report

Loop until: every increment done · both-altitude reviews green on the whole diff · the project's full test/gate suite green · own adversarial cold-review (T19) of the final diff · PR-body discipline gates satisfied (e.g. §1.7 sections each with a real `path.ext:N` citation; a new capability file needs a `Prior-art:` trailer — principle 11 F1 enforces it at pre-push; a stage PR additionally carries the `## Fidelity verdict` GO block from a cold [`agents/fidelity-auditor.md`](../../../agents/fidelity-auditor.md) run on spec+diff before `gh pr create` — the completeness-critic stays the deep in-loop check; the fidelity run is the cold boundary gate-grammar producer (spec D2); fidelity rework is session-local — cap 2 rounds (a counter separate from SDD's per-increment rework), Round tracked by the session, round-2 REVISE → STOP + a BLOCKED item in the morning report (spec D6 in-session column); on session crash the local Round resets — accepted gap (spec D10), the cap still bounds spend). If CI goes red after push → fix + re-push before merge. Merge to trunk if the harness pre-authorizes it and the call is clear. Then write a **morning report**: what merged, decision resolutions, BLOCKED increments, the owner-fork log, any degradation taken.

## Without this skill

Each unattended run re-improvises the parts SDD does not cover: it stops dead for a human on a technical fork (defeating «overnight»), silently decides an owner fork it should have logged, dies on the first quota reset, pulls full diffs into the orchestrator context until it drowns, and ships a load-bearing harness claim _inferred from the model_ — a wrong inference then corrupts hours of work with no human to catch it.

## With this skill

The executor + dual-reviewer loop is delegated to `superpowers:subagent-driven-development` (not re-described), and only the overnight delta is added: an autonomy policy that **logs** owner forks instead of deciding them, quota-backoff that survives the reset window, Workflow-driven context economy, and a verification discipline that **proves** harness claims before they become load-bearing — ending on a done, green, self-reviewed result plus a morning report.
