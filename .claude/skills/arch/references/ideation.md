## §1 Phase 1 — ideate + design (pure reuse)

Invoke `superpowers:brainstorming` AS IS: intent → clarifying questions → 2-3 approaches with trade-offs → design presented section-by-section → spec written and self-reviewed. Its user-review gate stands. Additionally, when the dialogue closes real forks with verdicts, record them with per-verdict falsifiers (H1 discipline) — as a research-patch decision record when the design closes a coverage gap (that folder's charter; established decision-record practice), otherwise inside the spec itself.

**Spec-format slot (P12, trio §A2 G1) — operator-axis ADOPT of the upstream `engineering:architecture` ADR template** ([spec D3 item (d)](../../../../docs/superpowers/specs/2026-08-06-pipeline-token-economy-design.md); [research-patch §A2](../../../../docs/meta-factory/research-patches/2026-08-02-knowledge-work-plugins-utility.md)). When that plugin is installed (`claude plugin install engineering@knowledge-work-plugins`), the spec produced by §1's brainstorming flow wraps its ADR template (Context / Decision / Status / Consequences); otherwise the same shape is hand-authored. Thin-wrapper only — the template body lives upstream, never re-described here (T16, `#parallel-evolution-creep`).

**Spec-template obligation (2026-08-10, [advisor-pattern-design §7/§8](../../../../docs/superpowers/specs/2026-08-10-advisor-pattern-design.md)):** every spec this contour produces carries an **operator-premise register** (verbatim-faithful = faithful to MEANING in context, never a naked transcript; transfer by copy-or-pointer, never paraphrase) and **per-decision falsifiers**. The register is the layer the recorded-premise test stands on ([reviewer-discipline.md](../../../rules/reviewer-discipline.md)): spec ≠ recorded idea — both required. **Live decision register (2026-08-17, operator-ratified D4):** the spec additionally carries a table `Decision | Status (answered / operator-fork) | Resolution | Falsifier`, grown **during** §1's dialogue as decisions settle — never reconstructed at close (T10: the population precedes the conclusions); the per-decision falsifiers above are its `Falsifier` column, and the §2 cold seats verify it as artifact content. **Testing seams slot (2026-08-18, [harmonization spec D-H14](../../../../docs/superpowers/specs/2026-08-18-skill-stack-harmonization-design.md)):** the spec also names its **testing seams** at spec time — where the design is verifiable through existing seams; prefer existing seams, ideal number is one; «seams: n/a — doc artifact» is a legitimate answer. Adopted from mattpocock `tdd`'s seams-first half WITHOUT importing its refactor placement (D-H2); the §2 cold seats check the slot is filled.

**Consensus retell (2026-10-01; incident 2026-09-29 in the header of `scripts/check-arch-retell.mjs`).** Whenever the operator is asked to confirm a design as agreed — a «do we agree?» summary, a retell before brainstorming's user-review gate, a retell after a compaction — the retell is written into the spec as a `## Consensus retell` section, never only into chat. Before writing it after any compaction, diff each claim against the last operator-confirmed commit of the spec (`git show <sha>:<spec> | grep …`) and the premise register: compaction summaries flatten who said what, and text the author wrote reads as agreed even when it is not. Template:

```markdown
## Consensus retell

Baseline: <SHA of the last operator-confirmed commit of this spec> | none — first retell

| #   | Claim   | Source                   |
| --- | ------- | ------------------------ |
| 1   | <claim> | operator «<their words>» |
| 2   | <claim> | P3                       |
| 3   | <claim> | register D4 (blanket)    |

### Unconfirmed — author derivations

- <claim> (source: author)
```

A `Source` cell is one or more of `operator «…»`, `P<n>`, `register <row-id>`, joined by `+` or `,`; mark `(blanket)` when the operator agreed to a batch rather than to this detail. A claim with no operator quote, premise or answered register row goes to the unconfirmed list — never into the table as `author`. In the framework repo `scripts/check-arch-retell.mjs` gates every such section (pre-commit on staged specs, CI over `docs/superpowers/specs/`): source grammar, one non-empty table, each cited premise or row recorded as a register entry outside the retells, the unconfirmed subsection present, and the Baseline SHA resolving at the commit that writes it (CI checks only its shape — a squash-merged design branch is deleted). It checks the tag, not its truth — whether a claim matches the row it cites, and whether that row is answered, stay the §2 cold seats' job — and it fires only where the section exists. A consumer install ships no such script, so there this template is the whole contract.

**Round form for batched questions (D-D, [spec :220](../../../../docs/superpowers/specs/2026-09-13-plain-words-recap-v2-design.md), operator-ratified 2026-09-13).** A round is ONE block per batch, not one message per question. Its section 0 — the recap's `AIF_EOT_SEC_WHERE` header — appears **once** per round: the goal plus what the previous round's go-ahead reply or silence accepted. Then **one FULL fork card per question** in upstream grilling's numbered `❓ Qn / ➡️` form — a card is never shortened to fit a cap. Then **one** closing line that IS the block's section 5 in the D-B gate scope (R-17: the gate reads the last line): the `AIF_EOT_FOR_YOU_PREFIX` line whose `decide:` value names the questions wanting an explicit answer, marks the reversible ones as free to stay silent, and states that a bare go-ahead accepts every recommendation at once — never a second section 5; a block carrying both a separate section 5 and a separate closing from-you line is malformed. Must-answer questions per round ≤ 4 — the cap binding (c) above already carries for the button arm, and it is the only cross-source numeric cap the prior-art pass found; a longer frontier splits by prerequisite depth, roots first. Reversible forks may be left to the recommendation; taste, goal and irreversible forks need an explicit answer. The verbatim ratified wording (RU) is the spec's — this paragraph owns the shape; the lang packs own the strings.
