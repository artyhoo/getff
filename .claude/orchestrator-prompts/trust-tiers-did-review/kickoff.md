## 3. The 4 items (grounded findings — verify, don't inherit)

Each finding below was independently traced by a prior session against `origin/staging`. **Treat it as a lead to re-run, not a verdict to accept.** Where the operator's original acceptance and the independent grounding agreed or disagreed is stated honestly.

### Item C — Union `homepage ∪ repository` trust (`allowlist-resolver.ts:182-199`)
- **Gap (confirmed):** Tier-1 derivation trusts BOTH a direct dep's `homepage` host AND its `repository` host. A self-hosted `repository` (e.g. `git.attacker-corp.example`) is not in `multi-tenant-hosts.json`, survives all guards, becomes trusted **scope-locked to that package**.
- **Reachability = CONDITIONAL.** Grounding could NOT construct a path from untrusted-only inputs: (1) plan JSON alone lets the attacker name only hosts the real dep *already declares* (trusted hosts come from installed metadata, not the plan); (2) attacker-controlled `repository` metadata only trusts a host if the package is *already a direct dependency*, which requires the consumer to have chosen to install it — at which point npm already ran arbitrary lifecycle code (a strictly larger grant than a scope-locked docs host). **Operator's acceptance HELD.**
- **Fix shape (~10 LOC):** tag each host with its source field; add a flag (e.g. `AIF_TIER1_REPO_HOST=off`) that drops repository-derived hosts. Paired-negative: a package whose only host source is a self-hosted `repository` (no `homepage`) yields no Tier-1 host when repo-trust is off, yields it when on.
- **Lean: either-defensible**, tilting keep-documented — harden-criterion is incident-driven ("split if repository-host abuse observed distinct from homepage-host abuse") and no such incident exists; building the split now risks build-ahead-of-need.

### Item D — Dep-name path-traversal in `installedPkgJsonPath` (`ecosystem-npm.ts:12-15`)
- **Gap (confirmed):** `join(root,'node_modules',...segments,'package.json')` with no `..`/`/`/empty rejection. Proved live by grounding: `installedPkgJsonPath('/tmp/.../consumer','../../../etc/passwd')` escapes `node_modules` entirely.
- **Reachability = NO.** The first thing `tier1For` does is `if (!listDirectDeps(ctx.root).has(packageName)) return {ok:false}`. `listDirectDeps` reads the **consumer's own** `package.json` (trusted) and `Set.has` **never calls `join`**. A traversal name is not a key in that trusted set → dropped *before* `join` ever sees attacker input. The `join`-with-attacker-string path is strictly downstream of the `.has()` gate. **Operator's acceptance HELD.** (This is the item to actually re-run — see §7.)
- **Fix shape (~8 LOC):** reject `..`/`.`/empty/absolute segments in `installedPkgJsonPath` (covers both `listDirectDeps` and `readInstalledMeta`), or a post-resolve `startsWith(join(root,'node_modules'))` assertion.
- **Lean: either-defensible**, marginally toward the cheap guard on defence-in-depth grounds (removes a whole "prove it's unreachable" class), but keep-documented is not wrong given confirmed no-reachability + a clear harden-criterion ("reject `..`/`/` if a non-`package.json`-controlled dep source is ever added to the ecosystem-adapter seam").

### Item F — `ackFilePath` no path-containment (`allowlist-resolver.ts:159-161`)
- **Gap (confirmed):** `loadAckFile(ctx.ackFilePath ?? default)` → `readFileSync` with no containment/normalization.
- **Reachability = NO.** `resolveCtx` is a **separate argument** from the untrusted `plan` in `validateResearchPlan(plan, resolveCtx?)`; `parsed` (the untrusted plan) is never read to construct `resolveCtx`. `git grep ackFilePath` over `packages/` returns only the type def, the read site, the bundle copy, and one test — **zero production ctor sets it**; both real callers pass `{root, adapter}` with no `ackFilePath`. `root` comes from `process.cwd()` / a positional CLI arg (out of threat model). **Operator's acceptance HELD.**
- **Fix shape (~12 LOC):** resolve the effective ack path, assert it stays under `resolve(ctx.root)+sep`, throw `AckFileError` otherwise. Paired-negative: `resolveAllowedSources({root:'/tmp/consumer', ackFilePath:'/tmp/consumer/../../etc/x.json'})` THROWS.
- **Lean: either-defensible.** Reachability genuinely no; harden-criterion sound ("if a plan-controlled ack path is ever introduced, add containment"). Do NOT escalate absent that seam.

### Item B — Bare-TLD / single-label ack host (`loadAckFile`, `allowlist-resolver.ts:82-95`) — **operator's LOW-confidence item**
- **Gap (confirmed):** `loadAckFile` rejects IP-literals + malformed dates + dup keys but NOT single-label hosts; `hosts:["com"]` is schema-valid (`minLength:1`) and `hostMatches` treats it as authorizing any `*.com`.
- **Reachability = NO.** Acks are read only from the consumer's committed `.ai-factory/research-allowlist.json` (or `ctx.ackFilePath`, never plan-set). Plan JSON can only *match* an existing ack key, not create one. No code writes the ack file (no `writeFileSync` near ack/allowlist). Live-research path calls the **one-arg** `validateProvenance` = Tier-0-only (empty tier2 Map) → acks never consulted on the LLM path. So a bare-TLD host can only enter via a **human-reviewed, PR-merged** file (DN #2 boundary, cargo-vet precedent, SSOT #186). **Independent grounding CONTRADICTS the operator's low-confidence worry — acceptance HELD under a fresh run.** But the operator asked for exactly this to be re-run independently, so **re-run it (§7), don't inherit even this.**
- **Fix shape (~6 LOC):** in the same per-host loop that rejects `isIpLiteral`, add `if (!h.includes('.')) throw new AckFileError('single-label host ...')`. Paired-negative mirrors the existing IP-literal negative at `allowlist-resolver.test.ts:58`.
- **Lean: either-defensible**, leaning slightly toward code-fix-now — the fix is **thematically identical to guards already shipped in the same function** (IP-literal/date/dup are all fail-closed pre-validation of this same trusted file), and a hand-editor typo (`"com"` meaning `"docs.com"`) silently widens trust to a whole TLD with zero load-time complaint. Consistency-with-existing-guards is the strongest code-fix argument in the set.

## 4. The decision to make

**Per item:** `keep-documented` / `code-fix-now` / `restructure`. **Plus the meta-question:** is the "document-not-code" **posture** sound, or should §5 be restructured?

Prior meta-review verdict (for you to challenge, not adopt): **posture SOUND with one binding condition.** "Document-not-code with a harden-criterion" is legitimate *in this project* — it is the shape of the peer Class-A `ci-tool-pinning.md`, which §5 already cites. But that precedent is precise: `ci-tool-pinning` defers a **non-exploitable** hardening AND **refuses to state it as a prose MUST** (a prose-only MUST the repo violates = `#trap-stated-but-not-enforced`). §5 stays on the right side of that line — it frames all four as *accepted risk / defence-in-depth*, not as unmet MUSTs. The posture holds **only while the reachability claims remain true**, and two harden-criteria are triggered by events with **no mechanical detector today** ("if ack files ever bypass human review" — B; "the moment Path B activates" — §2). Those are the armed-but-not-fired triggers that rot.

**Decision framework — apply all six signals per item:**
1. **Reachability from untrusted input (decisive gate).** Prove with a call-graph trace + file:line whether an attacker-controlled value can reach the unguarded parameter TODAY. If **NO** → a guard can't fire on real input → coding it = `#discipline-theatre` → keep-documented. If **YES** → code-fix-now regardless of the other five (a reachable trust gap in a trust rule is not deferrable).
2. **Can a paired-negative use a REAL input?** Sketch the positive arm: can you construct an input the *actual* call graph produces that makes the guard fire? If the only way to fire it is to fabricate an unreachable input → the test is theatre → don't code it. (Mechanical proxy for signal 1.)
3. **Fix cost vs trigger-detector cost.** A one-line, no-new-surface guard (e.g. B's single-label reject) with an honest real-input test may be cheaper AND safer than a rot-prone prose trigger — *only if signal 2 passes*. If the fix needs plumbing that doesn't exist yet (D's "non-package.json dep source"), building the guard means building the vulnerable seam first = worse; defer.
4. **Thematic centrality.** This is a trust rule; items on the trust boundary itself (B — what an ack grants; C — union of trusted fields) are more central than input hygiene on already-trusted plumbing (D/F). Higher centrality *raises the bar for keep-documented* (a central residual MUST have a swept trigger) but does NOT by itself force code — a central-but-unreachable item coded is still theatre.
5. **Scope / plan constraint (necessary, not sufficient).** S3 was docs-only; the resolver is S1/S2 files. A code guard is a cross-stage change on a security surface → a reason to **sequence as a separate atomic PR**, never a reason to leave a *reachable* gap unfixed. If signal 1 says reachable, scope means "new PR now", not "document forever".
6. **Harden-criterion sweep-detectability (the keep-documented admission ticket).** An item may stay documented **only if** its trigger is greppable/CI-detectable, not a prose promise that decays. Check each: D's "non-package.json dep source added" is detectable (a test asserting the ecosystem adapter's only source is `package.json` breaks when a second source lands); B's "ack files bypass human review" and §2's "Path B activates" require a human to remember → add a lightweight tripwire (e.g. a `principles/30` assertion pinning that `loadAckFile`'s callers pass a human-merge-gated path, or a pinned test that Path B is absent) so the trigger fires mechanically. An item whose harden-criterion cannot be made detectable should be **re-examined for code-fix-now** rather than left un-swept.

**Net default (challenge it):** all four are currently unreachable → keep-documented is defensible for all four *as risk-acceptance*. The actionable work is likely NOT four guards; it is (i) re-verify each reachability claim with fresh file:line evidence, and (ii) convert the rot-prone triggers (B, D, §2 Path-B) into sweep/test tripwires so §5 cannot silently become a lie. **But item B and item D each have a real code-fix case on cost + consistency/defence-in-depth grounds — hold that open through your own re-run.**
