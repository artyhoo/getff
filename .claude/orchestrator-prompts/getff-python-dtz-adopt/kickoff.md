# getff-python-dtz-adopt — close the naive-datetime middle case with ruff DTZ005

> **Type:** I-phase-small, single stage = one PR onto `staging`.
> **Origin:** the `KICKOFF-AMBIGUOUS` parked by `getff-honest-signals` S3 (#1150), raised to the operator and **approved** 2026-07-25.
> **Base branch:** staging.
> **Sequencing (binding):** dispatch ONLY after `getff-honest-signals` closes (S6 + `done.md`). This edits `packages/core/templates/python/ruff.toml` and shifts the python install baselines — the same generated artefacts S4/S5/S6 regenerate. Running it concurrently guarantees a baseline collision.

## §1 The gap (measured, not asserted)

S3 (#1150) narrowed both astgrep datetime rules from `datetime.now($$$ARGS)` to the zero-arg literal `datetime.now()`, so the recommended `datetime.now(timezone.utc)` stopped false-positiving. Correct, but a zero-arg literal makes **every** other argument form GREEN — including `datetime.now(None)`, which is still a naive read and is statically provable.

`packages/core/backends/ruff/render-ruff.ts:32` explains why astgrep owns this at all: `kind: 'call'` is **refused** (`FF7001`) by the ruff custom-rule path — «ruff bans a qualified NAME, it cannot express a call-site arg pattern». That is true of ruff's **custom-rule** surface (the closed flake8-tidy-imports vocabulary). It is NOT true of ruff's **built-in** rules, and `DTZ005` is built-in.

## §2 What to build — ADOPT `DTZ005`, narrowly (DECIDED, do not widen)

Emit `DTZ005` into the shipped `ruff.toml` `[lint] select`.

**Selector is `DTZ005`, NOT the whole `DTZ` family.** Verified live on ruff 0.15.21 — enabling all of `DTZ` double-reports `utcnow()`: our `TID251` banned-api entry AND `DTZ003` both fire on the same line. Two owners for one signal is the exact defect class the parent umbrella exists to remove. `DTZ005` alone gives:

| Input | With `select = ["TID251","TID253","DTZ005"]` |
|---|---|
| `dt.now()` / `datetime.datetime.now()` | `DTZ005` — RED |
| `dt.now(None)` / `datetime.datetime.now(None)` | `DTZ005 tz=None passed to …` — RED (**the gap**) |
| `.now(timezone.utc)`, both forms | not flagged — GREEN (the remedy stays clean) |
| `datetime.datetime.utcnow()` | exactly ONE report — our `TID251`, no `DTZ003` duplicate |

**Where the change goes.** `ruff.toml` is generated (`# generated by getff ruff backend v0 — do not edit by hand`), so edit the emitter, not the template. The site is `packages/core/backends/ruff/render-ruff.ts`, the `[lint] select` block:

```ts
const codes: string[] = [];
if (bannedApi.length > 0) codes.push('TID251');
if (bannedModules.length > 0) codes.push('TID253');
```

**Two things that block a naive edit — handle both:**

1. **The early return above it** — `if (bannedModules.length === 0 && bannedApi.length === 0) return …` exits before `[lint]` is emitted at all. A built-in selector is independent of whether any custom ban exists, so a config with zero custom bans must still get its `[lint] select`. Decide and implement the correct behaviour for that path.
2. **The closed-vocabulary design.** `render-ruff.ts:10` states the custom-rule surface is deliberately closed. Introducing a built-in selector is a **new, separate concept** ("built-in rules we opt into") — keep it visibly distinct from the generated-ban codes rather than smuggling it into the same list unexplained, and say in the code why the `kind:'call'`/FF7001 refusal does not apply to it.
