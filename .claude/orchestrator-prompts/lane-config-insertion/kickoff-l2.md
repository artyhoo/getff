**Deviations (declared):**

1. **The go CI `elif` branch.** `packages/core/templates/go/github-actions-ci.yml:67-78` runs
   `golangci-lint run --enable forbidigo --config .golangci.yml` whenever `getff-golangci.yml` is
   absent — that reads a consumer-owned `.golangci.yml`, which D9's falsifier forbids (spec §8
   D9). Spec §4.0 calls go «unchanged». L2 guards the `elif` with the getff header
   (`grep -q 'generated by getff'`, the same test `_lane_delivered_config_path` uses,
   `setup.d/lib.sh:1561` staging) and sends a header-less file to the new `else` behaviour
   below. Reason: I5 («every getff CI gate enforces getff's bans from a getff-owned config»)
   binds the go gate too.
2. **The go `else` branch — red, not green.** The spec says the branch «learns D11's lookup names
   so a `.golangci.yaml` consumer does not pass green while enforcing nothing», without naming the
   action. L2 makes it **fail** (exit 1) with a reason line when any D11 golangci name exists and
   no getff-owned config does. With no golangci config at all, it keeps today's message and
   `exit 0`. The CI failure line states the fact («getff's go bans are not enforced: no
   getff-owned golangci config in this repository»); it is CI output, not an install step, so
   umbrella §0.1 is not touched.
3. **This stage does not insert anything.** A newly detected consumer config lands in the existing
   REFUSE cell (reference copy plus a NOT-wired line naming the **actual** file). L3-L5 turn those
   cells into insertions.

Each result becomes **one lookup list per tool, held in one place** (a named array in

answer changes which cell a consumer lands in, where the spec does not say which wins → STOP
(umbrella §4). Park it as a question.

## §11 AI traps ([ai-laziness-traps.md §2](../../rules/ai-laziness-traps.md))

**Active traps: T3, T10, T12, T14, T15, T19, T21.**

- **T10 / T12** — the lookup list comes from the probe on the pinned binary, not from memory of
  the docs; a DeepWiki answer is a hypothesis until the probe runs.
- **T14** — a green LN arm on a fixture that never reached the collision branch is not coverage;
  each arm asserts the NOT-wired line text, not only the absence of a file.
- **T15 (mandatory)** — self-application: which lookup list does *this* repository's own lint
  tooling use for the three tools, if any? Record the answer in the Backward-check.
- **T21** — Backward-check class: «a lane hard-codes one config filename its tool does not
  exclusively load». Sweep every `[ -e "$PROJECT_ROOT/<name>" ]` in the three lanes and in
  `install.sh`'s lane table (`install.sh:265-324`).
- **T-LCI-C (domain)** — L1 and #1890 have both rewritten these functions; editing by staging
  line number edits the wrong code (umbrella §8).
- **T-LCI-E (domain) — «detected» ≠ «loaded».** A file existing on disk is not the file the tool
  loads (two names in one directory: only one wins). The cell choice follows the probe's winner,
  and the NOT-wired line names that winner.
