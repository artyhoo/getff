## §2 Deliverables

1. **`packages/core/docs-engine/resolver.ts`** — one module, imports from `node:*` only, exporting at least:
   - `resolvePlace(ref: string, read?: (p: string) => string)` → a DISCRIMINATED success: line-bearing kinds `h:` / `fn:` / `L:` return `{ kind, path, content, startLine, endLine }` with truthful bounds; `jp:` returns `{ kind: 'jp', path, content }` — `startLine` / `endLine` OMITTED, because `JSON.parse` supplies no positions and fabricated bounds are forbidden (S4 consumes the canonical signature; it must not invent line bounds). Errors are structured values `{ code: 'MISSING' | 'AMBIGUOUS' | 'UNSUPPORTED', message, ref }`. The injected `read` keeps the core pure and fixture-testable (the `:194-196` pattern); the default resolves repo-relative POSIX paths from the repo root.
   - **Path admission (every kind, before any read).** `<path>` must be a relative POSIX path; an absolute path, or one whose normalization escapes the repo root (`..` traversal), is rejected with `UNSUPPORTED` BEFORE any file is read — the same lexical admission the citation checker applies (`scripts/check-line-citations.mjs:529`: `if (!c || c.startsWith('..') || isAbsolute(c)) continue;`). The default reader additionally refuses filesystem escape through symlinks: after realpath, containment inside the repo root is re-asserted; escape → `UNSUPPORTED`. The injected-`read` route obeys the same lexical admission — an absolute or escaping path never reaches the reader. Diagnostics carry the ref only, never host-file content.
   - `canonicalJson(value: unknown): string` — recursively sorted object keys (arrays keep order), compact `JSON.stringify`, no trailing newline. THE canonical form of E-1 `jp:` and E-3's lock.
   - `signature(content: string): string` — CRLF→LF, then strip trailing spaces/tabs per line, join with `\n` (no trailing newline added), sha256 hex. Exactly these two normalisations, nothing else.
   - **Grammar.** `<path>#<kind>:<name>` for `h` / `fn` / `jp`; `<path>:NN` or `<path>:NN-MM` for `L`. `jp:` with an EMPTY `<name>` — `<path>#jp:` — is valid: the RFC 6901 empty pointer (the whole document). An empty `<name>` for `h:` or `fn:`, a ref with no `<kind>:` token (`<path>#`), an unknown kind token, or `NN-MM` with `NN > MM`, is `UNSUPPORTED` — a grammar refusal, not a `MISSING`.
   - **`h:`** — both GitHub heading forms, per E-1 (which says "markdown heading", not ATX-only): ATX `^ {0,3}#{1,6} ` (levels 1-6, slug from the heading text) and SETEXT per [CommonMark 0.31.2 §4.3](https://spec.commonmark.org/0.31.2/#setext-headings) — a PARAGRAPH: one or more consecutive non-blank, non-fence TEXT lines with no intervening blank line, immediately followed by `^ {0,3}=+$` (level 1) or `^ {0,3}-+$` (level 2). The slug is computed over the paragraph's text lines JOINED with a single space — the newline never reaches the transformation — then the §1 transformation applies (`Foo` / `bar` / `===` → `Foo bar` → `foo-bar`); ALL text lines plus the underline belong to the heading, and `startLine` is the FIRST text line. A `#`/underline inside a fenced code block is not a heading. Dedup is github-slugger's collision-aware EMITTED-slug dedup (§1 — `Alpha`/`Alpha-1`/`Alpha` → `alpha`/`alpha-1`/`alpha-2`), which makes emitted slugs unique, so `h:` never returns `AMBIGUOUS`. Content = the FIRST text line through the line before the next heading of the SAME OR HIGHER level (either form) or EOF — note the level arithmetic: a level-2 heading does NOT close a level-1 section, so a setext-1 section CONTAINS its `##` subsections (§7.7 fixture).
   - **`fn:`** — the supported carrier forms, per E-1 ("shell or JS/TS top-level function") with the repo's real surfaces as evidence (no silent declaration-only narrowing): shell `^<name>() {` AND the ksh form `^function <name> {` — the P16 tested input (`scripts/check-bash32.test.sh:88`) evidences the OPENER spelling only: its body closes INLINE (`}` on the same line), which is valid ksh but NOT E-1's column-0 boundary, so E-1 is NOT silently expanded to inline closes. JS/TS `^(export )?(async )?function <name>(` AND top-level arrow consts `^(export )?const <name> = (?:async )?\(` (real carrier: `packages/core/render/render-rules.ts:43,56,64`). Content = the signature line through the SYNTACTIC function-closing brace at column 0 — the §7.8 positive carrier fixture spells the ksh form with a multiline body and an actual column-0 close; a `}` at column 0 that lies inside a comment, string literal, or TEMPLATE LITERAL (JS/TS) or inside a HEREDOC body or quoted string (shell) does NOT close (a per-carrier lexical scanner tracks those regions; a full parser is NOT required). A DETECTED ksh opener whose body closes with an INLINE brace (the valid one-liner shape — P16's `function a { … ; }`) is explicitly REFUSED: `UNSUPPORTED` naming the inline close, the binder falls back to `L:` — the resolver never scans past it into sibling code and never reports `MISSING` for a function that exists (§7.8 negative fixture). More than one distinct top-level match for the name → `AMBIGUOUS`; none → `MISSING` (other spellings simply not matched — the binder falls back to `L:`); python `def` and other languages → `UNSUPPORTED` (parked q5).
   - **`jp:`** — RFC 6901 pointer, evaluated exactly as this bullet specifies. Root addressing: the EMPTY pointer (`<path>#jp:`, an empty `<name>`) is the whole document; `<path>#jp:/` is the single empty-string token — the root object's member NAMED `""`, never the document itself (RFC 6901 §4: ""-token = the member with the empty name; an empty token applied to an array root is an illegal reference). Unescaping follows RFC 6901 §4's stated order — encode `~`→`~0` then `/`→`~1`, decode the REVERSE: every `~1` → `/` first, then every `~0` → `~`; so `~01` names the member `~1`, never `/`; a bare `~` not followed by `0`/`1` is an illegal reference. Arrays: a token applied to an array must be a decimal index with NO leading zeros — `01` → illegal, and `-` (the after-last member, a JSON Patch notion) → illegal; both `UNSUPPORTED`. Error taxonomy for evaluation, per RFC: `UNSUPPORTED` = illegal reference (malformed escape, or a token that is not a legal array-index — empty, non-numeric, leading zero, or `-` — applied to an array); `MISSING` = reference legal but the target does not exist — an absent object member, a valid index beyond the last element, or a token applied to a scalar (evaluation cannot continue; the named place does not exist). The file must parse with `JSON.parse` (JSONC/comments → `MISSING` carrying that reason, never a guess); content = `canonicalJson` of the pointed-at value. The `jp:` success is the line-less shape — `startLine`/`endLine` OMITTED, unavailable, never fabricated (asserted in §7.4).
   - **`L:`** — 1-based inclusive; start or end beyond the file's line count → `MISSING`; content = the lines verbatim.
   - Errors are values (expected misses are not exceptions), and there is NEVER a silent fallback to whole-file content.
