## §0 The problem this stage solves

Measured on the operator's own transcripts (slice 0's vendored scripts): the operator re-asks what
a term means, repeatedly, for the same nine terms. The agent explains, the explanation scrolls
away, the next session starts from zero. D-F's answer is a glossary with **two mechanical
counters**, so «has this been taught yet» is a number and not somebody's impression —
agent-maintained «I think they know this now» marks were rejected as `#hope-as-gate`
([attention-is-not-a-mechanism.md §2](../../rules/attention-is-not-a-mechanism.md)).

## §1 Build list

1. **`CONTEXT.md` at the repo root**, English, mattpocock `domain-modeling` format
   (`**Term**:` / 1–2 sentences / `_Avoid_:`), **ADAPT not ADOPT**:
   - operator raw words go in an **added** field `_Operator says_:` — never in `_Avoid_`, which
     keeps its upstream meaning («words to stop using»);
   - upstream's «challenge the user against the glossary» rule is **explicitly NOT adopted** — the
     agent answers with the term plus its inline explanation and never corrects the operator's word
     (R-4). This is the inverse of what upstream does, and the reason the row in the harmonization
     spec has to be amended (item 6).
   - **Authority header first.** `CONTEXT.md` carries the standard `Authoritative for / NOT
     authoritative for` block as its opening lines, and joins the project-root doc list at
     [`doc-authority-hierarchy.md:46`](../../rules/doc-authority-hierarchy.md) **in the same
     commit**. Upstream's «a glossary and nothing else» is read as «no prose sections»; a header is
     not a section.
   - **Do NOT absorb the orchestrator role glossary.** `.claude/skills/orchestrator/references/glossary.md`
     is an owner doc with its own authority header, fingerprinted by 8 install baselines and the
     getff manifest. Per [harmonization D-H11 §5.2](../../../docs/superpowers/specs/2026-08-18-skill-stack-harmonization-design.md),
     a term with an owner doc gets a one-line gist plus a link, never a redefinition. `CONTEXT.md`
     **points at it**.
   - **Seed** (the measured re-ask list): приземлить, энв-тир, вендорить, чипы, глубина, «красное»,
     harvest, egress, handoff. Jargon the operator likes (harvest, egress, handoff) stays — it is
     taught, not replaced (D9).
2. **The `UserPromptSubmit` hook** — scans the operator's prompt for terms and for `_Operator says_`
   words, injects one line `"<raw word>" = <term>: <definition>`, and counts usages. New hook under
   `.claude/hooks/`, with the plugin twin regenerated by pre-commit (this one IS generated — it is
   not under `lang/`).
3. **`scripts/register-glossary-hook.sh`** — the D-E hand-action script. A `UserPromptSubmit` hook
   needs a `.claude/settings.json` entry **the agent may not write** (umbrella §2 item 3): without
   this script the glossary ships permanently dormant with green tests — the `WorktreeCreate` shape,
   where a hook sat unregistered from the day it shipped and a CLAUDE.md bullet claimed otherwise for
   months. Copy the shape of [`scripts/register-recap-gate.sh`](../../../scripts/register-recap-gate.sh)
   (191 L): resolves the repo from its own path so it runs from any cwd, idempotent, self-verifying,
   writes the USER settings file by default. Add it to the `SCRIPTS=(…)` array at
   [`register-root-resolution.test.sh:23`](../../../scripts/register-root-resolution.test.sh).
4. **Two counters** in `_glossary-counts.json`, in the residue dir
   ([`residue-dir.sh`](../../hooks/lib/residue-dir.sh) — shared across worktrees and sessions,
   outside git). **usages** — the `UserPromptSubmit` hook counts the term itself plus its
   transliteration in the operator's prompt; a synonym is NOT a usage. **explanations** — the Stop
   hook counts the fixed `term (explanation)` form, once per message. Learned =
   `usages ≥ AIF_GLOSSARY_USES` (3) **OR** `explanations ≥ AIF_GLOSSARY_EXPLAINS` (5), whichever
   comes first. Below threshold the Stop hook demands the inline explanation once; above it nothing
   fires.
   **Read [`residue-dir.sh:17`](../../hooks/lib/residue-dir.sh) before sourcing it** — its LOADING
   CONTRACT forbids an unconditional `.`: the Stop hook runs under `set -euo pipefail` and an
   unconditional source of a missing lib aborts it on every turn.
5. **`check-parity.sh` gains an `^AIF_GLOSSARY_[A-Z_]+=` probe in the same commit.** This is not

## §5 Falsifiers to write into the PR body

- The agent corrects the operator's word instead of answering with the term → R-4 broken.
- A `AIF_GLOSSARY_*` key exists in one pack only and `check-parity.sh` reports OK → item 5 failed.
- A seeded `CONTEXT.md` link resolves to a file but not to its anchor and principle 42 stays green →
  the test's fragment arm is not covering the seed.
- The hook is registered and a session still never sees an injected line → the counters file path
  disagrees between the two hooks.
- `/wait-what` answers in English under `AIF_HOOK_LANG=ru` and no `.override.md` ships → R-10 open.
