## §4c Autonomous aif-handoff dispatch — park-don't-guess contract

> **Live for every stage dispatched via the runtime bridge.** Inert only for a stage the operator
> chooses to run as a pasted CC tab.

**Why:** aif agents have no mid-implementation «pause and ask» primitive. They implement — *guessing* on
any ambiguity — then auto-review post-hoc, and a genuine design fork is not recognised as a question.
Without the levers below, aif decides forks wrong, silently.

**Lever 1 — conservative aif config. VERIFIED container-side 2026-08-17:**
`docker exec aif-handoff-agent-1 sh -c 'echo "${AGENT_MAX_REVIEW_ITERATIONS:-UNSET}"'` → **`1`**.
Re-probe at each stage entry (a host-side `echo` is UNVERIFIED — the value is not forwarded to the loop).

**Lever 2 — park-don't-guess instruction (verbatim, addressed to the aif agent):**

> **aif agent — fork discipline (non-negotiable):** On ANY genuine fork or ambiguity (two defensible
> implementations, an undecided design choice, a missing spec detail that changes behaviour) — **do NOT
> pick.** Park it as a question (set the task to `manualReviewRequired` / `blocked_external` with the
> fork stated as «Option A → consequence X / Option B → consequence Y») and **stop that task.** Proceed
> only on the unambiguous parts. Guessing a fork to «keep moving» is the failure this loop exists to prevent.

**Umbrella-specific parks that are known in advance — park them, never improvise:**
BS-pre env/keys + the aif project creation (host-side, §1.1); BS0 `beta.getff.ai` DNS record;
BS3 visual sign-off and the cutover GO.

**Recording a fired PARK is not a file write** (/pipeline §5 park-record contract): it lands in the park
payload + the stage PR's `## Parked questions` section, and its correction lands as a separate
owner commit — so no stage allowlist names a park-record artefact.

**Egress gate (mandatory after `status=done`/`verified`):** aif does not push or open PRs by design.

```bash
npx tsx packages/runtime-bridge/src/cli/harvest.ts <taskId> --base staging
```

For the landing repo, harvest through the **landing-side vendored** entrypoint that BS-pre installs —
that is the whole point of Stage 1.
