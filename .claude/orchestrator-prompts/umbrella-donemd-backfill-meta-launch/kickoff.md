## §3 Stage gates (real git checks — NOT in-memory FIFO)

### Stage 1 → Stage 2

Stage 2 dispatch waits for the Stage 1 PR to be merged to `staging` **AND** for the operator to confirm (or decline) the OBSOLETE-CANDIDATE table in `report.md`:

```bash
gh pr list --search "is:merged head:claude/umbrella-donemd-backfill-sweep base:staging" \
  --json number,title,mergedAt,headRefName --limit 10
```

Expected: non-empty JSON. If empty → halt. Do NOT dispatch Stage 2.

**Second, non-mechanical half of the gate:** the operator has answered on the OBSOLETE-CANDIDATE list. Absent an answer, Stage 2 does not start — an unanswered proposal is not a licence to close (umbrella kickoff T-UDB-A).

### Stage 2 → closure

```bash
gh pr list --search "is:merged head:claude/umbrella-donemd-backfill-obsolete base:staging" \
  --json number,title,mergedAt,headRefName --limit 10
```

On merge (or on an operator decline of the whole obsolete list), the merging session writes `.claude/orchestrator-prompts/umbrella-donemd-backfill/done.md` per CLAUDE.md «Umbrella closure convention» — **this umbrella's own closure is the last act, not the first** (umbrella kickoff Deliverable 3).

**Phase -1 cold-review between every stage transition is MANDATORY** (see §7 below).

## §4 Sub-wave dispatch instructions

### Sub-wave A — evidence-backed backfill sweep (Stage 1)

Branch: `claude/umbrella-donemd-backfill-sweep`, base `staging`. One PR; batch commits every ~25 files are fine.

Order of operations (each step is a T10/T3 obligation, not a suggestion):

1. **Enumerate the population FIRST** with the exact command, record the count in `report.md`. The report's checksum must hold: `population = closed + superseded + excluded + obsolete-candidates + unclear`.
2. Apply the exclusion list (umbrella kickoff §Scope, items 1 + 2) **per-dir**, not once by pattern (T7). The live-signal exclusion — open PR / unmerged branch ahead of staging / any commit under the dir in the last 45 days — is a per-dir command, and its result goes in the report.
3. Per remaining candidate, collect S1 → S2 → S3 in order, stop at first sufficient signal, and assign exactly one of the four verdicts.
4. Write `done.md` **only** for CLOSED-VERIFIED and SUPERSEDED. `Closed:` is the merged PR's date, not today's.
5. Write `report.md` into `.claude/orchestrator-prompts/umbrella-donemd-backfill/`, including the UNCLEAR section even when empty (T14).
6. Verify the acceptance gate before opening the PR: zero `done.md` under exclusion dirs; `bash .claude/skills/pipeline/helpers/priority-score.sh` still parses clean; every `done.md` traceable to a report row.

Do **not** touch code, hooks, or any file outside `.claude/orchestrator-prompts/*/done.md` and this umbrella's `report.md`.

### Sub-wave B — obsolete-close batch (Stage 2, gated)

Branch: `claude/umbrella-donemd-backfill-obsolete`, base `staging`. Writes `done.md` for **only** the rows the operator confirmed, with `Summary: obsolete (operator-confirmed <date>)`. Then writes this umbrella's own `done.md` and closes the umbrella. If the operator declines the whole list: skip the batch, write only this umbrella's `done.md`, note the decline in `report.md`.

## §5 AI-traps active (per `ai-laziness-traps.md §3`)

See `.claude/rules/ai-laziness-traps.md §2` for full catalogue.

**Active canonical traps for umbrella-donemd-backfill:**

- **T1** — «looked at 3, all closed, category done». There is no sampling here at all: the population is finite and fully enumerated. Any partial pass is a failed run, not a sampled one.
- **T3** — every `done.md` carries a verifiable `Final PR: #<num>` (spot-checkable via `gh pr view`) or a quoted supersede marker. No prose-only closure.
- **T7** — the exclusion list is re-checked per dir. Pattern-matching it once at the start and then proceeding from memory is exactly the trap.
- **T10** — population enumeration BEFORE classification; the report's count is the checksum. Reporting «closed 40» without knowing the denominator is meaningless.
- **T14** — a candidate with no merge signal is an UNCLEAR row, never a `done.md`. «No findings» ≠ «closed».
- **T15** — self-application: this umbrella's own `done.md` is written last, under the same evidence bar it applies to everyone else (Stage 2 gate above).
- **T17** — `done.md` is additive, but the *panel-hiding* effect is destructive-adjacent: a wrongly-written `done.md` silently removes a live umbrella from the operator's view. Treat a wrong close as data loss, not as a tidy-up.

**Domain-specific traps (umbrella-donemd-backfill-specific, NOT in canonical catalogue):**

- **T-UDB-A** — «cleaner panel» is not evidence. Writing `done.md` to shrink the open count without an S1/S3 signal is corruption of completion-detection Layer C3. Doubt = UNCLEAR.
- **T-UDB-B** — an exclusion-list umbrella that *looks* finished stays untouched. Its closure belongs to its own closing session (single-owner-per-stage), not to this backfill.
- **T-UDB-C (added at meta-launch)** — **PR-title substring ≠ umbrella closure.** `gh pr list --search "<slug>"` matches any PR mentioning the slug, including a *kickoff-authoring* PR (precedent: PR #1107 is this very umbrella's kickoff, and it would match `--search "donemd"` while proving nothing about completion). S1 requires that the matched PR plausibly delivers the umbrella's **final stage**, not merely that it names the slug. This trap was live at plan time and the same misread would have closed this umbrella against itself.

> **Anti-pattern warning:** blanket «see ai-laziness-traps.md» without enumeration above = T7 violation. Kickoff authors MUST enumerate T-numbers AND add ≥1 domain-specific trap.

## §8 Stop conditions

- Population checksum does not balance (`population ≠ closed + superseded + excluded + obsolete + unclear`) → halt, report; do NOT open the PR.

- `priority-score.sh` stops parsing after the new files → halt, report (the backfill broke the surface it exists to serve).
- Any `gh` command errors mid-sweep → halt with the partial state recorded; do not infer verdicts from a failed query.
- Operator has not answered the OBSOLETE-CANDIDATE list → Stage 2 does not start (no silent self-decision).
- Phase -1 reviewer returns STOP → halt, surface to maintainer.
