## Context (data — the two addenda)

### K-6 — SC2295 in validate-prompt.sh and its plugin twin
- **Where:** `.claude/hooks/validate-prompt.sh:150` and byte-twin `plugin/hooks/validate-prompt:142` — `${FILE_PATH#${REPO_ROOT}/}` (hooks).
- **Defect:** the unquoted inner expansion is a glob pattern; a `REPO_ROOT` containing `*`, `?` or `[` mis-strips the prefix. shellcheck reports SC2295 (measured pre-fix).
- **Fix:** `${FILE_PATH#"${REPO_ROOT}"/}` in the SOURCE hook only; the plugin twin is regenerated by the pre-commit twin sync (`scripts/generate-plugin-twins.sh`) — never hand-edit `plugin/hooks/`.
- **Verifier:** RED-first: `shellcheck .claude/hooks/validate-prompt.sh` shows SC2295 at :150 pre-fix and nothing post-fix; a runtime probe with a repo root containing a glob char (`mktemp -d` under a `[x]` directory) shows the wrong strip pre-fix and the right one post-fix. Twin parity: `diff <(sed '2d' plugin/hooks/validate-prompt) .claude/hooks/validate-prompt.sh` (the twin's line 2 is the generated banner — confirm the exact banner convention from an existing twin before relying on `sed '2d'`).

### T-6 — the assembled getff payload is reachable by the root vitest run
- **Where:** `scripts/build-getff-dist.sh` (header :9-16: the payload is COPIED into `packages/getff/`, gitignored there — only `MANIFEST.sha256` is tracked); root `vitest.config.ts:29-33` excludes only `node_modules`, `dist`, `.claude/worktrees` (test infra).
- **Defect:** after a local build, every shipped test exists twice on disk (`packages/getff/packages/core/hooks/*.test.ts` …) and the root `vitest run` executes the stale duplicate; vitest also treats a CLI path as a substring filter, so `vitest run packages/core/hooks/x` matches the payload copy too (TAIL-7 measured 5 false-red zcode-parity cases this way on 2026-09-06).
- **Fix:** exclude the payload roots under `packages/getff/**` (not `MANIFEST.sha256`, which is not a test) from the root `vitest.config.ts` and from `packages/core/vitest.config.ts` if it can reach them. Check the `hooks-tree-guard` globalSetup is not confused by the copy.
- **Verifier:** RED-first: build the dist, run `npx vitest list` (or a verbose run) and quote the duplicated path; paired negative: a planted always-failing test under `packages/getff/packages/core/…` must NOT fail the root run after the fix (and MUST before). State whether CI is affected: does any audit-self.yml job build the dist BEFORE running vitest (`grep -n build-getff-dist .github/workflows/audit-self.yml`)?
