```markdown
### §1.7 Forward-check applied

<≥40 non-whitespace chars enumerating which existing disciplines were checked, with file:line evidence>

### §1.7 Backward-check applied

<≥40 non-whitespace chars enumerating the sweep of sibling surfaces under this change's class, with file:line evidence>
```

**Hard rules (each has historically failed the gate):**

1. Heading depth = H3 (`###`), NOT H2. The CI awk regex matches `^### §1\.7 ...`.
2. The word «applied» is required in each heading.
3. ≥40 non-whitespace chars in EACH section body.
4. ≥1 file:line citation per section (regex `[^[:space:]]+\.[a-z]+:[0-9]+`).
5. Mechanical-maintenance escape hatch: `### §1.7 Skipped: <rationale ≥60 chars>` only when the PR is purely structural (no discipline surface).

**Pre-flight grep — Worker MUST run BEFORE `gh pr create`** (compose `$PR_BODY` first):

```bash
echo "$PR_BODY" | grep -cE '^### §1\.7 (Forward|Backward)-check applied'  # must be 2
echo "$PR_BODY" | awk '/^### §1\.7 Forward-check applied/{c=1;next} /^###/{c=0} c' | tr -d '[:space:]' | wc -c   # ≥40
echo "$PR_BODY" | awk '/^### §1\.7 Backward-check applied/{c=1;next} /^###/{c=0} c' | tr -d '[:space:]' | wc -c  # ≥40
echo "$PR_BODY" | grep -cE '[^[:space:]]+\.[a-z]+:[0-9]+'  # ≥2
```

S2 touches `install.sh` / `tests/` / templates — self-evaluate against the path list. If a worker's target does NOT match the list, §4b does not apply.
