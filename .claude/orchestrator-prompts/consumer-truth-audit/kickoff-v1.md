# consumer-truth-audit V1 — promise reconciliation (root docs vs measured delivery)

> **Umbrella:** [kickoff.md](kickoff.md) — §0 verdict classes, §5 truth criterion, §7 evidence
> discipline are binding.
> **Rigor label (effort-worthiness L0):** `research-grade`.
> **Depends on:** V0's `census-v0.json`. Without it this lane can only measure claims, not
> reconcile them — if the census is absent, report `PROBE-INCOMPLETE` rather than guessing.

## §0 Goal

Take every capability claim in the framework's own root-level documents and decide it against
V0's measured delivery. Not «does the doc read well» — «is this sentence true for a consumer».

Surface, enumerated not sampled: `README.md`, `INSTALL-FOR-AI.md`, `AGENTS.md`, `CONTRIBUTING.md`,
`CLAUDE.md`, every `packages/core/templates/shared/*.md` that ships to consumers, and every
`> **Authoritative for:**` header on a shipped artefact (`install.sh:242` already gates their
presence — this lane gates their *truth*).

## §1 Why this lane is not redundant with the docs-site audit

The site audit (18 GAPs) covered the site. These documents are a different surface with a
different failure mode: they are read by **AI agents at install time**, not by humans browsing.
A false sentence here is executed, not just believed. Two known instances, both already
confirmed, serve as calibration — find them independently and you have calibrated; miss them
and your coverage claim is wrong:

- `.claude/hooks/inject-matching-rule.sh:29-30` — «consumers DO get `.claude/rules/*` installed»,
  contradicted by `setup.d/LAYERS.md:79` and by every live install.
- `packages/core/templates/go/.golangci.yml:1` — «generated by getff go lane v0 — do not edit by
  hand», while no renderer emits it.

## §2 Method

1. **Enumerate claims** (T10). A claim is any sentence asserting the framework does, ships,
   enforces, supports or guarantees something. Emit the full list with `file:line` before
   deciding any of them. State the population size; it is the denominator for §5 row 6.
2. **Decide each** against V0's census and, for backend capability claims, against
   `packages/core/backends/<b>/capability-matrix.json` (umbrella §5). Where the two disagree,
   the matrix wins for *capability* questions and the census wins for *delivery* questions;
   a claim that survives neither is a finding.
3. **Class every finding** into `DOC-LIES` / `NOT-BUILT` / `BROKEN` / `BY-DESIGN` with a citation.
4. **Watch for the overloaded word «rules».** `install.sh:618` describes profile `core` as
   «rules + tests + guard hooks» where «rules» means **lint** rules; `.claude/rules/*.md` are
   **discipline** rules and are a different artefact class. Several claims in this corpus are
   ambiguous between the two. Report the ambiguity as a finding in its own right — an agent
   reading the doc at install time cannot disambiguate it either.

## §3 Deliverable

`report-v1.md`: §population (full claim list with `file:line`), §verdicts (one row per claim),
§findings (non-`BY-DESIGN`, most severe first, each with a concrete consequence for a consumer),
§coverage (`decided/enumerated`), §self-falsification.

Do not edit any document in this lane. Proposed rewordings belong in the finding, as a quoted
before/after — the triage pass decides whether the sentence or the code changes.

## §4 The gate — run it, quote command + output (T2/T3)

| # | Gate |
|---|---|
| 1 | claim population enumerated with `file:line` before any verdict |
| 2 | every claim has a verdict; no claim silently dropped |
| 3 | every finding cites the artefact that falsifies it, with the line's actual content |
| 4 | backend-capability claims decided against the capability matrices, not against prose |
| 5 | both §1 calibration instances found independently (report if you found them before reading §1) |
| 6 | coverage stated as `decided/enumerated`, with unreachable claims named and why |
| 7 | zero edits to any document — this lane measures |
| 8 | self-falsification section present and non-trivial |

## §5 Out of scope

The docs site (that is a separate surface with a separate ledger — do not re-derive its 18
GAPs), the stack-scope decision, and anything requiring a live harness (V3).

## AI traps ([.claude/rules/ai-laziness-traps.md §2](../../rules/ai-laziness-traps.md))

Active traps: **T2**, **T3**, **T4**, **T10**, **T14**, **T19**.

- **T2** — reading a doc is not auditing it. Each claim needs the check that decides it.
- **T3** — a verdict with no command or `file:line` is prose, and prose is not a finding.
- **T4** — adversarial counter-prompt at the CATEGORY level: which *class* of claim did I not
  enumerate at all? Write it, run it, record what it surfaced.
- **T10** — population before coverage.
- **T14** — a document with no findings and 30% coverage is not a clean document.
- **T19** — adversarially review your own verdict list before handing it over.
