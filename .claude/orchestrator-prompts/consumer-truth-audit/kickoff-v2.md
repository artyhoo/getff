## §0 Goal

For each shipped toolchain lane, fill one row of a maturity matrix from **executed evidence**,
so that «we support N stacks» becomes a sentence with a defined meaning.

Lanes, enumerated from `install.sh:281-283` (`LANE_TABLE`) plus the default npm path:
`npm`, `python`, `cargo`, `go`.

Columns, one per question the phrase «supported» silently bundles:

| Column | Question | Where the answer lives |
|---|---|---|
| delivery | does the lane install into a fresh consumer of the right shape | `setup.d/45-python.sh`, `46-cargo.sh`, `47-go.sh`; V0's census |
| collision | do the REFUSE-LOUDLY / AUGMENT cells behave as documented on a brownfield project | the lane scripts + `tests/install-sh/*-entry-lane.test.sh` + baselines |
| firing proof | is there an executed proof that a planted violation is caught | `packages/core/backends/<b>/firing.test.ts` + `firing-contract.json` |

| capability status | what does the lane's own matrix say, and is its evidence stale | `capability-matrix.json` (`status`, `caps[]`, `evidence.date`) |

## §1 Calibration — three findings already confirmed

Find these independently. If your pass misses one, your method is under-powered and the
coverage claim must say so.

1. **`go` ships exactly one ban.** `packages/core/templates/go/.golangci.yml` — «The single ban
   is the go analogue of clippy.toml's `std::env::var` disallow».
2. **That template calls itself generated, and nothing generates it.** Its line 1 reads
   `# generated by getff go lane v0 — do not edit by hand`; the synthesizer carries
   `render-researched-astgrep.ts` and `render-researched-clippy.ts` only, and `emit.ts` has no
   golangci target. → `DOC-LIES` on the header.
3. **`golangci` self-reports a hard cap.** Its `capability-matrix.json` records `partial` with
   «identity granularity is the LINTER name (`forbidigo`), not a per-pattern rule id — two
   different forbid patterns are indistinguishable in the JSON». That is an honest `partial`,
   not a defect — but any doc claiming per-rule attribution on the go lane is `DOC-LIES`.

A fourth, unverified at authoring time and left deliberately open: the bash firing runner
`packages/core/synthesizer/run-rule-tests-firing.sh` defines exactly three lane functions
(`_fire_astgrep`, `_fire_ruff`, `_fire_cargo`), while five backends carry firing contracts.
`agents/rule-test-author.md:52` indicates npm fires in-process via TS instead. **Determine
which channel proves each lane, and whether any contract is proven by nothing.**

## §2 Method

Run the proofs; do not read them. For each lane: plant a violation the lane is supposed to
catch in a fresh consumer, run the lane's own firing path, and quote the diagnostic. Record the
toolchain version — a `live-fired` cell with no version is not reproducible.

Where a capability-matrix `evidence.date` predates a change to that backend, treat the cell as
**suspect** and re-fire it per [`evidence-regeneration.md`](../../rules/evidence-regeneration.md).
Never hand-edit a matrix.

## AI traps ([.claude/rules/ai-laziness-traps.md §2](../../rules/ai-laziness-traps.md))

Active traps: **T2**, **T3**, **T6**, **T13**, **T14**, **T16**.

- **T2** — «the test exists» is not «the test proves it». Run it.
- **T3** — every cell needs an executed command or `INCONCLUSIVE`.
- **T6** — no confidence adjectives. «4/24 cells live-fired this run, 20 read from matrices
  dated <D>» is a confidence statement; «high» is not.
- **T13** — a capability cell validated only by a doc is not validated. Check the evidence kind.
- **T14** — a lane with no findings and two filled cells is not a mature lane.
- **T16** — for any cell justified by analogy to another lane («go mirrors cargo»), write the
  analogy out and say what evidence carries across. Structural similarity is not proof.
