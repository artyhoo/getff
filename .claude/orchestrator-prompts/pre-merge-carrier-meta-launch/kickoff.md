## §4c Autonomous aif-handoff dispatch — park-don't-guess contract

**Live for this umbrella:** the runtime bridge answers (`RUNTIME_BRIDGE_MODE=aif-handoff`,
`/health` → 200, `AGENT_MAX_REVIEW_ITERATIONS=1` verified **container-side** in
`aif-handoff-agent-1`), so autonomous dispatch is offered alongside — never instead of — the
paste tab. **Fit caveat, stated honestly:** the §5 dispatch-table row that matches this stage is
«R-phase, single → Mode A inline». Autonomous execution of a *design* stage whose deliverable
explicitly requires open forks to be marked `DECISION-NEEDED` puts the park contract under
maximum load; a paste tab is the better-fitting channel and the recommendation below reflects that.

If dispatched autonomously, the aif agent is bound by:

> **aif agent — fork discipline (non-negotiable):** On ANY genuine fork or ambiguity (two
> defensible implementations, an undecided design choice, a missing spec detail that changes
> behaviour) — **do NOT pick.** Park it as a question (set the task to `manualReviewRequired` /
> `blocked_external` with the fork stated as «Option A → consequence X / Option B → consequence
> Y») and **stop that task.** Proceed only on the unambiguous parts. Guessing a fork to "keep
> moving" is the failure this whole loop exists to prevent.

Recording a fired PARK is **not** a file write: it lands in the park payload plus the PR's
`## Parked questions` section, and its correction lands as a separate owner commit.

**Egress gate (mandatory after `status=done`):**

## §5 AI-traps active (per `ai-laziness-traps.md §3`)

See `.claude/rules/ai-laziness-traps.md §2` for the full catalogue. Carried from the umbrella
kickoff §3 (T3, T11, T12, T16, T19), each with its counter:

- **T3** — every finding must have ONE of: (a) command + output, (b) file:line citation + the
  line's actual content, (c) explicit `INCONCLUSIVE-needs-LLM` / `INCONCLUSIVE-needs-human`.
  **No prose-only findings** — the lane inventory in §(b) is exactly where prose-only would hide.
- **T11** — the build-vs-reuse SSOT consult + context7 at ≥3 phrasings + WebSearch on the
  problem-domain term comes **before** any «I propose…». This stage's deliverable 1 IS that consult.
- **T12** — training-data knowledge has a cutoff and is biased toward well-documented tools;
  `git merge-tree --write-tree` semantics and merge-queue behaviour both moved recently. Search
  at the moment of proposing, not from memory.
- **T16** — for every ADOPTED/ADAPTED candidate write «Upstream problem class: X. Our problem
  class: Y. Match? evidence: …». Merge queue solves the same defect class *hosted*; that is a
  problem-class statement the spec must make explicitly, not assume.
- **T19** — run your own adversarial cold-review of the diff before handoff. Green CI on a
  docs-only PR proves formatting, not design substance.

**Domain-specific traps (pre-merge-carrier-specific, NOT in the canonical catalogue):**

- **T-PMC-A** — generalising the interlock set from ONE measured host/stack. All evidence in
  #1466 is three runs, one machine, one consumer, docs-only branches. §(b) must probe each
  shipped lane's actual cache/shared-resource surfaces (grep the lane templates + `setup.d/`),
  never extrapolate timeliner's six traps by analogy.
- **T-PMC-B** — quietly designing a branch-gate because it is simpler. Any draft in which the
  verified sha equals the head sha on a branch that is behind base has re-created the exact
  defect the issue names. The spec must state the three-sha report (head, base, merge result)
  as a hard output contract.
- **T-PMC-C** (meta-launch addition) — **truncating §(b) against the 600-line markdown wall.**
  A spec with seven sections plus a four-lane inventory runs at the pre-commit gate's limit; the
  tempting fix is to thin the *inventory* because it is the most tabular part, which silently
  converts the one measured deliverable back into the estimate T-PMC-A forbids. Counter: check
  `wc -l` early and split the lane inventory into its own referenced file rather than shrinking it.
