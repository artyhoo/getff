## §5 AI-traps active (per `ai-laziness-traps.md §3`)

**Active canonical traps for getff-ai-site**, inherited verbatim from the umbrella kickoff §7
so a reader of this file alone is not short of them:

- **T3** — every claim about a file carries `path:line` **and** the line's actual content; a
  claim with neither is prose. This file's own measured claims each carry their command.
- **T8** — if the answer is in the specs, do not ask the operator. The two things that
  genuinely need them here are the S0a dispatch «го» (non-negotiable 9) and the R14 hands.
- **T10** — D49's page inventory is a population enumeration and precedes any coverage claim
  about the site.
- **T17** — S2 deletes `content/docs/**` and 195 route twins; preservation happens **before**
  the destructive prompt is written, and it is the orchestrator's job, not the Worker's.
- **T19** — the umbrella's own cold QA of these kickoffs happens before handoff, not after.
- **T21** — a backward-check that lists only the files a PR touched is a restatement, not a
  sweep; delegate the sweep to `agents/backward-sweep-auditor.md`.

**Domain-specific traps (getff-ai-site-specific, NOT in the canonical catalogue):**

- **`T-GA-A` «citation correct when written, false when read»** (the umbrella's own, recorded
  at its kickoff §7): an edit that inserts or deletes lines in a cited file invalidates every
  citation INTO that file past the insertion point, including correct citations written by
  other people in other specs. `scripts/check-line-citations.mjs` has exactly two arms
  (blame-based drift; blank cited line), so a citation wrong **when written** returns exit 0.
  Counter: pin every file of one answer to the same ref and name the ref; after any edit read
  the diff's hunk headers for the per-file shift map and re-check citations into each shifted
  file above its shift point.
- **`T-GA-B` «a probe verdict read as a headline»** (this preflight's own, new): the in-flight
  probe's `IN-FLIGHT` here came entirely from substring and full-text noise, and a session
  that reads only the `VERDICT:` line either stops forever on nothing or — worse, on the next
  umbrella — treats a genuine collision as more noise. Counter: every `IN-FLIGHT` verdict is
  triaged leg by leg, each leg named and disposed in writing (§3.0(b) is the worked example),
  and a leg that cannot be triaged is reported as untriaged, never as noise.

## §9a Host-verify contract

This preflight reasons over artifacts, so its contract asserts that the artifacts it reasons
over are still there and still runnable. It goes red if a stage kickoff is renamed or deleted,
if the runner this file's gates invoke disappears, or if the primitive whose existence retracted
the §3.0(c) BLOCKER stops existing — that last line is deliberate: a retraction is only as good
as the thing it rests on, and this makes the basis mechanical rather than remembered.

```bash host-verify
test -f .claude/orchestrator-prompts/getff-ai-site/kickoff.md
test -f .claude/orchestrator-prompts/getff-ai-site/kickoff-s0a.md

```

The last line is what keeps this contract from being `#contract-that-cannot-fail`
([`destination-environment-verification.md §4`](../../rules/destination-environment-verification.md)):

always-runnable one (13/13 at `79fa1b56b74`), so a break in it surfaces here too.
