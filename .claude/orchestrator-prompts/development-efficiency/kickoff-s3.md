## 2. Implementation contract

1. Include usable destination, permitted source changes, known generated outputs,
   necessary checks and already-specified repairs in each bounded assignment. Keep
   ordinary admitted corrections with the executor. Unexpected outputs/goals and live
   authority restrictions follow their existing route, not blanket permission expansion.
2. Reuse existing generators for manifests, catalogs and recoverable citations. Check
   outputs against admitted scope. Preserve staged versus working-tree identity and
   independent archive comparison. Keep `MANIFEST.sha256` tracked.
3. Reuse existing result fields/records for task/slice, immutable candidate/result
   generation and attempt, actual action/outcome, authoritative evidence, next action,
   accountable owner and authority/decision prerequisite. Change producer and consumer
   together. Reference one canonical result from task/PR records; no second universal packet.
4. Parse mechanically decidable facts and reconcile current authoritative evidence when
   necessary. Launch is not running; a response is not approval; results for another
   candidate do not clear this candidate's block. Narrow source reconciliation replaces
   another blanket narrative. Keep sent, received, accepted and performed distinct.
5. Consumption produces an authorized next action or a durably owned pending action with
   its prerequisite/return condition. Demonstrate an actual consumer. Route repair to its
   executor, review to its independent reviewer, delivery to its authorized owner. Native
   desktop-owned review routing retains writer locks; no CLI takeover or self-approval.
6. Reconcile stale role restrictions against the latest applicable explicit authority,
   removing only superseded restrictions with that reference. Record acknowledged serial
   custody return, next eligible work and displaced-task return conditions in the existing queue.
7. For each proposed handoff removal, map producer, consumer, unique evidence/decision/
   effect and surviving owner first. Remove only relay-only work after the unique control
   still demonstrably fires at the surviving boundary. Do not remove reviews wholesale.
8. Use targeted checks while editing. Stabilize through existing review/rework before
   expensive final conformance acceptance; preserve required pre-egress review. Final
   evidence binds the last relevant edit. Use an independent narrow delta review only
   under the existing unchanged-substance contract; changed substance gets required review.

No new universal schema service, scheduler, standing observer, coordinator role or
automatic terminated-chat recovery. S4 consumes the identities/actions established here.
Do not finish S3 by editing a template that its real installed reader never consumes.

## 3. Acceptance

Before mutation, the bounded plan names actual producer/consumer integration commands
and any installed-host controls. On those real boundaries, exercise:

- Known generated outputs finish within admitted scope; unexpected output stops.
- Blocking response never becomes approval; final same-candidate CI replaces stale
  evidence, while another candidate's result does not.
- Completion reaches its real next owner/action, or an explicit pending action retains
  accountable custody and a return condition. A passive file alone is not progress.
- Specified repair continues without re-planning; unchanged applicable evidence is reused,
  and changed relevant inputs invalidate it. Superseded restrictions and serial custody
  return are reconciled against actual records, not assumed.
- Every removed hop's unique necessary control still detects its intended violation.

Run the applicable named integration controls plus this existing repository floor:

```bash host-verify
node --test tests/roles/orchestrator-worker-discipline.test.mjs
npm --prefix packages/runtime-bridge run typecheck
npm --prefix packages/runtime-bridge test
```

These are regression checks, not proof of an installed report consumer. Acceptance also
needs the exact bound consumer and delivery evidence from the changed workflow. Retain
source readiness separately when a destination is unavailable. Bind S4's consumption
contract to the accepted generation/action fields before that dependent stage starts.

## §4c Park-don't-guess

On a genuine unresolved architecture, scope or authority fork, do not guess. Park it as
a question through the existing runtime task's supported park/answer path, name the
existing accountable recipient, and state both options with their consequences and the
missing decision/evidence. Stop dependent effects until a valid answer returns through
that route; continue independent already-admitted work when possible. A clear ordinary
in-scope correction is not a new operator vote. Preserve task identity, current authority,
review/launch caps and any owned pending result. This contract grants no launch itself.
