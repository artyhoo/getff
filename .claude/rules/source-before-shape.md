## §1 The PRIORITY-CHECK — «source-before-shape»

Before an authoring or scoping action that **commits to an artifact's shape**, the authoritative external source MUST be read **first, and as an input that drives the shape** — not consulted post-hoc as a trailer or a correction:

- **Reuse surface** (creating a new `SKILL.md`, `agents/*.md`, or a new `packages/core/<dir>/` module): `grep` the SSOT ([prior-art-evaluations.md](../../docs/meta-factory/prior-art-evaluations.md)) + the existing `.claude/skills/` and `agents/` for overlap on this capability-area **before writing the body**. If an own-stack or upstream analog exists, the body is a **thin adapter that subordinates to it** (`> **NOT authoritative for:** <the loop> — that is <owner>, which this layers over, never re-describes`), OR the commit carries an explicit BUILD justification whose verdict **matches what the body actually does**. A correct-sounding ADAPT/REFERENCE trailer over a re-describing body is `#discipline-theatre` at the trailer level ([phase-research-coverage.md §4](phase-research-coverage.md)), not compliance — and principle 11 F1 (presence check) will not catch it.
- **Scope surface** (scoping a dispatch, launch prompt, or kickoff): re-read the spec's scope / chain section (`sed`/`Read` the actual lines) **before scoping**. A scope stated from recollection is provisional until the source is quoted.

The load-bearing verb is **read the source as an input to the shape** — not «be more careful». Delivered at edit-time (§3) so it _can_ fire before the artifact exists — one step ahead of principle 11 F1's push-time presence check — but only **when the new-capability edit is the first matching edit of the session** (Layer A is once-per-session; §3 limitation 1). Where it does not fire, Layer B (the auditor, run before handoff) + the always-on parent BFR rule carry the discipline.

## §2 Trigger / non-triggers

**Applies when** an action commits to a capability's shape or a dispatch's scope:

- Creating a new `.claude/skills/<name>/SKILL.md`, a new `agents/*.md`, or the first file of a new `packages/core/<dir>/`.
- Authoring or editing a dispatch input under `.claude/orchestrator-prompts/**` (kickoff, launch prompt).

**Does NOT apply to:** edits to an existing capability that add no new capability-area (bug fix, typo, snapshot regen); non-capability files; a dispatch that merely re-runs a scope already quoted from source this session. Mechanical edits with an explicit done-criterion are out of scope (parallel to [ai-laziness-traps.md](ai-laziness-traps.md) preface).

## §3 Mechanism (two layers) + honest limitations

**Layer A — edit-time injection (deterministic, no LLM).** The `<!-- globs: -->` + `<!-- inject: -->` markers at the top wire this rule into [`inject-matching-rule.sh`](../hooks/inject-matching-rule.sh): on an Edit/Write under `.claude/skills/**`, `agents/**`, or `.claude/orchestrator-prompts/**`, the injector delivers the one-line source-before-shape reminder as PostToolUse `additionalContext`, **once per session** (session-cache). The `paths:` frontmatter mirrors the same scope as the CC-native read-time sibling channel (`@dual-pair` pattern, [rule-enforcement-channel-selection.md §4](rule-enforcement-channel-selection.md); keep the two glob sets identical). This is the earliest reachable channel for a **judgment** rule — an injection that _surfaces_ the check, never a gate that blocks (blocking a judgment call is `#gate-where-judgment-needed`).

**Layer B — AI-agnostic overlap auditor.** [`agents/capability-reuse-auditor.md`](../../agents/capability-reuse-auditor.md) — a sub-agent read by the active session (its own subscription, no API-billed call per [no-paid-llm-in-ci.md §1](no-paid-llm-in-ci.md)) that does the **semantic** «does this proposed capability overlap an existing skill/agent/SSOT entry, and does the body reuse or re-describe it?» triage the deterministic injection cannot. Run it before handoff of any new-capability PR (parallel to the T19 own-cold-review discipline).

**Honest limitations (Layer A is a nudge, not a net — these are load-bearing, not a silent cap):**

- **Spent-before-creation false-negative — applies to the INCLUDED globs too, not only the excluded one.** Layer A fires **once per session** and cannot distinguish creation from a routine edit. So if _any_ earlier edit in the session touches `agents/**` or `.claude/skills/**` (e.g. a bugfix to an existing skill), the injection is «spent» on that edit and the later real Write of the _new_ capability gets **zero** injections. Verified live: with `session_id` constant, a benign Edit to `agents/aif-init.md` returns the reminder (count 1); the subsequent Write of a new `agents/*.md` in the same session returns it 0 times. Concretely, **Layer A would not have fired on its own origin incident** — an `/orchestrator` session that edits a skill/agent before authoring `.claude/skills/night-mode/SKILL.md` (PR #858) disarms the injection for that Write. Layer A is therefore a **best-effort first-touch nudge**, not a reliable gate on the creation edit; the discipline is carried on those surfaces by **Layer B (the auditor, run before handoff)** + the **always-on parent BFR rule**, not by Layer A alone.
- **`packages/core/**` is the extreme case, deliberately NOT in the injection globs.** Core is edited so frequently that the spent-before-creation defeat above is near-certain — the once-per-session token would almost always be spent on a routine core edit before any new-module edit. Rather than pretend coverage, the surface is left to the always-on parent BFR + Layer B outright.
- **Inline dispatch prompts are not caught by Layer A.** The injection fires on an Edit/Write to a _file_ under `.claude/orchestrator-prompts/**`; a launch/dispatch prompt composed _inline_ in a chat turn (never written to disk) triggers no Edit/Write, so Layer A cannot reach it. Coverage there is the always-on §1.11 parent + Layer B before dispatch.
- **The one benign direction:** because Layer A cannot tell creation from edit, it _also_ fires on a matching edit that is not a creation (a harmless false-positive). Accepted — a once-per-session reminder is cheap; a gate would find both directions intolerable, which is exactly why this is injection, not gate.

## §4 Anti-patterns

- **`#authoring-from-internal-state`** (the family) — committing to an artifact's shape or a dispatch's scope from an internal mental model / session recall at an authoring moment that has no action-scoped gate, when the authoritative external source was one cheap probe away and would have changed the artifact. Two sub-cases:
  - **`#consult-as-trailer-not-input`** — the prior-art consult _happened_ but only as a post-hoc `Prior-art:` trailer, too late to shape the body (body reinvents while the trailer says «ADAPT»). Passes principle 11 F1 → `#discipline-theatre` on the trailer. Distinct from [ai-laziness-traps.md §2 T11](ai-laziness-traps.md) (T11 = _no_ consult; this = consult _mis-timed_). Counter: §1 reuse surface — grep before writing the body; the trailer verdict must match the body.
  - **`#scope-from-memory-not-source`** — scoping a dispatch/launch from recall instead of re-reading the spec's scope-chain. The shape-act specialization of `#claim-from-memory-not-source` ([phase-research-coverage.md §4](phase-research-coverage.md) / §1.11). Counter: §1 scope surface — quote the spec lines before scoping.
- Related existing anti-patterns this rule delivers at edit-time: `#parallel-evolution-creep`, `#own-stack-blind-spot` ([build-first-reuse-default.md §4](build-first-reuse-default.md)); T16 `#pattern-matching-on-name` ([ai-laziness-traps.md §2](ai-laziness-traps.md)).

## §5 Promotion / retirement

- **Promotion to Class A (principle test):** only if the reinvention shape proves to have a **mechanically-detectable structural signature** — e.g. every reinvention shares a trailer↔body divergence a deterministic check could catch (an ADAPT/REFERENCE trailer whose body carries an `Authoritative for:` claim over the very capability the cited SSOT entry owns). Until such a signature is demonstrated on ≥3 incidents, the discipline stays Class B (judgment ceiling — a structural proxy that passes on a merely-well-formed reinvention would be `#discipline-theatre`). This mirrors [reviewer-discipline.md §4](reviewer-discipline.md)'s judgment-ceiling rationale.
- **Retirement:** 12 consecutive months with zero `#authoring-from-internal-state` incidents → archive to prose in [CLAUDE.md](../../CLAUDE.md). Matches peer-rule retirement criteria ([egress-no-api-bypass.md §4](egress-no-api-bypass.md), [ci-tool-pinning.md §6](ci-tool-pinning.md)).
- **Incident counter (as of 2026-07-02):** 2 in-session events + 1 operator-confirmed cross-session recurrence = the recurrence that promoted this from a research-patch recommendation to a shipped Class-B mechanism.
